资源 约定

项目板只追踪可交付的 Issue/PR，不预先堆积无法验证的愿望清单；设计事实回到仓库 docs，讨论性内容放 Discussions。

五条发布链

CI

类型、lint、文件大小、Spark engine 和包级验证。

打开 CI →

桌面 / CLI

桌面安装包走 GitHub Release；CLI 制品走 spark-cli-releases 分支。

查看 Releases →

官网 / Pages

官网走 Docker 与自有服务器；Pages 只部署 docs-site 工程手册。

查看 Actions →

GitHub Pages 合同

源文件在主仓库，artifact 只来自 docs-site。

Pages 使用相对链接，适配项目页的 /spark-agent/ 路径；不读取发布 secrets，不参与桌面/CLI/官网部署。若内容错误，回滚文档提交并重跑部署即可。

维护节奏

每次 PR

  • 补齐验证命令和风险
  • 架构/计划文档更新状态行
  • Pages 入口文件仍可构建
  • 不公开凭据和私有数据

每季度

  • 核对 docs 与代码
  • 检查 Wiki、Pages、README 链接
  • 复核 Project 字段和视图
  • 检查 workflow action 版本
