02

操作流程

每条都给「正常路径 + 失败路径」

A新建会话（最主链路，3 步内必须发出第一条消息）

STEP 1
上下文已就绪
首屏顶部常驻 设备 · 项目，上次选择自动恢复；没选过则默认「最近活跃的在线设备」+「该项目列表第一项」。
→
STEP 2
直接打字发送
不要求先进空会话。输入框常驻，点 ↑ 即在该项目建会话；也可点 ＋ 先建空会话再打字。
→
STEP 3
乐观插入 + 进详情
列表顶部立刻出现「新会话 · 正在创建」，成功后 redirectTo 会话详情，Tab 仍高亮「会话」。
→
失败
不丢内容、不重复提交
留在首页，输入框保留原文；结果未知时按钮变「检查」而不是「重发」，点开确认后再决定。

B切换设备 / 项目（两处入口，一套状态）

ENTRY
顶部 chip / 抽屉设备名
两个入口打开同一个底部弹层，不做两套 UI。
→
SELECT
选中即生效
点行关闭弹层，列表在 200ms 内切到新数据；不做「确认」二次点击。
→
MEMORY
按设备记住项目
A 机选 Spark-Agent、B 机选 edu-web，来回切不互相覆盖。
→
EDGE
离线 / 无项目
离线：可查看历史，发送置灰 + 顶部「该电脑离线」；无项目：空态给「刷新」和「去桌面端新建空间」。

C抽屉直达（跳过选项目）

1
☰ 打开抽屉
左滑手势也能开，但只在根 Tab 页生效（二级页左边缘右滑属于系统返回，抢不到）；遮罩点击 / 右滑关闭。
→
2
展开空间
点行展开子会话（懒加载），点 › 进该项目的完整会话列表。
→
3
点会话 / 点 ＋
点会话直接进详情；点 ＋ 关抽屉、上下文切到该项目、输入框聚焦——两条都是「一步到位」。

D消息长按（按消息类型给两套，逐个写行为）

触发
长按 350ms
小程序 bindlongpress 固定 350ms，不可配置；配 vibrateShort + 气泡描边；滑动超 8px 视为滚动不弹。
→
定位
跟手不遮挡
默认在触点右下方；底部不足则上翻，右侧不足则左移，始终距屏幕边 12px。
→
关闭
三种都能关
点遮罩、滚动列表、触发返回；关闭时不动滚动位置、不改变选中状态。
动作行为定义依赖
复制内容整段纯文本写入剪贴板。对应现网「复制消息」/「复制为纯文本」，行为不变已支持
复制 Markdown原样 Markdown（代码块、表格不丢）。仅助手消息出现，对应现网「复制 Markdown 原文」已支持
节选复制保持气泡 user-select（现网已开），点此项收起菜单直接进选择态，顶部「完成」退出已支持
从此处分支仅用户消息、且该条有 turnId 时出现，调现网 forkFromTurn，从该轮另起分支已支持
再发送一次用户消息 → 原文回填输入框（不自动发）；助手消息 → 重新生成该轮，接口不支持则降级回填看接口无 regenerate
分享会话卡片（标题 + 摘要）走小程序分享或 canvas 长图需新增页面暂无 onShareAppMessage
朗读TTS 播报，再点停止。仓内无实现、小程序无内置 TTS → v1 不渲染该项缺能力需网关 TTS
删除仅本机隐藏该条；需新增 storage 键 + 与 seq 对账，桌面端不受影响需新增本地隐藏表

修正（原稿写错）：不要为了菜单关掉 user-select。现网气泡已经是「可选文本 + 长按并存」（chat/index.wxml 里 user-select 与 bindlongpress 同时存在），关掉等于砍能力。真机要验的只有一件事：长按后系统选择气泡出现时，自绘菜单是否被压住——若冲突，改成「长按出菜单、菜单里点『节选复制』才进选择态」的顺序，而不是全局关闭。

技术边界（现在就该定）

点结论
底栏实现项目无原生 tabBar，继续自绘；切 Tab 用 reLaunch（栈只留一层），chat 用 navigateTo。代价：reLaunch 重建页面、丢滚动位置，必须靠现有 list-cache 回填首屏，否则每次切 Tab 都白屏一下
滚动高度列表容器必须给确定高度（height: calc(100vh - 顶 - 输入 - 58 - safe)），不能靠 flex 分配，真机会顶飞底栏
抽屉手势小程序无系统侧滑，边缘拖拽自己写，阈值 24px。但只在根 Tab 页启用：二级页从屏幕左缘右滑是系统返回，微信不会把事件交给我们，硬做只会「划一半页面就退了」
长按 vs 滚动bindlongpress（固定 350ms）+ bindtouchmove：移动超 8px 取消。遮罩层不能 catchtouchmove，否则页面滚不动；改成遮罩上监听 move → 关菜单 → 放行
为什么自绘菜单wx.showActionSheet 的 itemColor 全局生效，没法让「删除」单独变红，也做不了图标与分组的视觉；这就是不走系统菜单的硬理由
深色新增样式仍只写浅色源码，跑 pnpm theme 生成 dark；菜单/弹层用同一套 token，禁止写死颜色
