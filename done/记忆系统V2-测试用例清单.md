# 记忆系统 V2 — 测试用例清单

> 状态: 已落地 | 最后核对: 2026-07-04
>
> 本清单覆盖记忆系统全流程全场景的手工验证用例。每条都标注前置条件、操作步骤、预期结果。
> 配套自动化测试（138 单测 + 16 gate evals + 11 search evals，100% 通过）已在 CI 跑通，
> 本文档聚焦**真实端到端**（不同 adapter × 不同 scope × 团队/单 agent）的人工验收。

## 0. 前置准备（所有用例都需要）

1. 启动 app，确认至少有 1 个 provider 配置好（anthropic / openai / deepseek 任一）+ API key 已存入 keystore
2. 进入 **设置 → Agent → 记忆**，确认：
   - 「启用长期记忆」开关 = ON
   - 「抽取模型」section：要么配好 provider+model，要么留空（走回退，见用例 A1）
3. 点「测试抽取配置」按钮 → 预期：toast「抽取配置可用（...）」。**这一步通过是所有后续用例的前提**

## A. 不同适配器下的记忆抽取

### A1. Claude SDK 路径（claude-sonnet / claude-haiku）

- **前置**：会话的 agent adapter = claude 或 claude-sdk，provider_type = anthropic
- **操作**：发起一个明显含可记忆信息的 turn，例如：
  > "我用 React 19 + vite，请记住我偏好函数式组件，不用 class"
- **预期**：
  1. turn 结束后几秒，日志（开发者工具主进程）出现 `Memory injection` 或 `memory extraction` 相关行
  2. 打开记忆面板，**user scope** 下出现一条 `feedback` 类型记忆，name 含 `prefer-function-component`（或类似）
  3. 详情 body 含 **Why** / **How to apply** 段落

### A2. Codex CLI 路径（gpt-5 / o-series 本地 CLI）

- **前置**：会话的 agent adapter = codex，用本地 codex CLI provider（isLocalCli）
- **操作**：同 A1，发一条可记忆消息
- **预期**：
  1. turn 结束后记忆被抽取（与 A1 同）
  2. **额外验证**：会话中 agent 能调用 `mcp__spark_memory__search_memory` 工具（codex CLI 通过 stdio MCP 挂载）——问 agent「我之前告诉过你什么偏好？」，预期它调 search_memory 工具
- **回归点**：本次新实现的 stdio spark-memory MCP server（`packages/agent-runtime/src/tools/spark-memory-mcp-server.mjs`）走 PlatformBridgeService HTTP RPC 回主进程

### A3. Codex SDK 路径（API-only，gpt-4o 远程）

- **前置**：会话的 agent adapter = codex，但**不是**本地 CLI（API-only）
- **预期（已知架构限制）**：
  1. 记忆**抽取正常**（complete() 不依赖 adapter）
  2. 但 agent **无法**在会话中调 search_memory/recall_memory（codex-openai-executor.ts:308 明确：API-only Codex 不 attached 本地 MCP）
  3. 会话开始时的 seed 注入仍然有效（loadForSession 不依赖 MCP）
- **这是 codex SDK 本身的限制，非 bug**

### A4. Claude CLI 路径（claude 本地 CLI）

- **前置**：会话用 claude CLI provider（isLocalCli && provider_type=anthropic）
- **操作**：同 A1
- **预期**：与 A2 同（抽取正常 + stdio spark_memory 工具可用）

### A5. 抽取模型回退（settings 未配）

- **前置**：记忆配置页「抽取模型」section **全部留空**（Provider/Model 都不选）
- **操作**：发起 A1 那种含可记忆信息的 turn
- **预期**：
  1. complete() 走回退路径，用该会话当前生效的对话模型（看日志 `complete` 行的 providerId/model = 对话用的那个）
  2. 记忆正常抽取写入
- **回归点**：本次修复（session.service.ts activeChatModelBySession + complete() 5th 参数）

### A6. 回退时 @mention 切到成员 agent

- **前置**：团队模式（见 D 节），settings 抽取未配
- **操作**：`@member-agent 帮我记住...`
- **预期**：抽取走 **被 @ 成员 agent 自己的** provider/model（不是主持 agent 的）—— 验证 line 1256 `isMentionTurn ? agent.modelId : null` 回退正确

## B. 应用级（user scope）记忆

### B1. 抽取写入

- 同 A1，记忆落到 user scope（跨项目共享）

### B2. 会话注入

- **前置**：B1 已写入一条 user feedback 记忆
- **操作**：**新开一个会话**（不同项目也行），问一个相关问题
- **预期**：新会话的 system prompt 含该记忆的摘要（看日志 `Memory injection: N entries`）
- **回归点**：user scope 对所有会话可见

### B3. 查阅 + 编辑

- 记忆面板 → scope 选 User → 找到那条 → 点开 → 改 description/body → 保存
- 预期：toast「已保存」，列表刷新

### B4. 清除字段

- 进入配置页，Provider 下拉点 × 清除 → 预期：下拉变空，settings 里该 key 被删除（不再是空字符串）
- 验证：重启 app，Provider 仍是空（说明真删了，不是 ''）

## C. 项目级（project scope）记忆

### C1. 抽取写入

- **前置**：当前会话绑定了工作区（workspaceId）
- **操作**：发一条项目特定信息，例如「这个项目用 Arco Design，不用 antd」
- **预期**：记忆落到 project scope，scopeRef = 当前 workspaceId

### C2. 跨项目隔离

- **前置**：C1 已写入
- **操作**：切换到**另一个工作区**的新会话
- **预期**：那条 project 记忆**不出现**在注入里（scope 不匹配）
- 切回原工作区 → 那条记忆重新出现

### C3. 手动新增 project 记忆

- 记忆面板 → scope 选 Project → 填 workspaceId → 新增
- 预期：创建成功，列表能看到（scopeRef 匹配时）

## D. 团队模式 vs 单 agent

### D1. 单 agent 会话

- 所有 A/B/C 用例都是单 agent 场景
- 记忆 scope = user + project + 当前 agent

### D2. 团队模式（主持 agent 抽取）

- **前置**：开启团队模式，配置主持 agent + 成员 agent
- **操作**：对**主持 agent**发一条可记忆消息（不 @）
- **预期**：抽取走的模型 = 主持 agent 的对话模型（session 默认）
- 记忆的 agent scope = 主持 agent id

### D3. 团队模式（@mention 成员抽取）

- **前置**：同 D2
- **操作**：`@member-agent 帮我记住...`
- **预期**：
  1. 抽取走的模型 = **成员 agent 自己的** provider/model（A6 回归）
  2. 记忆的 agent scope = **成员 agent id**（不是主持）
  3. 成员 agent 在后续被 @ 时能看到自己的记忆

### D4. 团队成员各自的 agent scope 隔离

- **前置**：D3 已为 member-A 写入一条 agent scope 记忆
- **操作**：`@member-B 你之前告诉过我什么？`
- **预期**：member-B **看不到** member-A 的 agent scope 记忆（scope 隔离）

### D5. 显式「记一下」+ Agent 角色偏好

- **操作**：对某个 agent 发送「你是一个架构师，你懂得所有技术栈的知识，记一下」
- **预期**：
  1. 抽取不返回空数组；至少产生 1 条 `scope=agent,type=feedback` 候选
  2. description/body 表达为「用户期望该 Agent 以架构师视角、跨技术栈协助」，而不是存成「模型懂所有技术栈」事实
  3. body 含 `**Why:**` 与 `**How to apply:**`
  4. 下一次同 agent 会话注入该 agent scope 记忆；其他 agent 不注入

## E. 检索与会话中使用

### E1. 会话开始时 seed 注入

- 每个 A 用例都已覆盖（loadForSession → MemoryReaderService → system prompt）

### E2. 会话中按需检索（search_memory 工具）

- **仅 A2/A4 路径可用**（claude SDK in-process + codex/claude CLI stdio；A3 codex SDK 不可用）
- **操作**：会话中问 agent「我之前有没有告诉过你关于 X 的偏好？」
- **预期**：agent 调 `mcp__spark_memory__search_memory`，返回相关记忆列表

### E3. recall_memory 读完整正文

- **操作**：agent 调 search_memory 拿到 id 后，再调 `mcp__spark_memory__recall_memory`
- **预期**：返回完整 markdown 正文（含 Why / How to apply）+ hitCount +1

### E4. 向量检索（embedding 配置时）

- **前置**：配置页「向量模型」配好 OpenAI 兼容 provider
- **操作**：用语义相近但关键词不同的查询（如之前记了"偏好函数式"，现在问"组件写法"）
- **预期**：向量检索召回那条记忆（FTS-only 召回不到，因为无关键词重叠）

### E5. FTS-only 降级（embedding 未配）

- **前置**：向量模型留空
- **预期**：所有检索走 FTS-only，看日志 `memory search: vector=disabled (FTS-only)`

## F. 整合 job

### F1. 触发整合

- **前置**：某 scope 攒够阈值（默认 30 条；真机测试改成 2 加速）+ 间隔满足（默认 7 天；真机改成 0.01）
- **操作**：写够 2-3 条相似/可合并的记忆，发起新 turn 触发整合 job
- **预期**：日志 `memory consolidation trigger fired`，整合后出现 `source_session_id='consolidation'` 的高阶记忆，原记忆被 superseded

### F2. MERGE 行为

- 写两条同名同义记忆 → 整合后合并成一条，另一条 invalid_at 被填、superseded_by 指向新条

### F3. ELEVATE 行为

- 写多条低阶 feedback 暗示通用模式 → 整合后升华成一条高阶 feedback

## G. 配置与错误处理

### G1. 业务错误透传（审查 CRITICAL#1）

- **操作**：手动新增一条**已存在 name** 的记忆
- **预期**：toast 显示「该 scope 下已存在同名记忆 "xxx"。请改名...」（**不是**「An internal error occurred」）

### G2. 敏感词拦截

- **操作**：手动新增 body 含 `api_key=sk-xxx` 的记忆
- **预期**：toast 显示「记忆内容含敏感信息，已被拒绝保存...」

### G3. 抽取配置错误不再静默（审查 HIGH#6）

- **前置**：故意把抽取 provider 的 API key 改错
- **操作**：点「测试抽取配置」按钮
- **预期**：toast 显示「抽取配置不可用：HTTP 401...」（**不是**默默什么都不说）

### G4. 向量维度变化

- **操作**：从 text-embedding-3-small 切到 bge-m3 → 点「重建向量索引」
- **预期**：toast 提示「向量表已重建，后台正按新模型回填...」

### G5. 列表搜索 + scope 切换清理

- 记忆面板列表上方有搜索框，输入关键词 → 即时过滤
- scope 从 Project 切到 Agent → scopeRef 输入框自动清空（不泄漏 workspaceId 成 agentId）

## H. 已知限制（非 bug，列入后续优化）

| 项 | 说明 | 影响 |
|---|---|---|
| codex SDK（API-only）不支持会话中 MCP 工具 | codex-openai-executor 架构限制 | search_memory/recall_memory 工具不可用，但 seed 注入仍有效 |
| listByScope 无完整游标分页 | 当前加安全 LIMIT 500 防极端 | 超过 500 条时只显示最新 500 条（前端搜索框二次过滤） |
| 重建向量无实时进度条 | backfill 是 fire-and-forget | toast 已提示"后台回填可能持续几分钟"，但无进度百分比 |
| 抽取/embedding 走两个 provider | embedding 仅 OpenAI 兼容（anthropic 无 embedding 模型） | 配 anthropic 抽取时向量栏只能配另一个 provider |
