# Spark Engine 执行可靠性与核心替换路线

> 状态: 实施中 | 最后核对: 2026-09-10

## 对比基线

本次按能力和实际源码核对，不以工具数量判断成熟度，也不把文档对比当作实测性能结论。

| 维度 | 参考实现 | Spark 当前状态与差距 |
| --- | --- | --- |
| 自动化交付 | [Codex 非交互模式](https://developers.openai.com/codex/noninteractive)：结构化事件、恢复执行、最终输出 | 已有事件账本、CLI/SDK 和恢复机制；还需跨宿主真实任务验收，不能直接宣称可替换现有核心 |
| 执行生命周期 | [pi agent core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)：工具执行事件、取消、继续执行 | 已有 turn/tool 生命周期；同步 task 不等于后台 agent，需要独立生命周期协议 |
| 权限一致性 | Spark 宿主 disallowedTools 必须始终生效 | 本批修复 hook approve 提前返回绕过策略；策略异常仍拒绝执行 |
| 命令取消 | 取消必须处理后代进程而非仅父进程 | 本批修复 POSIX 父进程正常退出后漏杀占管道后代；Windows 进程树仍需专门实现和平台验收 |
| 操作质量 | 任务应经过检查、实施、验证和交付 | 原内核提示词仅一句；本批增加明确的共用执行约定，但实际模型遵循度需真实任务评测 |

## 阶段 A：执行可靠性首批（已落地）

- hook approve 只替代交互 ask，不覆盖 deny，也不屏蔽策略异常；不产生会话永久授权。
- POSIX 取消升级到 SIGKILL 时按进程组处理，不再用父进程 exitCode 判断后代是否存活。
- CLI、TUI、SDK 共用提示词规定：精准读取、读后修改、独立操作才批处理、检查全部结果、不盲重试不确定副作用、按变更验证并如实交付。
- 回归覆盖三个权限模式下的宿主强制拒绝、策略崩溃、正常 hook 批准和父进程退出后的取消。

## 阶段 B：持续任务与操作反馈（实施中）

### B1：终端操作反馈（已落地）

修复准备/审批混淆、终止后活动项残留、流式正文重复、历史输入只能取回一条，以及异步异常无反馈。增加中断清理状态与运行期排队提示；全屏终端支持折叠已完成思考。测试覆盖 64 列单色终端、拒绝审批、任务异常、取消清理和历史编辑。

### B2：长命令生命周期（实施中）

第四批已落地任务内版本：bash 的 yield_ms、进程 ID、process_wait / process_cancel、游标分页、任务归属校验与退出清理。未观察完进程终态禁止正常结束；TUI 区分启动成功与命令完成。详见 [受管命令协议](spark-engine-managed-processes.md)。持久化、跨崩溃恢复和 Windows 进程树仍未完成。

后续范围：

1. 为长命令定义持久进程 ID、增量输出游标、等待、取消、退出和失联状态；先完成协议和资源所有权，再接 TUI。
2. 区分运行中、等待审批、等待外部结果、失败、取消与结果未知；账本、SDK 和桌面映射使用一致语义。
3. 增量输出必须有背压、大小上限、终端控制字符处理和完整诊断引用，避免每次把全部日志重新送给模型。
4. 完成 Windows 进程树取消与真实 shell 的平台测试。

验收：长命令持续输出、取消进程树、超时后无残留、重新连接不重复执行、日志不重复显示。

## 阶段 C：后台 Agent 与上下文恢复（待开发）

将同步 task 演进为显式 spawn/wait/message/stop 生命周期，约束子任务预算和权限继承；恢复时对未确定副作用先核对实际状态。上下文压缩必须保留任务目标、授权、未完成工具调用及结果引用，不能以摘要代替执行事实。

## 阶段 D：替换准入（待开发）

在同一任务集比较现有两个第三方核心和 Spark：成功率、误报完成率、工具失败恢复、取消耗时、进程残留、token/耗时、修改范围和最终验证。任务集至少涵盖读代码、跨文件修改、测试失败修复、权限拒绝、网络中断、长输出、会话恢复。先灰度切换并保留回退，再讨论默认核心替换。

本次验证限本地构建与自动化测试，不包含真实模型质量、桌面端到端和跨平台性能结论。GitNexus MCP 未暴露，影响检查使用调用点检索与源码、测试和 diff；索引刷新结果单独记录于交付说明。
