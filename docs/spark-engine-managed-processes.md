# Spark Engine 任务内受管命令

> 状态: 已落地 | 最后核对: 2026-09-10

## 能力与范围

CLI、TUI 和 SDK 的默认工作区工具现在支持任务内受管命令。它用于启动后需要等待、读取进度或取消的命令，不是常驻服务管理器。保留原有不带 yield_ms 的前台 bash 行为。

当前仅支持 POSIX 进程组环境。Windows 显式拒绝受管启动，原有前台 bash 仍可用。没有真实 Windows 进程树验收前不开放受管路径。

## 工具协议

1. 调用 `bash`，传入 `command` 与 `yield_ms`（0—30000 毫秒）。沿用 bash 的权限检查。启动后等待新输出、退出或达到 yield_ms，然后返回结果。
2. 若返回 `status=running`，使用 `process_wait`，传入 `process_id`、上次 `next_cursor` 和可选 `wait_ms`（默认 1000，最大 30000）。此操作只等待或读取，绝不重新执行命令。
3. 需要停止时使用 `process_cancel`，传入进程 ID 和输出游标。取消等待进程组清理，再返回状态；重复取消已结束的进程保持其终态。
4. `has_more=true` 时继续按 next_cursor 分页读取。只有终态并读完全部已捕获输出，才算观察完成。

结果为 JSON 文本，字段如下：

| 字段 | 含义 |
| --- | --- |
| process_id | 不透明随机 ID，仅在所属任务存活期间可用 |
| status | running / completed / failed / cancelled / timed_out |
| output | 本页输出；stdout/stderr 以接收顺序合并，分别使用 UTF-8 流解码器 |
| next_cursor | 下一页起点，单位是解码后字符串的 UTF-16 code unit；调用方原样回传，不自行计算字节偏移 |
| has_more | 是否还有已捕获但未返回的输出 |
| exit_code | 已退出且取得退出码时提供；非零退出对应 failed |
| error | 启动失败、取消、超时或输出超限时的诊断 |

`ok=true,status=running` 只表示本次工具操作成功返回进度，不代表命令成功。终端显示 still running 和进程短 ID，不显示 completed；后续等待结果显示相应终态。终端预览仍进行控制字符转义和长度限制。

## 归属与收尾

- ToolRunner 注入可信 sessionId、turnId 和整个 turn 的 signal。工具参数不能覆盖归属。普通单次工具的 timeout signal 不作为后台进程的生命周期。
- 读、等、取消均校验所属会话及任务。子代理和父任务使用同一个执行器也无法相互读取或停止进程。
- 同一任务、同一调用 ID、相同命令重复启动返回已有 ID；同一调用 ID 换命令报错。不同调用 ID 代表新的执行请求，模型应使用等待工具而不是重复发起 bash。
- 取消某次等待只中断等待；取消整个任务或 process_cancel 才停止进程。
- 模型尝试最终回答或预算耗尽时，若存在运行中或尚未完整读取结果的命令，内核产生 tool.process_unobserved 失败，避免将未确认命令当作已完成。
- 所有任务退出路径均等待 closeTurn 清理，再释放记录。MCP CompositeToolExecutor 转发同样的完成检查和清理接口。

## 资源边界

- 每个受管命令最长运行 120 秒，沿用进程组先 SIGTERM、再 SIGKILL 的清理机制。
- 单命令合计最多捕获 256 KiB stdout/stderr，超限则停止并记录 failed，保留已捕获前缀。
- 单页最多 2000 个 UTF-16 code unit，避免 JSON 转义后挤爆普通工具输出预算；已有 artifact 治理仍在外层生效。
- 每任务最多保留 8 个命令记录，每执行器最多 64 个；已结束记录保留到任务退出以支持幂等查询，不自动淘汰。
- 新接口为 ToolExecutor 的可选生命周期方法，现有无受管进程的执行器无需实现；旧事件 schema 保持不变。

## 尚未支持

不支持跨任务驻留、PTY/交互 stdin、进程重启恢复、持久游标、超过 120 秒的受管执行。宿主被强杀时内存清理和定时器无法执行，可能存在 OS 残留进程；进程组之外自行脱离的 daemon 也不在保证范围。不得把本实现宣称为跨崩溃的进程托管。后续持久化阶段必须定义失联核对和副作用恢复，不能自动重启旧命令。

## 验证方式

真实 Node 子进程验证启动幂等、UTF-8 跨块解码、游标读取、非零退出、等待中断、归属隔离、取消与容量限制。内核测试覆盖模型启动→等待→最终回答、提前回答拒绝、用户中断、权限拒绝和 MCP 转发；终端组件测试确认运行态不冒充完成态。测试不使用外部模型 API。
