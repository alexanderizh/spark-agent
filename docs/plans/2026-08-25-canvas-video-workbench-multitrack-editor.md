# 画布视频工作台多轨剪辑器开发计划

> 状态: 实施中 | 最后核对: 2026-08-25

## 1. 结论与建议范围

当前视频工作台已经具备资源收集、单主轨排序、片段分割与末端伸缩、列表式连播、关键帧提取，以及一组独立 FFmpeg 操作，但它仍是“素材拼接与处理工具”，还不是可完成日常成片的非线性编辑器。

下一阶段不建议继续在现有 `track: TrackClip[]` 上追加零散按钮。建议先升级为版本化的多轨工程模型，再让预览和导出共同消费同一份时间映射与渲染计划。首个实用版本应形成以下完整闭环：

1. 从当前画布、本机和上游连线收集图片、视频、音频素材。
2. 建立视频、叠加、音频、文本/字幕等类型明确的多轨时间线。
3. 完成移动、双边裁剪、分割、复制、删除、吸附、变速、画面裁剪和音量调节。
4. 支持轨道锁定、显隐、静音、独奏、排序和折叠。
5. 在预览区同步播放可见画面与多路音频。
6. 通过 FFmpeg filter graph 导出与预览语义一致的成片。
7. 从播放头或画布图片设置封面，并回写为画布视频缩略图。

首期不追求完整复刻剪映。优先覆盖高频的剪、排、叠、混、字、导出，智能抠像、美颜、目标跟踪、云模板生态等能力不进入本轮本地 FFmpeg 主线。

### 1.1 当前实施进度（2026-08-25）

- V2 工程模型、V1 纯迁移、严格解析、command reducer、有界撤销/重做、共享时间换算和吸附已经落地；主视频、叠加和音频轨进入同一多轨时间线。
- 素材面板已经支持图片、视频和音频，同一素材可重复加入轨道；本机导入、画布选择和资源拖放共同使用 V2 资源与片段模型。
- 非正数媒体时长按“元数据未知”处理，先显示 8 秒占位，元数据返回后只回填仍保留占位值的片段；连续主视频片段会保持相邻且不重叠，不覆盖用户已经做过的真实裁剪。
- 资源拖入或点击加入轨道成功后会立即选中新片段并在主预览区加载对应素材；命令被轨道规则拒绝时不改变当前选择或预览。
- 当前响应式实现已在独立 Electron 实例中按 1310×800、1024×768、800×600 三档验证：侧栏使用 300–360px 比例宽度，时间线工具栏按容器宽度切换单行图标、双行和窄屏紧凑模式，播放器分段操作在窄预览区改为保留可访问名称的图标按钮。
- 主视频轨开启磁吸后，片段拖动使用插入排序并自动闭合空隙；修复无吸附目标时错误把片段向右偏移一个自身时长的问题。红色播放头可直接拖动或用方向键微调，重复的时间线播放按钮与时间码已移除。
- 当前视频工作台目录及 FFmpeg 能力 IPC 共 27 个测试文件、153 个测试通过，Protocol 4 个测试通过；Desktop renderer/node 与 Protocol strict TypeScript 检查通过，除画布核心入口既有告警外，本轮相关生产文件 ESLint 零警告；真实合成预览、RenderPlan 导出和文本/字幕轨仍属于后续阶段。

### 2.2 当前限制

- `WorkbenchResourceKind` 只有 `video | image`，素材面板明确排除了音频。
- `VideoWorkbenchData` 只有一个 `track: TrackClip[]`，无法表达轨道类型、锁定、静音、显隐、层级和并行片段。
- `TrackClip` 只有顺序 `order`，没有绝对的 `timelineStartSec`，因此不能表达空隙、覆盖、画中画、字幕时间段和音频错位入场。
- 片段只有 `range` 和图片 `staticDuration`，缺少速度、音量、淡入淡出、画面变换、透明度、转场和文本样式。
- 当前预览是播放列表，不是合成预览；同一时刻只能展示一个视频或图片资源。
- 当前整轨导出会拒绝图片，并且只执行逐段 `trim` 后 `concat`，不能叠加画面、混音、字幕或转场。
- 参数型操作直接作用于当前预览源并生成新文件，没有形成非破坏性工程参数。
- `CanvasVideoWorkbenchModal.tsx` 已约 1840 行，`videoWorkbench.less` 已约 2770 行；后续必须按领域拆分，不能继续把功能集中堆入这两个文件。

### 2.3 可以直接复用且无需新增大包的依赖

| -------- | --------------------------------------------------- | -------------------------------------- |

| 裁剪     | 现有 `VideoCropOverlay`，仓库另有 `react-easy-crop` | 画面框选、比例裁剪、封面裁剪           |

## 3. 产品信息架构

### 3.1 桌面宽屏布局

- 顶栏：草稿名、比例/分辨率、撤销/重做、封面、导出、保存并关闭。
- 左侧素材区：画布素材、本机素材、上游素材、文本/字幕入口；支持搜索、类型筛选、排序和缺失资源提示。
- 中央预览区：合成画布、播放控制、当前时间码、安全框、画面内选中与变换手柄。
- 右侧属性区：根据当前选中对象展示片段、画面、音频、速度、文本、转场或轨道属性。
- 底部时间线：轨道控制头、标尺、片段区、播放头、缩放、吸附、分割和删除工具。

视觉继续采用当前深色、扁平、低装饰的工作台风格。轨道类型通过细色条、图标和文字区分，不使用大量套娃卡片。建议颜色为：主视频青绿、叠加视频紫、音频蓝、文本/字幕橙、特效灰紫。

### 3.2 响应式策略

- 宽度大于 1600px：素材、预览、属性三栏同时展示。
- 1200–1600px：素材与属性共用一个可切换侧栏，预览保持最大面积。
- 小于 1200px：侧栏改为覆盖式抽屉，时间线仍占满底部宽度。
- 时间线高度允许在 220–480px 之间拖动；轨道头固定，片段区横向滚动。

## 4. 多轨工程数据模型 V2

### 4.1 核心原则

- 素材是不可变来源，片段只引用素材并保存非破坏性编辑参数。
- 轨道表达“同类片段的组织与控制”，片段表达“某段素材在工程时间上的投影”。
- 所有时间统一使用秒的浮点数，展示时按工程 fps 格式化时间码。
- 预览和导出必须共享同一套 `resolveActiveClipsAtTime`、片段时间换算和 `RenderPlan`。
- 持久化结构必须带 `schemaVersion`，旧单轨数据只能通过显式迁移进入 V2。

### 4.2 建议类型

```ts
type WorkbenchTrackKind = 'video' | 'overlay' | 'audio' | 'text' | 'subtitle'

interface VideoWorkbenchDataV2 {
  schemaVersion: 2
  project: WorkbenchProjectSettings
  resources: WorkbenchResource[]
  tracks: WorkbenchTrack[]
  cover?: WorkbenchCover
  keyframes: WorkbenchKeyframe[]
  outputs: WorkbenchOutput[]
  ui: WorkbenchUiState
}

interface WorkbenchTrack {
  id: string
  kind: WorkbenchTrackKind
  name: string
  order: number
  locked: boolean
  muted: boolean
  solo: boolean
  visible: boolean
  collapsed: boolean
  clips: WorkbenchClip[]
}

interface WorkbenchClip {
  id: string
  resourceId?: string
  timelineStartSec: number
  sourceInSec: number
  sourceOutSec: number
  durationSec: number
  speed: number
  enabled: boolean
  transform?: ClipTransform
  audio?: ClipAudioSettings
  fadeInSec?: number
  fadeOutSec?: number
  transitionIn?: ClipTransition
  transitionOut?: ClipTransition
  text?: TextClipSettings
}
```

补充字段：

- `WorkbenchResource.kind` 扩展为 `video | image | audio`，记录 `mimeType`、`durationSec`、尺寸、音轨信息、波形缓存和丢失状态。
- `WorkbenchProjectSettings` 保存宽高、比例、fps、背景色、默认图片时长、音频采样率和导出预设。
- `ClipTransform` 保存位置、缩放、旋转、镜像、裁剪和透明度。
- `ClipAudioSettings` 保存 `gainDb`、静音、左右声道平衡、淡入淡出和标准化开关。
- `WorkbenchCover` 保存来源类型、源片段/资源、时间点、图片路径、预览 URL 与裁剪矩形。
- `ui` 只保存值得恢复的界面状态，例如缩放、滚动时间、轨道高度和吸附开关；临时 hover、拖拽状态不持久化。

### 4.3 旧数据迁移

1. `resourcePanel` 原样迁移到 `resources`。
2. 旧 `track` 迁入一个默认主视频轨 `V1`。
3. 按旧 `order` 累加片段时长生成 `timelineStartSec`。
4. 旧 `range` 转成 `sourceInSec/sourceOutSec`；图片 `staticDuration` 转成 `durationSec`。
5. 旧字段读取兼容至少保留一个版本周期，不在迁移时删除关键帧和产物。
6. 迁移必须是纯函数并有 fixture 测试；只有用户实际编辑并保存后才写回 V2。

## 5. 功能清单与优先级

### 5.1 P0：工程基座

| 功能            | 说明                                   | 技术实现                                     |
| --------------- | -------------------------------------- | -------------------------------------------- |
| V2 数据迁移     | 单轨无损迁入多轨                       | 版本化 parser + 纯函数迁移                   |
| 编辑 reducer    | 所有修改走统一 command/reducer         | 不新增状态库；React reducer + 不可变更新     |
| 撤销/重做       | 覆盖轨道、片段和属性操作               | 有界历史，拖动过程合并为一次命令             |
| 时间换算        | 工程时间、源时间、速度后时间统一换算   | 共享纯函数 + 单测                            |
| 吸附引擎        | 播放头、片段边界、标记点、工程起点吸附 | 像素阈值转秒，按缩放动态计算                 |
| FFmpeg 能力探测 | 启动时读取 filters/encoders 并缓存     | 不假设所有静态构建都含 `libass`/`xfade`/硬编 |
| RenderPlan      | renderer 只发结构化渲染计划            | 主进程严格校验并编译参数数组                 |
| 任务取消        | 导出和代理生成可取消                   | `AbortController` → 子进程优雅终止           |

### 5.2 P1：首个实用剪辑闭环

#### 素材管理

- 支持画布、本机和上游的图片、视频、音频资源。
- 素材按全部/视频/图片/音频筛选，支持名称搜索、导入时间排序和来源标识。
- 视频生成缩略帧；音频复用现有波形组件和 peaks 缓存。
- 同一路径素材去重，但允许同一素材多次放入时间线。
- 素材丢失时保留资源和片段，显示“重新定位”，禁止静默删除。
- 从画布选择时继续让当前选中节点排在前面。

#### 轨道

- 新建视频轨、叠加轨、音频轨、文本轨、字幕轨。
- 轨道重命名、拖拽排序、折叠、删除。
- 锁定：阻止该轨全部拖动、裁剪、分割、删除和属性修改。
- 显隐：只对画面轨生效；静音只对含音频的轨道生效。
- 独奏：存在任一 solo 轨时，仅播放/导出 solo 音频轨；画面轨可暂不提供 solo。
- 轨道头与时间线内容垂直同步滚动，标尺和工具栏保持固定。

#### 片段

- 从素材面板拖入指定轨道和指定时间点。
- 水平移动、跨同类型轨移动、双边伸缩、播放头分割、复制、删除、批量多选。
- 片段移动时支持边界吸附；按住修饰键临时关闭吸附。
- 主视频轨提供“磁吸主轨”开关；开启时删除或缩短片段会自动闭合空隙，关闭时保留绝对时间位置。
- 插入和删除提供普通/波纹两种语义，波纹模式只移动同轨后续片段，不隐式改动其它未关联轨道。
- 图片片段可调整持续时间；视频/音频片段伸缩只改变入点/出点，不改源文件。
- 支持时间线空隙和重叠；同一普通视频轨禁止重叠，叠加轨/音频轨允许并行。
- 支持“替换素材并保留时长与编辑参数”，源素材不足时明确提示截断范围。
- 支持音视频逻辑分离：视频片段静音，同时在音频轨创建对同一源文件音轨的非破坏性引用；只有导出独立音频节点时才真正抽取文件。
- 支持片段链接/取消链接，已链接的视频和音频默认同步移动、分割和删除。
- 常量变速 `0.25x–4x`，变速后自动重算工程时长；可选择音频跟随或静音。
- 画面裁剪、缩放、位置、旋转、水平/垂直镜像、透明度。
- 音量采用 dB 表达，默认 0 dB；提供静音、淡入、淡出。
- 支持时间线标记点和工程入点/出点，供定位、选区播放和选区导出使用。

#### 预览与封面

- 以一个单调时钟驱动所有当前活跃片段，避免多个媒体元素各自计时产生漂移。
- 视频/图片/文本采用绝对定位 DOM 图层预览；音频使用媒体元素与 Web Audio GainNode。
- 预览区支持画面内选择、拖动、缩放和安全框。
- 支持空格播放/暂停、逐帧、跳到首尾、J/K/L、时间码输入跳转。
- “设置封面”支持当前播放头抽帧、从画布选择图片、本机上传图片。
- 封面裁剪后保存到项目资产目录，并回写当前视频工作台/成片节点的 `thumbnailUrl`。

#### 导出

- 导出完整工程、播放头选区或选中片段。
- 首期提供 MP4/H.264/AAC 预设，以及沿用现有 WebM/MOV/GIF 能力。
- 支持分辨率、fps、CRF/质量和是否包含音频。
- 显示阶段、进度、耗时和可读错误；支持取消。
- 导出成功后进入产物面板，可添加到画布或替换当前视频节点。

### 5.3 P2：字幕、文本、转场和音频增强

| 功能       | UI 行为                                  | FFmpeg/现有能力                                                 |
| ---------- | ---------------------------------------- | --------------------------------------------------------------- |
| 文本片段   | 字体、字号、颜色、描边、背景、位置、对齐 | 优先生成 ASS；能力不足时用 `drawtext`，两者均需 capability gate |
| SRT 导入   | 导入后按条生成字幕片段，可批量改样式     | 解析在 TS，导出时生成临时 ASS/SRT                               |
| SRT 导出   | 把字幕轨导出为独立字幕文件               | 纯 TypeScript 序列化                                            |
| 淡入淡出   | 视频透明度与音频增益曲线                 | `fade`、`afade`                                                 |
| 交叉溶解   | 相邻视频片段拖出转场区                   | `xfade`，音频用 `acrossfade`                                    |
| 黑场/白场  | 片段入出转场                             | `fade=color=black/white`                                        |
| 音量标准化 | 片段或整轨一键标准化                     | `loudnorm` 两遍分析/应用                                        |
| 声道平衡   | 左右声道调节                             | `pan`/`volume`                                                  |
| 基础降噪   | 明确标注为“基础”而非 AI 降噪             | `afftdn`，过滤器可用时开放                                      |
| 画中画     | 叠加轨拖动、缩放、圆角/边框后续          | `overlay` + `scale` + `crop`                                    |
| 水印       | 图片资源转为固定叠加片段                 | 复用 overlay 管线，不再单独破坏性生成                           |

首批转场只实现 3–5 个稳定选项，不直接暴露 FFmpeg 的全部 `xfade` 枚举。所有转场先把输入统一为相同分辨率、fps、像素格式和 timebase。

### 5.4 P3：可选高级本地能力

以下能力依然不需要新增大包，但应在核心闭环稳定后逐项启用：

- 调色：亮度、对比度、饱和度、色温近似、色相、曲线和用户导入 `.cube` LUT。
- 画面效果：模糊、局部马赛克、暗角、锐化、黑白、色键抠像。
- 定格：在播放头抽帧并生成指定时长的图片片段。
- 画面适配：填充、适应、拉伸、背景色/背景模糊。
- 蒙版与混合：矩形/圆形/线性蒙版、羽化和少量稳定的混合模式，均受 FFmpeg filter 能力门控。
- 音频闪避：旁白轨激活时自动压低背景音乐，使用 `sidechaincompress`。
- 旁白录制：复用浏览器 `MediaRecorder` 和现有麦克风权限链路，录制后作为画布音频素材插入播放头位置。
- 节拍候选：用 Web Audio 计算能量峰值并生成可确认的标记点，不承诺专业 BPM/乐理识别。
- 静音段检测：使用 `silencedetect` 标记候选区间，由用户确认后批量删除。
- 代理文件：高分辨率素材生成低码率代理，预览用代理、导出用原片。
- 硬件编码：探测 VideoToolbox/NVENC/QSV 后提供开关，失败自动回退软件编码。
- 关键帧动画：位置、缩放、旋转、透明度、音量的线性关键帧；先做线性，再考虑缓动。
- 组合片段：把一组已选片段保存为可折叠的逻辑组；真正的嵌套时间线另行立项，避免首版引入递归渲染复杂度。

### 5.5 明确不进入本轮的能力

- AI 人像抠像、智能美颜、自动跟踪、口型同步、光流补帧质量增强。
- 在线模板/贴纸/音乐版权库和剪映账号生态。
- 多人实时协作、云草稿、移动端同步。
- 专业 HDR/广色域色彩管理、RAW 工作流、多机位自动对齐。
- 在没有启用平台转写模型时，FFmpeg 本身不能完成高质量语音识别和自动字幕。

## 6. 预览与导出架构

### 6.1 共享时间语义

预览与导出偏差是本功能最大的架构风险。应先把每个片段归一为以下共享计算结果：

```ts
interface ResolvedClipTiming {
  timelineStartSec: number
  timelineEndSec: number
  sourceStartSec: number
  sourceEndSec: number
  speed: number
}
```

预览协调器、吸附、波形裁剪、转场和 FFmpeg 编译器都只能调用这套纯函数，不允许各自重新解释时间。

### 6.2 预览合成器

- 使用 `requestAnimationFrame` 驱动工程时钟，播放中以 `performance.now()` 计算目标时间。
- 只挂载当前时间附近的媒体元素，离开窗口的片段暂停并释放解码压力。
- 视频漂移小于约 40ms 时不 seek，超过阈值才校正，避免频繁 seek 抖动。
- 图片、文本和字幕直接按当前工程时间控制显隐与 CSS 变换。
- 音频节点用 GainNode 处理音量与淡入淡出；暂停/seek 后统一重建调度点。
- 时间线拖动时进入 scrub 模式，只刷新画面，不自动播放多路音频。

### 6.3 FFmpeg 渲染计划

renderer 不能传任意滤镜字符串。它只发送经过协议校验的 `RenderPlan`，主进程负责：

1. 校验所有输入路径、输出目录、数值范围、轨道数和片段数。
2. 为每个视频片段生成 `trim,setpts,scale,crop,rotate,format,fps` 链。
3. 为图片片段创建指定时长的循环输入并生成画面链。
4. 按画面轨层级使用 `overlay` 合成，按片段时间增加时间偏移和 enable 区间。
5. 为音频生成 `atrim,asetpts,atempo,volume,afade,adelay`，最后通过 `amix` 混音。
6. 文本/字幕统一生成临时 ASS 或安全的 drawtext 参数。
7. 映射最终视频/音频流并编码到目标容器。

复杂工程使用 `-filter_complex_script` 临时文件，避免 Windows 命令行长度限制。临时文件写入工作台产物目录，结束、失败或取消后清理。

### 6.4 FFmpeg 能力门控

当前仓库会使用受管 FFmpeg，也允许系统 FFmpeg 回退；不同构建的 filter 和 encoder 可能不同。新增 `ffmpeg:capabilities` 查询并缓存：

- 基础过滤器：`overlay`、`scale`、`crop`、`volume`、`amix`、`atempo`。
- 转场：`xfade`、`acrossfade`。
- 字幕：`subtitles`/`ass`、`drawtext`。
- 音频增强：`loudnorm`、`afftdn`、`sidechaincompress`。
- 高级画面：`chromakey`、`lut3d`、`boxblur`、`deshake`。
- 编码器：`libx264`、`libx265`、`h264_videotoolbox`、`h264_nvenc`、`h264_qsv` 等。

必需能力缺失时阻止导出并给出完整性修复入口；可选能力缺失时只禁用对应控件，不让整个工作台失效。

- 建立长音频波形降级策略：短音频用 Web Audio peaks，长音频用 FFmpeg 波形图或分段 peaks，避免整段解码占用过多内存。

验收：拖动任一片段后预览、时间线和属性面板同步；两路画面叠加和多路音频可连续播放；封面在关闭重开后仍可见。

### 9.3 前端交互测试

- 拖入指定轨/指定时间、跨轨限制、锁定态、吸附提示、多选和撤销/重做。

- 响应式三档布局和窄屏抽屉。

### 9.4 手工验收场景

1. 主视频 + B-roll 叠加 + 背景音乐 + 旁白 + 字幕，完成 30 秒成片。
2. 视频静音、旁白独奏、背景音乐 -12 dB 并带淡入淡出。
3. 片段 2x 变速、画面裁剪为竖屏、封面取播放头画面。
4. 保存关闭后重新打开，所有轨道、位置、属性和封面一致。
5. 取消一次导出后立即重新导出，进度和临时文件状态正常。
6. 删除/移动一个源文件后打开工程，能提示重新定位而不是丢片段。

## 10. 性能、可靠性与安全约束

- 默认限制同时活跃的视频解码元素数量，超出时暂停远离播放头的预加载。
- 素材缩略图、波形和代理文件按源文件路径、大小、mtime 和参数生成缓存键。
- 工程数据只保存元数据和缓存路径，不保存 base64、大型 peaks 或逐帧缩略图数组。
- 长列表和长时间线只渲染可视区域，缩放很小时降低缩略帧密度。
- FFmpeg 继续保持最多 2 个并发任务；导出任务优先级高于后台缩略图/代理生成。
- 所有输入路径继续使用 safe-file 允许根校验，输出只写工作台产物目录或项目资产目录。
- renderer 不得提交任意 FFmpeg 参数、滤镜字符串或输出路径。
- 自动保存只 merge `videoWorkbench` 字段，避免覆盖同一节点的其它并行数据。
- 导出前建立只读工程快照，渲染过程中继续编辑不会改变正在执行的 RenderPlan。

## 11. 主要风险与应对

| 风险                       | 影响                 | 应对                                            |
| -------------------------- | -------------------- | ----------------------------------------------- |
| 预览与导出时间语义不一致   | 成片错位、转场错帧   | 共享 timing 纯函数和 RenderPlan，不允许两套计算 |
| 多视频元素时钟漂移         | 预览卡顿、音画不同步 | 单调主时钟 + 阈值校正 + 活跃元素限流            |
| FFmpeg 构建能力不同        | 部分机器导出失败     | filters/encoders 探测与 UI capability gate      |
| VFR 与不同 fps 素材        | 转场/帧步进误差      | 工程时间仍用秒，导出链统一 fps/timebase         |
| Windows 命令过长和路径转义 | 复杂工程无法导出     | `filter_complex_script` + 参数数组 + 路径测试   |
| AudioContext 解码长音频    | 内存峰值过高         | 长音频改 FFmpeg 波形缓存或分段采样              |
| 单文件继续膨胀             | 难维护、并行修改冲突 | 按 model/timeline/preview/inspector/export 拆分 |
| 资源移动或删除             | 草稿片段丢失         | 保留悬空引用、显式重定位、禁止静默过滤          |

## 12. 建议首个版本边界

如果要尽快从“作用不大”提升到“能真实做片”，建议首个发布版本只承诺：

- 图片/视频/音频素材管理。
- 主视频、叠加视频、音频三类轨道。
- 轨道锁定、显隐、静音、独奏。
- 片段移动、双边裁剪、分割、复制、删除、吸附、图片时长。
- 恒定变速、音量、淡入淡出、裁剪、位置、缩放、旋转、镜像、透明度。
- 磁吸主轨、普通/波纹编辑、素材替换、音视频分离与链接。
- 多轨同步预览。
- 播放头抽帧或图片设置封面。
- MP4/H.264/AAC 多轨导出和画布回填。
- 撤销/重做、自动保存、导出取消、资源丢失重定位。

文本/字幕和转场可紧随其后作为第二个小版本。这样首版的技术闭环完整、用户价值明确，也不会因一次追求剪映全部功能而把时间线、预览和导出三条主链同时做散。
