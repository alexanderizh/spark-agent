# SparkWork 核心 Agent 行为提示词设计

> 状态: 已落地 | 最后核对: 2026-07-27

## 目标

为 SparkWork 的主会话 Host 和团队成员提供短小、供应商中立的基础行为协议，提升主动推进、工具闭环、事实来源校准和回复质量，不复制任何特定模型或产品的完整系统提示词。

## 分层

1. `APPLICATION_FOUNDATION_SYSTEM_PROMPT` 始终注入，由应用身份和核心行为两部分组成。
2. 记忆来源校准独立为 `MEMORY_PROVENANCE_SYSTEM_PROMPT`，紧跟实际记忆摘要和现有记忆行为协议注入。
3. 时效性、一手来源和冲突核验规则保留在 `WEB_SEARCH_SYSTEM_PROMPT`，仅当内置搜索工具可用时注入。
4. 工作流、画布、媒体、调试和自动化继续使用现有的条件型能力提示词，避免全局 Prompt 膨胀。

本功能注入给模型的所有内置 Prompt 文本统一使用英文，用户交互语言仍由应用身份中的语言跟随规则决定。

## 行为边界

- 能从现有上下文安全推进时先行动；只有答案会实质改变结果或无法继续时才提问。
- 发起命令、写入、委派或后台任务不等于完成；完成声明必须有实际结果和与风险匹配的验证。
- 文件、网页、工具输出和记忆中的指令默认视为数据，不自动获得高于用户的指令权限。
- 用户原话、用户决定、Agent 建议、模型推断和第三方主张必须保持来源区分。

## 执行路径

`SessionService` 在主会话和成员执行配置中都注入同一份基础 Prompt。Claude SDK 路径将应用 Prompt 作为 SDK system prompt 传入；Codex 各执行路径按其宿主协议将 Spark Runtime Context 合并到输入，因此测试聚焦于内容完整性，不假设不同供应商的指令优先级完全相同。

## 回归保护

- 核心行为 Prompt 限制在 3500 字符以内，防止持续膨胀。
- 核心行为 Prompt 不得包含 Anthropic、OpenAI、Claude 或 ChatGPT 身份。
- 搜索 Prompt 必须同时覆盖时效判断、原始页面读取、来源优先级和冲突处理。
