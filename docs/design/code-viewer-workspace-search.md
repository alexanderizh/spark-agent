# 内置编辑器工作区搜索

> 状态: 已落地 | 最后核对: 2026-08-25

## 目标与入口

代码侧栏提供独立搜索视图，与文件树、Git 面板互斥复用左侧栏空间：

- 搜索面板首次使用默认进入内容搜索；`Cmd/Ctrl+P` 显式切到文件搜索。
- 代码面板范围内（文件树、Git、搜索、Monaco 任一板块）`Cmd/Ctrl+F` 切到内容搜索，`Cmd/Ctrl+P` 切到文件搜索；捕获阶段会阻止 Monaco 和应用全局快捷键重复响应。
- 代码面板外仍沿用 Spark 的全局快捷键；`Cmd/Ctrl+Shift+F` 继续作为全局“打开代码内容搜索”入口。

搜索结果点击后复用 `openInCodeTab(relativePath, { lineNumber })`，内容命中会切回源码模式并定位对应行。

结果区支持树形 / 列表切换。树形下，文件搜索展示「目录 → 文件」，内容搜索展示「目录 → 文件 → 命中行」；列表下直接按相关度展示文件或逐条内容命中。两种布局都使用虚拟滚动。目录数量表示后代文件数或命中总数，内容文件数量表示该文件的命中数；折叠状态只影响当前可见行，不会重新触发磁盘搜索。

搜索上下文按 `workspaceId` 缓存：文件查询、内容查询分别保留，大小写选项与结果布局一并恢复。用户切换到文件树或 Git 再返回搜索时，输入不会丢失；重新挂载后按缓存条件刷新结果，避免长期展示磁盘变更前的陈旧快照。

## 分层实现

- `packages/protocol/src/workspace-search.ts` 定义文件搜索、内容搜索、取消和流式结果协议。
- `WorkspaceSearchService` 负责工作区索引、文件名打分、并发文本扫描、结果截断和请求取消。
- `registerWorkspaceSearchIpc` 解析工作区根路径并把内容匹配分批推送到渲染端。
- `search-panel/` 封装侧栏 UI、持久化可见性/宽度/模式、项目级搜索上下文，以及防抖和流竞态处理。

内容搜索的 `requestId` 由渲染端预生成 UUID，并在调用主进程前设为当前令牌。这样即使空仓库或极快搜索先返回流终态，也不会因为 IPC 响应尚未抵达而丢失结果。不同窗口使用独立 UUID，可并行搜索且只取消自己的上一轮请求。

## 性能护栏

- 文件索引按工作区缓存 30 秒，最多保留 8 个工作区；显式刷新可强制重建。
- 目录遍历使用游标队列，避免大目录下 `Array.shift()` 的二次复杂度。
- 固定跳过依赖、构建产物和 worktree 容器，并应用逐层 `.gitignore` 规则；符号链接不跟随。
- 索引最多 20 万文件 / 3 万目录；内容搜索跳过空文件、二进制文件和超过 1 MB 的文件。
- 内容扫描并发上限为 8，单文件最多 50 个匹配，全局默认最多 2000 个匹配。
- 结果按 30 条或 120 ms 分批推送，渲染端使用虚拟列表；输入防抖为文件 200 ms、内容 400 ms。
- 搜索结果树由已返回路径一次线性聚合，目录继承最高相关度后代的顺序；树形只把当前展开节点压平成虚拟行，列表则直接虚拟化扁平命中，折叠分支不会创建 DOM。
- Enter 立即搜索会取消待执行的防抖计时器；切换模式或关闭面板会停止旧扫描。

## 验证

- 协议 schema 测试覆盖 UUID、查询长度和结果上限。
- 服务测试覆盖 ignore、缓存刷新、文件打分、二进制过滤、长行上下文、取消、截断和多窗口并行。
- 渲染端测试覆盖快捷键路由、面板互斥、默认内容模式迁移、项目级搜索上下文、Enter 去重和“流事件早于 IPC 响应”竞态。
- `@spark/desktop` 双 TypeScript 项目检查通过；搜索与代码查看器相关聚焦测试通过。
- 真实界面仍需验收默认内容模式、树/列表切换、缓存恢复、快捷键聚焦与跳转手感。
