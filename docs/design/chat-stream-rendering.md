# 对话流式渲染性能

> 状态: 已落地 | 最后核对: 2026-07-19

对话事件先由 `LiveAgentEventBuffer` 按 animation frame 合并，再由 `MessageBuilder` 更新消息模型，避免同一帧内多次提交 React 状态。历史消息通过 memo 与长会话虚拟列表隔离，流式增量只需要更新当前消息。

Markdown 流式正文按 fenced code 之外的空行划分为“稳定前缀”和“活动尾段”：

- 已完成段落的解析结果进入有上限的缓存，后续 token 不再重复解析这些段落。
- 只有仍在增长的末尾段落重新解析和渲染。
- fenced code 内的空行不能作为边界，避免把未闭合代码块拆坏。
- 流式结束后完整解析一次最终正文，保证表格、列表、代码块和文档卡片语义与非流式消息一致。

稳定前缀缓存最多保留 64 项，防止长时间使用后无界增长。未完成代码块继续使用纯文本展示，闭合后才执行 Shiki 语法高亮，避免对每个代码 token 重跑高亮器。
