# 登录注册验证码状态设计

> 状态: 已落地 | 最后核对: 2026-07-14

## 目标

统一桌面端邮箱验证码、短信验证码和图片验证码的生命周期，避免验证码用途、账号目标和前端倒计时互相脱节。

## 服务端契约

- 图片验证码有效期为 5 分钟，校验成功后单次消费。
- 邮箱验证码按 `code:{register|login}:{normalizedEmail}` 存储，有效期由 `expire_in` 返回。
- 手机短信登录同时承担首次注册，验证码统一按 `code:login:{phone}` 存储和校验。
- `send-sms` 的旧 `type=register` 参数仅用于兼容和短信场景文案，不再决定 Redis 验证码键。
- 业务验证码重发冷却为 60 秒，与验证码有效期是两个独立时间概念。

## 桌面端状态约束

1. 发送业务验证码前必须校验当前账号和图片验证码。
2. 发送成功后立即刷新图片验证码并清空旧答案，因为旧图片验证码已被服务端消费。
3. 业务验证码必须绑定发送时的规范化账号；用户修改邮箱或手机号后，旧验证码和倒计时立即失效。
4. 邮箱/短信验证码提交阶段不再要求图片验证码；密码登录仍要求图片验证码。
5. 从发送请求发起时间开始，使用服务端 `expire_in` 计算业务验证码有效截止时间，并使用独立的 60 秒截止时间计算重发冷却。
6. 所有倒计时基于绝对时间戳，应用休眠或切到后台后按真实经过时间恢复。

## 回归测试

- 邮箱验证码登录和注册必须先成功发送，再允许提交。
- 手机号登录和注册必须使用同一个 `login` 验证码键。
- 发送成功刷新图片验证码后，业务验证码仍可提交。
- 修改账号必须清空已输入验证码并禁用提交。
- 60 秒后允许重发，但服务端返回的 5 分钟有效期内验证码仍可提交。
- 新旧客户端传递 `register` 短信用途时，服务端都必须写入 `code:login:{phone}`。
