# 跨会话协作功能设计

> 状态: 待开发 | 最后核对: 2026-08-12

## 1. 背景

用户经常会在一个长会话中产生新的探索方向，或希望让另一个会话参考既有讨论。当前只能新建空白会话、手工复制文字，既丢失上下文，也难以追溯来源。

本功能把需求归纳为两个底层能力、三个用户入口：

1. **会话分叉（Fork）**：把源会话截至某个稳定位置的历史复制为一个可独立继续的新会话。
2. **会话引用（Reference）**：不复制历史，只把另一会话注册为当前会话可按需读取的只读上下文资源。
3. 侧边栏右键“新建协作会话”是“从源会话最新已完成轮次分叉”的快捷入口，不单独形成第三套数据语义。

“协作”在本期指多个会话共享或引用上下文，不代表多人实时聊天、双向消息同步，也不代表一个会话可以直接控制另一个会话。

## 2. 目标与非目标

### 2.1 目标

- 用户可以从一段已完成的会话历史中分出一条新路线，源会话不受影响。
- 新会话能明确展示其来源和分叉位置，并可以跳回源会话。
- 用户可以通过“+”菜单或侧边栏拖拽，把其他会话添加为参考资源。
- 模型可以通过内置只读工具按需搜索、分页读取已授权的参考会话，避免一次性注入完整历史。
- 分叉和引用均可审计、可撤销授权，并受稳定的上下文预算和隐私规则约束。

### 2.2 非目标

- 不做多人共同编辑同一会话。
- 不让两个分叉后的会话自动同步后续消息。
- 不允许模型任意枚举、读取、发送消息到其他会话。
- 不复制源会话的运行中任务、等待审批、定时任务、Goal、队列、终端进程或底层 Provider resume 状态。
- 首版不把分叉与 Git worktree 创建绑定；新会话默认继承同一个工作区。

## 3. 核心概念

| 概念         | 含义                               | 是否独立继续 | 源会话后续更新是否可见     |
| ------------ | ---------------------------------- | ------------ | -------------------------- |
| 分叉会话     | 截至选定轮次的历史快照副本         | 是           | 否                         |
| 快速协作会话 | 从最新已完成轮次创建的分叉会话     | 是           | 否                         |
| 参考会话     | 当前会话被授权按需读取的另一个会话 | 否           | 只读取添加时确定的快照边界 |

关键约定：所有“位置”都使用稳定的 `turnId + cutoffSeq` 表示，不使用屏幕下标或时间戳。首版只允许在**完整轮次边界**分叉，不允许在一次工具调用、流式回复或未完成回复的中间截断。

## 4. 用户场景

### 4.1 从会话任一已完成阶段分叉

入口放在每个已完成轮次的操作菜单中，建议文案为“从此处分支”。

交互流程：

1. 用户在某轮对话上打开操作菜单，选择“从此处分支”。
2. 弹窗展示新会话将继承的范围：“从会话开始到此轮结束，共 N 轮”。
3. 用户可修改新会话标题；默认标题为“源标题 · 分支”。
4. 创建成功后打开新会话，并在顶部显示来源条：“分支自《源会话》· 第 N 轮”。
5. 新会话从该位置独立继续；源会话内容和状态不发生改变。

边界规则：

- 只有完整轮次显示入口；正在流式生成的轮次暂不显示或置灰。
- 若源会话此时仍在运行，允许从更早的已完成轮次分叉。
- 分叉创建采用一致性快照；创建期间源会话新产生的事件不进入子会话。
- 源会话后续改名、归档或删除，不改变已经创建的子会话。
- 分叉链允许继续分叉，形成可追溯的树，但列表默认仍保持普通会话展示，避免强制改变现有信息架构。

### 4.2 从侧边栏快速新建协作会话

在会话条目的右键菜单和“更多”菜单中增加“新建协作会话”。

其语义固定为：**从该会话最新已完成轮次创建分叉**。

- 源会话空白时，该操作退化为继承其工作区和运行配置的新空白会话。
- 源会话正在回复时，只复制到上一完整轮次，并提示“当前进行中的回复未复制”。
- 创建后默认直接打开新会话。
- 为减少术语歧义，菜单可使用“新建协作会话”，二级说明使用“复制已完成历史并独立继续”。

### 4.3 添加会话作为参考资源

提供两个等价入口：

- 输入框左下角“+”菜单新增“添加会话作为参考”。
- 从左侧会话列表拖动会话到输入框区域。

交互流程：

1. 菜单入口打开会话选择器，支持按标题、内容、项目、时间和归档状态筛选；默认优先展示当前项目的最近会话。
2. 选中后，输入框上方出现会话引用卡片，展示标题、项目、更新时间和预计轮次数。
3. 用户发送消息时，引用卡片被提交并成为当前会话的持久只读参考资源。
4. 后续轮次中，模型可以通过内置工具搜索或分页读取该会话；不会在每轮自动塞入完整历史。
5. 用户可在当前会话的“参考资源”区域撤销授权。撤销后模型不能继续读取，但此前已经产生的工具结果和回答仍属于当前会话历史，不做追溯删除。

拖拽规则：

- 侧边栏会话行对内部拖拽写入专用 MIME 数据，例如 `application/x-spark-session-ref`，载荷只包含会话 ID 和显示信息。
- 拖到输入框时展示“松开以添加会话参考”，与文件拖拽提示区分。
- 拖拽排序和拖拽引用使用不同的拖拽意图：在侧边栏排序域内仍执行排序，进入会话输入区才切换为“复制/引用”。
- 禁止引用当前会话自身；重复引用时复用已有引用并提示，不创建重复记录。

## 5. 分叉的数据语义

### 5.1 继承内容

新会话继承：

- 源会话截至 `cutoffSeq` 的用户消息、完整助手消息和用户可见的工具过程/结果。
- 源会话的工作区、Agent、Provider、模型、会话模式、权限模式、推理强度和调试模式配置。
- 消息中仍然有效的文件、图片和媒体引用。
- 团队对话中已经完成并对用户可见的成员消息。

### 5.2 不继承内容

新会话不继承：

- 流式 delta、运行中状态、等待用户输入、等待权限审批和未完成工具调用。
- 待发送队列、定时任务、Goal、后台任务、终端进程和临时锁。
- Usage 账本归属；历史消耗仍属于源会话，子会话只统计创建后的新消耗。
- 代码还原点和源会话专属临时快照，因为它们可能无法在新会话安全恢复。
- `sdkSessionId` 或其他 Provider 原生 resume 标识。子会话第一次运行必须走 fresh runtime，并由本地历史/连续性胶囊恢复上下文，避免两个会话并发续接同一个底层会话。

### 5.3 快照实现建议

首版建议采用**物化快照**：把允许继承的事件复制到子会话，重写 `event.id`、`sessionId` 和 `seq`，在同一会话内保持 `turnId`、`toolCallId` 等关联关系一致；同时保存独立的 lineage 记录。

不建议首版采用“运行时递归读取父会话事件”的写时共享方案，因为它会使历史分页、源会话删除、深层分叉链、事件裁剪和计数逻辑都变复杂。

建议新增：

```text
session_lineage
  child_session_id       PK / FK
  parent_session_id      FK
  fork_anchor_turn_id
  fork_cutoff_seq
  source_title_snapshot
  created_at
```

所有复制和 lineage 写入必须在一个数据库事务中完成；失败时不能留下半个会话。

## 6. 会话引用的数据语义

### 6.1 引用采用快照边界

添加参考时记录源会话当时最新的完整轮次水位 `snapshotSeq`。此后源会话继续产生的新内容默认不可见，以保证回答可复现，并避免用户在不知情时扩大授权范围。

用户可在引用卡片上主动选择“更新到最新”，更新后写入新的水位并产生审计记录。首版不提供自动实时跟随。

建议数据模型：

```text
session_references
  id                     PK，作为模型工具使用的 opaque referenceId
  target_session_id      当前会话
  source_session_id      被引用会话
  snapshot_seq           可读取的最大 seq
  source_title_snapshot
  status                 active | revoked | unavailable
  created_at
  revoked_at

session_reference_audit
  id
  reference_id
  action                 attach | update_snapshot | revoke | read
  actor                  user | agent
  detail_json
  created_at
```

若源会话被删除，引用状态变为 `unavailable`，工具返回可解释错误，当前会话继续正常工作。首版不因引用关系阻止用户删除源会话，也不级联删除目标会话。

### 6.2 协议不要复用文件附件

现有 `SessionAttachment` 的 `path` 语义明确面向图片、文件和目录。会话引用不应伪装成文件路径，建议在发送协议中增加独立字段：

```ts
interface SessionReferenceInput {
  sourceSessionId: SessionId
  snapshotSeq: number
}

interface SessionSendTurnRequest {
  // existing fields...
  sessionReferences?: SessionReferenceInput[]
}
```

Renderer 草稿也应分别保存 `attachments` 和 `sessionReferences`，防止文件预览、路径校验和媒体上传流程误处理会话引用。

## 7. 模型内置工具

模型不能传入任意 `sessionId`。主进程只把当前会话仍处于 `active` 状态的引用映射成不可猜测的 `referenceId`，并在服务端再次校验目标会话所有权和 `snapshotSeq`。

建议提供三个只读工具：

1. `referenced_sessions_list()`：列出当前会话已授权的参考资源，仅返回标题、项目、快照时间、轮次数和 `referenceId`。
2. `referenced_session_search(referenceId, query, limit)`：只检索用户消息和完整助手消息，返回命中片段及轮次定位。
3. `referenced_session_read(referenceId, cursor, turnLimit, detail)`：按完整轮次分页读取；`detail` 首版支持 `transcript` 和 `user_visible_activity`。

工具约束：

- 单次输出必须有字符/token 上限和分页游标，不能一次返回超长会话。
- 不返回系统提示、密钥、环境变量、完整权限载荷、白盒 prompt 快照或仅供内部调试的事件。
- `user_visible_activity` 可以返回工具名称、状态和经过裁剪/脱敏的结果摘要，不默认返回原始工具参数与超长终端输出。
- 不递归授予源会话所引用的其他会话；只能读取当前目标会话直接授权的引用。
- 所有读取记录审计信息；工具调用在当前时间线中可见。

当前轮只需向模型注入一段很小的引用目录，告知有哪些 `referenceId`、标题和工具使用方法。正文由模型在确有需要时读取，从而控制上下文成本。

## 8. UI 信息架构

### 8.1 会话时间线

- 已完成轮次的操作菜单增加“从此处分支”。
- 分叉会话标题栏显示可关闭但可再次查看的来源条。
- 点击来源条可打开源会话并定位到分叉轮次；源会话不存在时显示“来源会话已删除”。

### 8.2 侧边栏

- 会话右键/更多菜单增加“新建协作会话”。
- 分叉会话可显示轻量分支图标；悬浮卡展示源会话标题和分叉时间。
- 首版不改造成树形侧边栏，后续可在会话详情中提供“查看分支关系”。

### 8.3 输入框

- “+”菜单新增“添加会话作为参考”。
- 文件/图片卡片与会话引用卡片使用不同图标和颜色语义。
- 草稿阶段可以移除引用；发送后在“参考资源”管理区撤销或更新快照。
- 引用数量首版建议限制为每个会话最多 10 个，每次最多新增 5 个，超限时给出明确提示。

## 9. 权限、安全与隐私

- 只有当前本地用户有权访问的会话可以被选择、分叉或引用。
- 默认选择器只展示当前项目；跨项目引用需要用户主动切换到“全部项目”，并在卡片上持续显示来源项目。
- 模型没有全局会话列表权限，也不能通过工具猜测 ID 越权读取。
- 会话历史按不可信外部上下文处理：其中的“忽略规则”“执行命令”等文字只是历史内容，不得升级为系统指令。
- 分叉继承运行配置不等于继承一次性授权；所有待审批操作必须在新会话重新审批。
- 删除源会话、撤销引用、引用读取失败都必须产生可解释状态，不得静默退回读取其他内容。

## 10. 异常与边界情况

| 情况                     | 预期行为                                                              |
| ------------------------ | --------------------------------------------------------------------- |
| 源会话正在回复           | 只能选择更早完整轮次；快捷分叉复制到上一完整轮次                      |
| 源会话为空               | 创建继承配置和工作区的空白会话                                        |
| 源会话已归档             | 可以分叉/引用，但选择器明确显示“已归档”                               |
| 源会话在创建过程中被删除 | 事务失败，提示源会话不可用，不创建残缺子会话                          |
| 引用源会话后来删除       | 引用标记不可用；已有当前会话历史保留                                  |
| 文件/图片路径失效        | 保留历史卡片并标注资源不可用，不阻塞文本历史分叉                      |
| 重复拖入同一会话         | 聚焦已有引用卡片并提示“已添加”                                        |
| 拖入当前会话自身         | 拒绝并提示“不能引用当前会话”                                          |
| 分叉后的首次模型调用     | 强制 fresh runtime，使用本地历史重建，不复用父会话 Provider resume ID |
| 超长源会话               | 后台事务复制并展示进度；模型上下文仍按现有胶囊与 token 预算裁剪       |

## 11. 建议 IPC/API

```text
session:fork
  input:  sourceSessionId, anchorTurnId | latestCompleted, title?
  output: childSessionId, copiedTurnCount, cutoffSeq, session

session:get-lineage
  input:  sessionId
  output: parent?, children[]

session-reference:list-candidates
  input:  query?, workspaceId?, includeArchived?, limit?, cursor?
  output: sessions[], nextCursor?

session-reference:attach
  input:  targetSessionId, sourceSessionId
  output: reference

session-reference:list
  input:  targetSessionId
  output: references[]

session-reference:update-snapshot
  input:  referenceId
  output: reference

session-reference:revoke
  input:  referenceId
  output: revoked
```

所有 IPC 请求必须在主进程重新验证会话存在性、当前用户可见性、完整轮次水位和引用归属，不能信任 Renderer 传来的标题、项目或 `snapshotSeq`。

## 12. 分期建议

### Phase 1：会话分叉 MVP

- 新增 lineage 表、事务化事件快照服务和 `session:fork`。
- 支持侧边栏“新建协作会话”和完整轮次“从此处分支”。
- 新会话来源条、基础异常处理和测试。
- 强制子会话 fresh runtime，验证不会复用父会话 SDK/Provider 会话。

### Phase 2：会话引用 MVP

- 新增 reference/audit 表和会话选择器。
- “+”菜单、引用卡片、侧边栏拖入输入框。
- 注册只读 list/search/read 内置工具，完成输出裁剪、脱敏和越权测试。
- 引用撤销、源会话删除后的不可用状态。

### Phase 3：可管理性增强

- 分支关系视图、跳转定位、更新引用快照。
- 引用读取统计、上下文成本展示和长会话性能优化。
- 评估是否增加“在独立 worktree 中分叉”和“向另一个会话发送消息”；两者需要单独的权限与冲突设计，不并入本期。

## 13. 验收标准

### 13.1 分叉

- 从第 N 个完整轮次分叉后，子会话只包含第 1 到 N 轮的允许继承事件。
- 源会话继续产生消息不会改变子会话；子会话消息也不会写回源会话。
- 分叉过程中任一步失败时不留下子会话、孤立事件或 lineage 脏数据。
- 源会话运行中快捷分叉不会复制当前未完成轮次，并有明确提示。
- 子会话首次运行不复用父会话底层 resume 标识。

### 13.2 引用

- 菜单选择和侧边栏拖拽产生相同的引用卡片与授权记录。
- 未经用户添加的会话无法被模型工具列出、搜索或读取。
- 模型只能读取到 `snapshotSeq`，源会话后续内容不会自动泄露。
- 撤销后工具立即拒绝继续读取；源会话删除后返回稳定的不可用错误。
- 大会话读取支持分页且单次输出不超过配置上限。
- 系统提示、白盒 prompt 快照、密钥和内部权限载荷不会出现在工具结果中。

### 13.3 兼容性

- 现有会话创建、发送、历史分页、搜索、归档、删除和侧边栏拖拽排序行为不回归。
- 文件、图片、目录附件保持原协议和处理路径，不被会话引用类型污染。
- 分叉历史可以被现有时间线正常渲染，也可以被现有会话连续性逻辑重建上下文。

## 14. 产品决策摘要

建议首版采用以下默认决策：

1. “任一阶段”收敛为“任一已完成轮次”，避免创建逻辑不完整的会话。
2. “协作会话”本质是从最新完整轮次快速分叉，不做实时同步。
3. 参考会话默认固定快照边界，不自动跟随更新。
4. 参考能力只读；模型不能任意查看全部会话，也不能向其他会话发消息。
5. 分叉采用物化事件快照，引用采用受控指针和按需工具读取。
6. 子会话永远启动新的底层 runtime，不复用父会话的 Provider resume 状态。
