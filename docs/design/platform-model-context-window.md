# 平台官方模型级上下文窗口设计

> 状态: 已落地 | 最后核对: 2026-08-13

## 背景

Spark 平台官方 Provider 同时包含多个对话模型。上下文窗口如果只保存在 Provider 级别，会让不同模型共享同一个窗口配置，无法准确表达模型能力，也会让模型切换后的历史预算和画布文本预算产生偏差。

## 目标

- 在平台官方模型设置中按单个文本模型配置上下文窗口。
- 保存、目录刷新、会话运行时和画布文本任务使用同一份模型级配置。
- 保留旧版 Provider 级 `contextWindow` 的兼容读取，并在首次保存模型级配置时完成迁移。
- 普通 Provider 继续使用现有 Provider 级上下文窗口表单和运行时语义。

## 数据结构

平台受管 Provider 的 `config_json` 增加可选字段：

```json
{
  "modelContextWindows": {
    "glm-5": 1000000,
    "deepseek-v4": 256000
  }
}
```

约定：

- key 必须是当前平台目录中的文本模型 ID，value 为 1,024～10,000,000 的整数 tokens。
- 没有 key 的模型先回落到兼容的 Provider 级 `contextWindow`，再回落到 `supportsMillionContext` / 运行时默认值。
- 模型被用户禁用时保留其 key，重新启用后继续生效。
- 平台目录刷新时只保留仍存在的模型 key，下线模型的 key 清理。
- 首次从旧版统一配置保存模型级设置时，将旧值迁移到当前目录中的模型；之后删除 Provider 级 `contextWindow`，避免新增模型继续继承旧的统一值。

## 页面交互

平台官方模型设置弹窗保留默认模型选择和模型启用开关，将对话模型展示为表格：

| 启用 | 模型          | 上下文窗口                              |
| ---- | ------------- | --------------------------------------- |
| ☑    | `glm-5`       | 默认 / 200K / 256K / 400K / 1M / 自定义 |
| ☑    | `deepseek-v4` | 默认 / 200K / 256K / 400K / 1M / 自定义 |

自定义值复用普通 Provider 表单的交互和校验：整数，范围 1,024～10,000,000。选择“默认”会移除该模型的映射，不会影响其他模型。图片模型继续只读展示，不参与上下文窗口配置。

## 运行时解析

统一解析优先级为：

```text
modelContextWindows[selectedModel]
  → contextWindow（旧版兼容）
  → supportsMillionContext ? 1M : 200K
```

会话运行时使用最终路由到的模型 ID；画布文本任务使用最终选择的模型 ID。这样自动路由和手动切换模型都不会误用初始 Provider 的窗口配置。

## 验证

- 共享解析函数覆盖模型级优先级与 Provider 级回落。
- ProviderService 覆盖模型映射保存、禁用模型保留和目录下线清理。
- 平台设置弹窗覆盖每模型独立显示。
