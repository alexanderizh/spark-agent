# Agent 快捷回复建议工具设计

> 状态: 已落地 | 最后核对: 2026-07-31

## 目标

当 Agent 用普通文本向用户请求简单确认或方向选择时，可以自主决定是否提供最多四条快捷回复。用户点击后，应用把对应文本立即作为一条普通用户消息发送，并即时隐藏本组建议。

快捷回复不是结构化问答，也不是权限审批。它只减少用户输入短文本的成本，不建立新的阻塞控制流。

## 工具契约

内置 MCP 工具名为 `mcp__spark_ui__suggest_replies`，参数为：

```json
{
  "replies": ["确认无误", "需要调整", "先暂停"]
}
```

- Agent 自主判断是否调用，不要求每轮出现。
- 每次接受 1～4 条去重后的非空文本。
- 每条最多 40 个字符，按钮文字与发送内容完全一致。
- 工具为非阻塞工具；Agent 调用后继续给出与选项匹配的最终提问并结束本轮。
- 与 `AskUserQuestion`、`request_user_input` 互斥，同一轮只能选择一种交互方式。
- 不得用于文件、命令、网络、账户、支付、删除等权限或高风险授权。

## UI 生命周期

Renderer 把固定工具调用映射为 `quick_replies` UI Block，不在消息时间线渲染普通工具卡。Composer 从最新用户消息之后的 assistant blocks 中选取最新一组建议。

以下情况不展示或立即取消展示：

1. 同一段未消费历史中存在未回答的结构化问答。
2. Agent 仍在运行、输入框已有草稿或已有附件。
3. 用户点击任意快捷回复；点击文本立即通过普通 `sendTurn` 通道发送。
4. 用户自行发送消息、新用户消息进入事件流、切换会话或产生更新的一组建议。

历史回放不持久化额外“已点击”字段：新用户消息天然构成消费边界，因此应用重启后不会恢复已经回答过的旧建议。

## 兼容性

`spark_ui` 使用独立 stdio MCP server，并通过统一 `SDKExecutorConfig` 装配到 Claude SDK、Codex SDK 和本地 CLI Host 路径。成员 Agent 不装配该工具，避免成员绕过 Host 直接影响用户输入区。
