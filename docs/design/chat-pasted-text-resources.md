# 会话超长文本粘贴引用资源

> 状态: 已落地 | 最后核对: 2026-08-26

## 目标

会话输入区粘贴超过 3000 字符的纯文本时，不把全文铺平到输入框和用户消息气泡，而是保存为 `.txt` 会话附件。Agent 按现有文件附件协议读取原文，历史会话继续使用时附件仍然可用。

## 交互规则

- `Cmd+V` / `Ctrl+V`：纯文本长度大于 3000 字符时自动转为引用资源；等于或小于阈值时按普通文本插入。
- 右键「粘贴为文本」：无条件插入输入框，优先级高于自动阈值。
- 右键「粘贴为资源」：无条件保存为 `.txt` 附件，短文本也可主动引用。
- 剪贴板包含图片时维持既有图片粘贴逻辑，不同时创建文本附件。
- 单轮附件已达到 20 个时，在写文件前阻止转换并给出提示，避免产生未被会话引用的持久文件。

## 数据与运行链路

1. 渲染进程提取 `text/plain`，生成首个非空行摘要和字符数展示名。
2. `file:save-pasted-text` IPC 校验请求后，把 UTF-8 文本写入 `{userData}/attachments/pasted-texts/`。
3. 输入区只保存标准 `SessionAttachment { type: 'file', path }`，沿用草稿、消息事件和历史恢复协议。
4. Agent Runtime 的 `prepareTurnAttachments` 校验文件存在，并通过 `additionalDirectories` 授权附件目录；各执行器提示 Agent 按需使用文件读取工具。
5. 设置页的存储用量统计包含 `attachments/`，便于观察会话附件占用。

## 持久化与边界

- 会话附件不能写入系统临时目录；macOS/Linux 可能周期清理临时文件，导致历史消息中的附件路径失效。
- 当前粘贴文本附件与既有普通文件附件使用同一消息协议，不把全文重复写入 prompt。
- 当前版本不提供附件正文展开预览和阈值设置项；阈值集中定义在 `composer-pasted-text.ts`。
- 用户主动移除尚未发送的附件、删除会话或删除消息时，持久文件回收仍沿用现有附件生命周期策略，后续可统一建设引用计数或会话级垃圾回收。
