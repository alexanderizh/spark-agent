# 无限画布 Prompt 参数编排器

> 状态: 已落地 | 最后核对: 2026-07-20

## 文本任务执行路径

画布中的文本类操作节点（文本生成、改写、提示词优化、分镜文本等）按所选 Provider 选择执行通道：

- 选择普通文本/多模态 Provider 时，继续使用 `canvas:task:generate-text` 的 HTTP API 路径。
- 选择内置的本地 Claude CLI 或 Codex CLI Provider 时，主进程创建一次性会话并复用工作台 `SessionService`，分别进入 Claude SDK 或 Codex CLI/SDK 执行，再把最终 assistant 文本写回画布任务。
- 本轮任务显式选择的 Provider/Model 优先于 Agent 历史绑定；复用操作节点时，卡片与任务同步写入新的运行时配置。
- Codex CLI 报告“Skill descriptions were shortened...”时属于技能描述压缩警告，不应被当作任务失败；运行器会忽略该条警告并继续等待最终文本。
- 画布本地会话只传递节点选中的 Skill ID，只在上下文中注入元数据目录；完整指令通过 `skills_load` 按需读取。Codex CLI 画布路径同时关闭宿主原生插件技能扫描，避免与 Spark 的渐进式披露重复。
- 本地 Agent 返回值只在收到 `isFinal=true` 或 turn 终态后采用，不把 Codex 中间 `complete` 消息误当作最终结果。结构化实体解析会从混合文本、代码块及多个 JSON 片段中选择真正的实体对象。
- 本地 CLI 当前只承载纯文本输入；包含图片输入的任务应选择支持多模态的 API Provider。

这样模型选择器中的本地 CLI 选项与工作台对话的实际运行时保持一致，不再因本地 Provider 没有 API Key 而落入 HTTP Provider 的 `keystoreRef` 检查失败。

## 产品边界

- 功能节点的内置能力提示词属于 `systemPrompt`，始终隐式，不进入用户可见编辑区。
- `CanvasPromptDocument` 是用户可见提示词内容与引用位置的唯一真值；旧字符串 `prompt` 仅用于兼容，不参与受控编辑器反向初始化。
- `CanvasInputBinding[]` 是本次任务实际输入资料的唯一真值。物理连线和 `@`/“+”引用都归一为绑定；提示词 Tag、媒体角色、校验与提交请求只做绑定投影。
- 文本、剧本、分镜、角色、场景和道具等上游输入以原子引用 Tag 表示。
- 任务配置不再提供独立的资源宫格、媒体多选框或重复文本资料列表。图片、视频、音频和文本统一通过提示词中的引用 Tag 管理，避免两套编辑入口产生不同步。
- 物理连线产生的媒体引用也显示为 connection Tag，不再为了上方媒体区而从可见文档中剔除。
- 首帧、尾帧和参考图控件只负责给已有绑定分配模型通道，不创建第二套资源来源。
- 自定义文本、引用 Tag 和结构化参数共享同一有序文档，提交时按文档顺序编译。

## 编辑器模型

编辑器采用 Lexical。普通文字使用 TextNode，引用和参数使用自定义 inline DecoratorNode，因此浏览器原生负责选区、输入法、任意位置插入、换行、撤销重做和原子节点前后光标。

## 引用插入与节点名称

- 提示词工具栏“+”与输入 `@` 共用同一个插入菜单，菜单顶部提供名称、类型和文本内容搜索。
- 插入菜单提供“从画布点选节点”。进入点选模式后任务面板保持打开，单击画布节点会在原光标位置插入 Tag；Esc 或状态条“取消”退出点选模式。
- 从 `@关键词` 进入画布点选时，在成功选择节点前保留原查询文本；取消点选不修改提示词，成功后才以 Tag 原子替换原查询。
- 快捷参数使用单行宫格；镜头时长、台词和站位直接插入参数，图片与视频切换下方资源筛选。
- 资源列表独立滚动。鼠标或键盘高亮条目后，文本在菜单外侧展示可滚动正文，图片和视频展示可用预览；右侧空间不足时预览自动翻到左侧。
- 菜单支持选择条目、Esc 和点击菜单外部关闭。“+”入口通过 body portal 展示，避免被操作工作台滚动容器裁切；`@` 入口仍锚定编辑器光标并保持原插入位置。
- 操作节点工作台提供独立“节点设置” Tab。名称在 Enter 或失焦时保存，Esc 恢复已保存名称；任务配置不再重复编辑标题，避免保存运行参数时覆盖节点名称。

引用来源分为两类：

- `connection`：由画布物理连接自动产生。删除后写入 `suppressed: true`，表示保留连接但本节点不使用该参数；断开再重连后可重新初始化。
- `manual`：由 `@` 或添加菜单主动插入。删除时直接移除引用。

相同 `(sourceNodeId, role)` 只保留一个实际输入；同一资料承担首帧、尾帧或参考资料等不同角色时保留独立绑定。所有启用绑定都必须归属于一个可见 Tag：删除提示词 Tag 会同步删除或停用该 Tag 拥有的默认、首帧、尾帧和参考图绑定。历史 `picker` 绑定在打开面板时迁移为可见的手动引用 Tag，新任务配置不再通过独立资源选择器创建它。

引用分组或操作节点时，编辑器保留原始节点 Tag，绑定和首尾帧选择可以解析到其当前子产物；子产物绑定记录原始 Tag 为 owner，删除原始 Tag 时必须级联停用，不能留下不可见输入。

## 提交约束

- `systemPrompt`、`promptDocument`、`inputBindings`、媒体输入和模型参数分别提交，不互相拼接污染。
- 编辑器保存的是“可见文档”；提交编译器只消费启用绑定并生成一次性的“可执行文档”。引用 Tag 对应的图片、视频、音频和文本按绑定角色进入模型请求。
- 右键创建时预绑定输入、创建后物理连线、`@` 手动插入均调用同一套文档初始化与连接对账逻辑。连线只改变引用块和输入清单，不再继承或展开上级任务的旧 `prompt` 字符串。
- `promptDocument` 中被抑制或断开的引用不进入有效任务输入。
- `@` 新增的有效引用会进入任务输入节点清单和 relation manifest，保证运行历史可追踪。
- 文本/剧本/角色等引用编译进 `compiledUserText`；图片等媒体编译进带稳定 role 的 `inputFiles`；结构化参数编译进用户消息；`systemPrompt` 始终保持单独字段。文本模型接收 system + user + vision 输入，媒体模型适配器接收最终 prompt + typed input files。
- 编译器先解析并去重最终输入，再按 Provider 通道独立编号。`参考图 #1` 必须对应 `reference_images[0]`；首帧、尾帧不占用参考图编号。同一图片的重复引用复用一个 Provider 槽位。
- 文本资料使用 `[文本引用 Tn 开始]` / `[/文本引用 Tn 结束]` 明确正文边界；同一文本的重复引用只输出一份正文，后续位置显式复用同一 T 编号。
- 分镜 JSON、分镜 Markdown 表格和普通 Markdown 表格在模型请求路径中转换为“字段：值”记录。`formatStoryboardRowsAsMarkdown()` 只保留给 UI 编辑与分镜拆分，不再用于模型输入。
- 引用操作节点或分组时，提交阶段会解析为其当前主产物/集合产物并冻结 `inputSnapshots`，而编辑器仍保留原始上游节点卡片，避免提交后卡片被产物正文替换。
- 任务运行或特殊工作流回绑节点时，`task.prompt` 只保存编译后的执行快照，`node.data.promptDocument` 仍保存用户可见文档，`node.data.systemPrompt` 保存隐藏指令；三者不得互相反向初始化。
- 旧节点中混合保存的功能提示词与上游正文会在面板初始化时迁移：功能指令转入隐藏层，上游文本和自动媒体输入都转成可见连接 Tag。

## 媒体 Prompt 拼接与校验

- 媒体 Provider 只接受单一 prompt 时，由 protocol 共享拼接器统一合并 `systemPrompt` 与 `compiledUserText`，renderer 预检和 main 执行不得各自实现一套拼接规则。
- 若 System Prompt 已逐字包含 User Prompt，或已包含 `[文本引用 Tn]` 中的实质正文，最终请求只保留一次；编辑器和任务详情仍分别保存原始 system/user 字段。
- 模型清单的 `safety.maxPromptLength` 是 Provider 文档参考阈值，不是本地可信硬上限。必须同时记录已知的 `promptLengthUnit` 和 `promptOverflowBehavior`；单位不明时不得按字符数伪装成精确限制。
- 提示词长度、模型参数范围和 Provider 兼容性问题在画布中作为 advisory warning 保存，不阻断请求。缺少任务必需输入、畸形 data URL 和主进程文件路径越权仍是硬错误。
- renderer 对拼接后的 Provider prompt 做一次预检；main 不再在补齐系统提示词和节点上下文后重复执行更严格的 manifest 校验，避免同一请求前后判定不一致。

## 设计参考

- Dify：区分 System/User 消息和工作流变量。
- n8n：将上游数据映射为节点参数引用。
- Lexical/Tiptap：Mention 采用可序列化、可整块删除的原子节点。
- React Flow：不同输入类型使用明确连接语义，而不是把所有输入压成字符串。
