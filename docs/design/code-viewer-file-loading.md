# 内置代码编辑器文件加载与内存策略

> 状态: 已落地 | 最后核对: 2026-08-25

## 目标

代码侧栏同时打开多个文件时，只为当前激活文件付出磁盘读取与 Monaco 内容模型成本；超大文件和二进制文件在进入渲染进程前被拦截，避免完整读取、IPC 序列化和多份字符串常驻导致界面卡顿或渲染进程崩溃。

## 加载策略

- 文件 tab 只保存路径、展示名等轻量元数据；文件首次成为激活 tab 时才调用 `file:read`。
- `useCodeViewerFiles` 只保留当前激活文件以及仍有未保存修改的非激活文件。非激活且已保存的内容立即释放，下次激活时重新读取。
- 关闭 tab 后删除对应 runtime；读取尚未返回时若 tab 已关闭或切走，迟到结果不会重新写回渲染端状态。
- 编辑器仍只挂载一个 Monaco 实例，切换 tab 时复用实例。Monaco 的视口渲染、worker 和 `largeFileOptimizations` 继续承担允许范围内长文件的编辑性能。

## 主进程护栏

`file:read` 增加向后兼容的可选参数：

- `maxBytes`：主进程先读取文件元数据，超过限制直接返回结构化错误。
- `rejectBinary`：只读取前 8 KiB 样本进行二进制探测，通过后才完整读取与解码。

代码编辑器固定传入 5 MiB 上限并启用二进制拦截；文件预览、画布等旧调用方不传参数，保持原行为。UTF-16 BOM 文件明确按文本处理，避免 NUL 字节造成误判；其余编码继续走 BOM → 严格 UTF-8 → GB18030 的现有识别链路。

## 取舍

- 超过 5 MiB 的文件不做分块只读预览，直接显示清晰错误。当前方案优先保证应用稳定，避免引入分块模型、增量 tokenizer 和编辑保存语义的额外复杂度。
- 未保存文件不能在切 tab 时释放，否则会丢失用户编辑；因此内存上限是“当前文件 + 所有脏文件”，而不是绝对单文件。

## 验证

- 主进程测试覆盖超限拦截、二进制拦截、受保护文本从文件开头完整读取以及旧调用兼容。
- 渲染端 hook 测试覆盖只读激活 tab、切换时释放已保存内容、脏内容保留、重新激活按需读取、关闭 tab 清理，以及同路径关闭后重开时拒绝旧请求回写。
- `@spark/desktop` 双 TypeScript 项目检查与相关聚焦测试通过。
