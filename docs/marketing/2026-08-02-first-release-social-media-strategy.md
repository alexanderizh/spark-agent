# Spark Agent 首次发布社媒营销策略与功能分级

> 状态: 实施中 | 最后核对: 2026-08-02

## 1. 文档目的与口径

本文件为 Spark Agent 首次公开发布准备一份可直接执行的社媒策略，并以当前仓库 `README.md`、产品界面和已实现画布能力为依据，列出对外可讲的功能清单。功能按用户认知分为「平台、工作台、画布」三类；同一能力只在最符合用户使用场景的一类中出现一次，避免重复计数。

**对外一句话定位**：Spark Agent 是一个本地优先的桌面 AI Agent 工作台，把真实任务执行、代码与知识工作、可复用工作流、Agent 协作和多媒体创作放进同一台电脑。

### 评价级别定义

| 级别 | 含义 | 首发内容动作 |
| --- | --- | --- |
| 重点功能 | 能单独构成下载理由，或是产品定位不可替代的证据 | 首发主叙事；至少 1 条完整 Demo + 1 条场景内容 |
| 优势特色功能 | 对目标用户有明显差异，适合在功能系列中深入说明 | 首月/第二波单独成篇；作为 Demo 的关键转折 |
| 普通功能 | 重要的体验基础或生态补全，但不宜单独承担首发流量目标 | 在总览、清单、FAQ 或系列内容中顺带呈现 |

> 分级是传播优先级，不代表研发价值、成熟度或能力上限。所有对外演示均应只展示已在发行版本中可用的能力，并标注所用系统、模型/Provider 与必要前置条件。

## 3. 完整功能总表：工作台

工作台类回答「Agent 如何把一项真实工作推进到可审查的结果」。这是首次发布的主战场，核心受众为开发者、独立开发者和重度知识工作者。

| 功能 | 用户收益 / 对外表述 | 级别 | 首发呈现建议 |
| --- | --- | --- | --- |
| 会话式任务执行 | 在真实项目中描述目标，让 Agent 阅读文件、执行命令、生成补丁并交付结果 | 重点功能 | 首条完整 Demo 的主线 |
| 文件目录与文件预览 | 在对话旁查看项目文件与交付物，不在多个应用间切换 | 普通功能 | 录屏中自然出现 |
| 内置终端 | 让 Agent 和用户在同一工作台运行命令、读取输出 | 重点功能 | Demo 必须保留关键终端验证 |
| 代码开发、解释、重构与测试 | 支持修改代码、解释逻辑、重构并补齐/运行测试 | 重点功能 | 用一个可复现 bug 或小功能全程演示 |
| Debug 模式 | 以“假设 → 插桩 → 运行 → 读日志 → 修复”闭环定位问题 | 优势特色功能 | “AI 如何不是瞎猜地修 bug”主题 |
| Git Hunk Review | 按改动块查看、接受、拒绝或回滚 Agent 修改 | 重点功能 | 首发 Demo 的关键可信时刻 |
| 代码还原点（Checkpoint） | 保留关键改动、补丁和工作区状态，可一键恢复稳定版本 | 重点功能 | 与 Git Review 组成“敢让它改”的证据 |
| Worktree 隔离 | 为会话创建隔离工作树，主工作区保持干净 | 优势特色功能 | 面向开发者的深度演示 |
| 浏览器自动化（Playwright） | 自动完成网页操作、验证和数据采集 | 优势特色功能 | 从改代码到网页验证的闭环 Demo |
| 应用内浏览器观测 | 可见浏览器窗口、console/network 观测、元素读取和 profile 管理 | 优势特色功能 | 调试/网页任务系列补充 |
| 联网搜索与网页抓取 | 供应商无关的搜索和 URL 内容获取，可配置多个后端 | 普通功能 | 调研任务或资料核验中呈现 |
| 在线交付物生成 | 生成定制网页、HTML 幻灯片，并可导出 PPTX / DOCX / Markdown | 优势特色功能 | 面向产品/运营的第二人群案例 |
| 任务附件与多媒体输入 | 将文件、图片等带入任务上下文，结合预览继续处理 | 普通功能 | 录屏操作，不单独讲 |
| 语音输入 | 通过麦克风将语音转为任务输入 | 普通功能 | 短视频开场可作为效率细节 |
| 多 Agent 团队（A2A） | Host 分派多个成员，成员可有独立模型、MCP、Skills | 重点功能 | 首发后第 2 个重量级系列 |
| 成员间协作讨论 | 成员广播/定向消息、共享讨论线程与显式轮次推进 | 优势特色功能 | 展示“不是并排跑几个聊天框” |
| 团队预算、超时、取消与嵌套控制 | 控制成员级预算、超时、上下文和嵌套深度，异常可传播取消 | 优势特色功能 | 深度教程中的安全边界 |
| 可视化工作流编排 | 用节点与连线将多步任务固化为可复用流程 | 重点功能 | 首发后第 1 个功能系列 |
| 11 类可执行节点 | input / plan / agent / subagent / skill / tool / mcp / approval / verify / review / artifact | 优势特色功能 | 用“计划→审批→执行→验证→交付”单条流程解释 |
| 节点级能力收窄与只读默认 | 为节点指定工具/Skill，计划和审查节点默认只读 | 优势特色功能 | 与权限审批共同建立可信执行认知 |
| 工作流运行快照与恢复 | 记录完成/失败节点和恢复信息，便于审计、复盘与断点继续 | 优势特色功能 | 展示一次失败恢复，增强真实性 |
| 工作流模板、导入导出与条件路由/循环 | 从模板起步、复用流程，并支持分支/循环控制 | 优势特色功能 | 发布后教程；避免首发一次讲完 |
| 会话排程 | 在会话中设置并查看任务的计划执行信息 | 普通功能 | 与定时任务合并为“持续自动化”内容 |

| 功能 | 用户收益 / 对外表述 | 级别 | 首发呈现建议 |
| --- | --- | --- | --- |
| 多项目无限画布 | 在一张可缩放画布中编排文本、Prompt、素材、任务和产物；支持多画布项目 | 重点功能 | 画布线首条总览 Demo |

## 5. 首次发布的取舍

产品功能宽度不是首发文案的宽度。首次发布只建立一个清晰认知，再用两条内容线逐步扩展。

| 传播层级 | 必须讲清楚的内容 | 暂不展开的内容 | 成功信号 |
| --- | --- | --- | --- |
| 首发主叙事 | 本地优先桌面 Agent；能在真实项目中读文件、跑终端、改代码、审查与回退 | Provider 数量、所有 Skill 名称、全部工作流节点、所有画布媒体操作 | 用户能复述“不是聊天，而是可审查地推进真实任务” |
| 首发 Demo | 一条完整代码任务：目标 → 执行 → 终端验证 → Hunk Review → Checkpoint | 多 Agent、画布、远程连接 | 观看后愿意下载或询问复现条件 |
| 第二波功能系列 | 可执行工作流、A2A 团队、本地优先/权限、长期记忆 | 细颗粒治理配置 | 形成收藏、讨论和高级用户试用 |
| 第三波独立支线 | 无限画布、资产血缘、故事板、3D 导演台与视频工作流 | 与代码主线混讲 | 吸引创作者人群并验证第二个获客入口 |

建议对外功能优先级为：

1. 本地优先 + 可审查的真实任务执行；
2. 代码开发工作台（终端、Review、Checkpoint）；
3. 可执行工作流；
4. 多 Agent 团队；
5. 无限画布 + 资产血缘 + 画布助手；
6. Provider / MCP / Skill / 记忆 / 定时与远程连接等扩展能力。

## 6. 首发社媒策略

### 6.1 目标用户与核心承诺

首月只把资源压在**正在让 AI 参与真实代码项目的独立开发者、开发者和技术型创作者**。他们能最快验证 Spark Agent 的关键差异：Agent 是否可控、是否看得到过程、是否能留下可审查的改动。

核心承诺：

> AI 不只给你一段答案；Spark Agent 在本地桌面上把任务推进到可验证、可审查、可回退的结果。

第二人群是需要将剧本、Prompt、素材、镜头和生成结果统一管理的 AI 视觉/影视创作者，使用独立的「Spark Canvas」系列承接，不与首发代码 Demo 混用。

### 6.2 渠道分工与首月投入

| D+14 | 多 Agent 团队 | 60–90 秒 Demo | 多 Agent 的价值是明确分工与协作可见 | 留言你的协作任务 |
| D+18 | 长期记忆 / 工具生态 | 图文或录屏 | 新会话不必反复补背景，能力可按需装配 | 加入种子用户 |
| D+21 | Spark Canvas 预告 | 30 秒视觉短片 | 创作项目的素材和生成结果也应有上下文 | 关注画布系列 |
| D+24 | 画布：资产血缘与故事板 | 60–90 秒 Demo | 从剧本到镜头到生成结果在一张图里持续派生 | 报名创作者试用 |
| D+28 | 首月公开复盘 | 图文/视频 | 展示真实数据、已修问题、未解决问题和下月计划 | 提交反馈 / Star |

### 6.4 首发内容资产清单

| 资产 | 数量 | 制作要求 |
| --- | ---: | --- |
| 统一产品总览短片 | 1 | 45–60 秒；只展示一条“任务执行→审查”主线 |
| 完整代码任务录像 | 1 | 3–8 分钟；保留一次验证和一次人工判断，不剪成魔法 |
| 竖屏功能短片 | 6 | 每条只讲一个结论：本地优先、Review、Checkpoint、工作流、团队、画布 |
| 图文轮播模板 | 3 套 | 产品总览、功能拆解、开发日志；封面只写一个利益点 |
| 演示项目 | 1 套 | 可公开、可复现；无 API Key、真实路径、客户资料和私人通知 |
| 首发 FAQ | 1 页 | 支持系统、是否开源、数据位置、模型费用、安装条件、当前边界、反馈渠道 |
| 带来源参数的链接 | 1 套 | 至少识别平台、内容主题和发布时间，避免只看总下载量 |

### 6.5 选题模板与话术边界

每条内容采用「具体问题 → 真实过程 → 可验证结果 → 当前边界 → 一个行动」的结构。示例：

> 让 AI 改代码时，我最担心的不是它写得慢，而是不知道它到底动了哪里。Spark Agent 会在同一个桌面工作台里跑命令、给出 Hunk Diff，并保留能回退的 Checkpoint。下面是我今天用它跑的一次真实修复；这个版本仍需要你审核改动，不适合把生产权限直接交给 Agent。

避免使用“全能”“自动完成一切”“零成本”“绝对安全”“替代开发者”等不可验证表述。对模型输出、外部 Provider 费用、需要用户审批、平台/系统前置条件和仍在迭代的能力，应在视频字幕、置顶评论或 FAQ 中明确说明。

## 7. 转化与反馈闭环

| 环节 | 要做什么 | 关键指标 |
| --- | --- | --- |
| 认知 | 前 3 秒给出任务结果/冲突，不先罗列功能 | 3 秒留存、完播率、轮播首图停留 |
| 兴趣 | 一条内容只证明一个差异，保留真实验证步骤 | 收藏率、评论中的具体追问 |
| 转化 | 所有平台链接到同一下载/FAQ 页面，并注明版本和系统 | 带来源参数的下载、安装完成、GitHub Star |
| 激活 | 下载页提供 1 个可复现代码任务和 1 个最短工作流模板 | 首次会话、首次任务完成、模板使用 |
| 反馈 | 邀请种子用户提交任务类型、失败点、系统/Provider；每周公开答复 | 有效反馈数、问题复现率、7 日回访 |
| 迭代 | 用首月最高转化主题决定第二月 70% 内容；其余 30% 验证画布线 | 各主题下载转化、评论质量、留存 |

首月复盘不以播放量单独决策。优先比较“每千次有效观看带来的下载、实际任务完成和高质量反馈”，并记录每个内容所使用的版本、系统、模型与任务类型，保证结论可复查。

## 8. 发布前检查清单

- [ ] 发布版本已在目标系统完成安装、启动、核心 Demo 和更新路径验证。
- [ ] 官网、下载页、GitHub Release、README、FAQ 的版本号与支持平台一致。
- [ ] 演示项目、录屏、截图已清除密钥、私人路径、客户数据、通知和浏览记录。
- [ ] 每个视频只包含一个明确结论，并有字幕、版本号和必要前置条件。
- [ ] 首发主 Demo 已包含：任务输入、Agent 执行、终端/测试验证、Hunk Review、Checkpoint 或回退说明。
- [ ] 下载链接带来源参数；反馈入口能收集系统、版本、模型/Provider、任务描述和日志线索。
- [ ] 已准备一条“当前不适合什么”的边界说明，避免夸大自动化程度。
- [ ] 评论与 Issue 的响应责任人、首周响应时限和高风险问题升级路径已明确。

## 9. 维护说明

本策略以首次发布版本的已实现功能为准。每次发行前，应重新核对功能状态、支持平台、Provider/模型可用性和隐私/权限表述；若功能尚未进入发行版本，应从对外清单和演示中移除，或显式标为预览能力。
