# 画布创作与视频工作台质量升级设计

> 状态: 实施中 | 最后核对: 2026-07-14

本文记录 2026-07-14 画布创作链路的一轮质量升级，覆盖输入继承、组合图、图片标注、分镜拆分、视频工作台和视频提交前检查。目标不是增加更多孤立按钮，而是让“上游素材 → 任务配置 → 本地编辑 → 产物复核”的链路可预测、可检查、可继续编辑。

## 1. 设计原则

- 上游连线代表语义输入。连接操作节点时，消费方必须解析其真实主产物，不能把操作节点外壳当成图片或文本。
- 模型接收创作语义，不接收画布内部存储格式。分镜 JSON 在提交前转换为 Markdown 表格，普通文本保持原样。
- 高成本视频任务在提交前提供非强制检查，帮助用户发现缺少的风格、资产和镜头信息，但不替用户做决定。
- 工作台使用渐进披露：顶层只表达当前阶段，高级参数留在对应工具区；编辑结果统一进入产物区复核。
- 大型工作区文件只承担接线，新算法与交互策略拆成独立模块并有纯逻辑测试。

## 2. 视频工作台信息架构

视频工作台保持全屏、深色、创作者工具风格，延续现有画布视觉语言，不引入第二套主题。界面分为三个连续阶段：

1. **素材分析**：视频监看、逐帧控制、时间线定位、手动标记、关键帧提取。
2. **剪辑处理**：时间裁片（无损快切/精确切）、固定时长分段、转码、变速、倒放、画面裁剪。
3. **产物检查**：集中列出本地处理产物，支持回看，并作为后续回填画布的稳定出口。

右侧阶段条用于建立方向感，标签页仍是主要导航。FFmpeg 缺失时在工作台顶部直接显示“下载并安装”和实时进度，不再要求离开任务上下文进入设置页。

后续分步式视频生成配置将沿用相同结构：

- Step 1：风格与连续性约束；
- Step 2：人物、场景、道具资产；
- Step 3：对白、动作、表演和站位；
- Step 4：景别、机位、焦段、运镜、布光；
- Step 5：模型、时长、画幅、帧率与提交复核。

本轮先落提交前提醒，不强行改造现有任务数据协议。

## 3. 数据与交互决策

### 3.1 输入继承

统一使用 `expandCanvasInputNodes` 展开操作节点主产物和组成员。细节设定图根据展开后的真实输入判断：只有文本时创建文生图，有图片时创建图生图；视频节点同样从上游操作节点取得参考图。

### 3.2 分镜文本

分镜 JSON、容错 JSON 和 Markdown 表格统一解析为 `ParsedShotRow[]`，再输出可读 Markdown。右键“按镜拆分”创建一镜一个文本节点，按稳定网格排在原节点右侧，并保留来源连线。

### 3.3 组合与截图

创建组或向组内追加节点时，按阅读顺序重排成 1–4 列自适应网格，统一间距和组内边距。多选右键保留“合并为组合图”。截图范围从节点正文扩大为完整节点卡片，因此头部名称和类型信息会进入组合图；采样倍率提高到至少 2.5 倍并输出 PNG。

### 3.4 图片标注

标注舞台新增手型平移、25%–400% 缩放、滚轮缩放与视图复位。标注窗口可以暂时收起，状态保留并允许用户查看画布。文字回车后提交并回到选择工具；Esc 依次取消文字输入、取消选择、回到选择工具，只有再次退出时才触发关闭。存在未保存标注时关闭必须二次确认。

### 3.5 视频任务提交提醒

视频任务提交前展示四项例行检查：视觉风格、人物/场景资产、镜头参数与运镜、动作/对白/运行说明。系统根据当前提示词、输入图和模型参数标记“已检测”，未检测不等于不允许提交。用户可返回完善、继续提交或选择不再提醒。

## 5. 验证与后续

本轮以纯逻辑单测覆盖输入呈现、分镜拆分、组布局和提交检查，以 Agnes 适配器测试覆盖请求体，并通过桌面生产构建。后续重点是把视频生成配置升级为真正的分步骤表单，并为字幕、水印、拼接和多轨时间线补充独立设计与执行协议。
