# 贡献流程

> 状态: 已落地 | 最后核对: 2026-09-22

## 分流

- 可复现缺陷：使用 Bug 报告模板。
- 功能建议：先写问题和场景，再写方案和验收条件。
- 使用求助与路线讨论：使用 Discussions。
- 安全问题：只按 [SECURITY.md](https://github.com/alexanderizh/spark-agent/blob/master/SECURITY.md) 私下报告。

## PR 要求

一个 PR 尽量只做一个可验收主题，并说明：

- 背景、变更边界和未做事项；
- 迁移、权限、凭据、兼容性和发布影响；
- 执行过的命令及结果；
- UI 截图/录屏（如适用）。

主分支有保护规则，需要 PR、代码所有者审查和解决 review conversation。不要直接推送 `master`。

## 文档

`docs/` 中的 plan/spec/PRD/设计文档在标题下第一段保留状态和最后核对日期。架构事实写入主仓库，不把 Wiki 当唯一事实源。

## 许可证

项目使用自定义个人使用许可证，不是标准 `Apache-2.0`。商业使用或商业授权请先联系维护者。
