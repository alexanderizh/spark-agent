# 会话与适配器端到端测试用例

> 相关审计：[2026-07-11-会话消息乱序消失与适配器审计.md](2026-07-11-会话消息乱序消失与适配器审计.md)
>
> 用途：对 `bae3ea1d6` 至 `1c767242c` 的会话与适配器改造做真实 SDK / 真实 Electron 验收。本文是人工 E2E 用例；仓库现有 `apps/desktop/e2e` 仍是脚手架，不应用其代替本文验收。

## 准备

1. 使用全新的测试数据目录启动应用，避免与日常会话或供应商配置混用。用一个空 Git 工作区作为会话工作区，以便验证快照和文件变更。
2. 为测试账号完成 Claude 登录/凭证和 Codex 登录/凭证。两者都应先在「供应商」页面显示为可用。
3. 从仓库根目录运行 `pnpm --filter @spark/desktop dev:rebuild`，在启动的 Electron 窗口中执行用例。需打包验证时改用 `pnpm --filter @spark/desktop build:unpack`。
4. 每个用例记录：适配器、模型、输入、开始/结束时间、会话 ID、截图和重启后的结果。发现问题时导出相关会话和应用日志。

| ID     | 步骤                                                                                     | 预期结果                                                                         | 验收证据                                  |
| ------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------- |
| E2E-01 | 新建会话，发送「用 10 个段落解释这个工作区的结构」。等待完成后切换出再返回。             | 用户消息、思考/工具、助手结果均可见；顺序不变，且没有重复气泡。                  | 完成前后截图、会话 ID。                   |
| E2E-02 | 当助手正在输出时点「停止」，等待取消状态稳定。切换会话并回来，再重启应用后打开同一会话。 | 已输出的助手文本仍可见且不处于 streaming；状态明确为取消，不应因加载历史而丢失。 | 停止时、切回后、重启后三张截图。          |

| E2E-07 | 使用「逐步输出 200 行日志，每行都包含编号」的提示，在输出中滚动、切换侧栏后回来。        | UI 保持可操作；内容无闪烁、没有重复段落、不乱序；完成后滚动位置正常。            | 录屏；记录若有超过 1 秒的输入或滚动阻塞。 |

## 通过标准与自动化路线

- 高优先级用例 E2E-01 至 E2E-08、E2E-12 至 E2E-15 必须全通过，且同一问题不得在两个适配器中重现。
- E2E-16 至 E2E-18 需在有可控 MCP/错误测试账号的环境中执行；无环境时标记为「阻塞」而不是「通过」。
- `pnpm --filter @spark/storage test:unit`、`pnpm --filter @spark/desktop test:unit`和 `pnpm --filter @spark/agent-runtime test:unit` 是提交前的回归门禁，但不代替真实 Electron E2E。
- 下一步应将 E2E-01、E2E-02、E2E-04、E2E-06 重写为 Playwright Electron 测试：启动打包后的 Electron，使用定义义的 fake 适配器产生乱序 delta/取消/崩溃事件，对真 SDK 测试保留为密钥隔离的夜间验收。
