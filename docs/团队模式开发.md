## 1. 背景与目标

### 1.1 现状

当前 `Spark Agent` 中，每个 Session 绑定 **单一 ManagedAgent**（默认 `code-agent`）。底部 `AgentPicker`（位于 [ChatView.tsx:4635](apps/desktop/src/renderer/design/views/ChatView.tsx:4635)）允许用户切换内置或自建 Agent，但同一时间一个 Session 只有一个 Agent 与用户对话，Agent 之间没有「互相调用」的能力。

`ManagedAgent` 数据结构定义于 [packages/protocol/src/ipc/index.ts:1283](packages/protocol/src/ipc/index.ts:1283)，存储表 `agents`（迁移 [packages/storage/migrations/015_agents_and_workflow_runtime.sql:8](packages/storage/migrations/015_agents_and_workflow_runtime.sql:8)）。每个 Agent 自带 provider、model、permission、prompt、skill、mcp、workflow 配置。

Workflow（[docs/agents-workflows.md](docs/agents-workflows.md)）当前只把节点信息注入 system prompt，**没有真正的 Agent 间运行时通信**。

### 1.2 目标

为所有 Agent 提供一个**通用调用工具**，使「主 Agent 可以在对话中动态拉起其他被授权的 Agent」，并以**类 IM 群聊**的形式直观展示多 Agent 协作过程。具体目标：

1. **新模式：Team Agent Mode**  
   底部 Agent 选择器新增一项「团队模式」。仅当选择团队模式时启用本功能；其他模式保持现状不变（零回归）。

2. **核心工具：`agent_dispatch`（+ A2A 升级后的 `agent_message` / `team_round_advance` / `team_conclude`）**
   内部通过 `createSdkMcpServer` 注入到 SDK runtime 的 MCP 工具（类似现有 `mcp__spark_image__generate_image` 注入方式，参考 [session.service.ts:1186](packages/agent-runtime/src/services/session.service.ts:1186)）。任何运行在 Team Mode 下的主 Agent 都能调用它。工具短名集中在 `packages/agent-runtime/src/services/team-tool-names.ts`。

3. **A2A 通信协议**  
   定义 `TeamA2AMessage`、`TeamA2AReply` 结构，参考 Google A2A（agent-to-agent）的 task/message/artifact/state 概念，但**简化为单进程内 RPC**。本期不实现跨进程 A2A，但协议预留扩展位（`transport` 字段）。

4. **群聊式 UI**  
   - 每个 Agent 在群内以「成员身份」存在（头像 / 名字 / 配色）。
   - 用户、主 Agent、被调用的子 Agent 各自的消息分别用不同 bubble 渲染。
   - 主 Agent 调用子 Agent 时，时间线出现「@子 Agent」气泡；子 Agent 回复后，主 Agent 继续输出。

5. **右侧面板：团队成员管理**  
   在 Inspector 中新增 **Team Members 区块**，仅在 Session 处于 Team Mode 时显示。允许用户勾选哪些 Agent 可以在当前 Session 被调用。未勾选的 Agent 即使 `agent:list` 可见也不能被 dispatch。

6. **零侵入既有 Session**  
   Team Mode 是新 Session kind/runtime patch，**不修改** 默认 `code-agent` 的现有 Session 行为。

### 1.3 非目标（明确不做）

- 不做跨进程 / 跨主机的 A2A（Google A2A over HTTPS、JSON-RPC streaming 留到 v2）。**注：** codex 成员经本地 HTTP 桥接（`127.0.0.1` + Bearer）消费同一个 `spark_team` 工具面，仍属同进程编排范畴，不算跨主机 A2A。
- 不做 Agent 主动发起对用户的提问（被调 Agent 通过 reply 返回结果，不能在群内独立发言；用户的提问只发给主 Agent）。
- 不做 Workflow Studio 级别的可视化 DAG（团队模式是 **动态 ad-hoc**，不是预定义流程）。
- 不做模型路由 / 成本预算细化（沿用 Agent 已配置 provider/model；预算后续接入 Usage Ledger）。
- ~~不做 Agent 间「私聊」~~ **已演进（2026-07-04 A2A 升级落地）：** 成员间可经 `agent_message` 互发消息（广播 / 定向 `call` / 定向 `note`），由 `enablePeerMessaging` 开启；多轮讨论有显式轮次状态机（`team_round_advance` / `team_conclude`）与跨 turn 持续的共享讨论线程。所有 peer 消息仍写入事件流可审计（不存在真正"不可见"的私聊），详见 §2.1。

## 2. 名词解释 & 概念地图

| 术语 | 含义 |
|---|---|
| **Team Mode（团队模式）** | Session 的一种运行模式。Composer 底部 AgentPicker 选择「团队模式」时生效。 |
| **Team Session** | 处于 Team Mode 的 Session。`sessions.kind` 仍为 `chat`，但 `metadata.teamMode = true`。 |
| **Host Agent（主持 Agent）** | 用户直接对话的 Agent，由用户在 Team Mode 的子下拉中选择。负责决定调度谁、合并子 Agent 的输出。 |
| **Member Agent（成员 Agent）** | Session 当前授权可被 dispatch 的 Agent 集合（不含 Host 自身）。 |
| **Dispatched Agent / Sub-call** | 在一次 dispatch 中被主 Agent 拉起的 Member。**注意不是 Claude Code 的 subagent**（避免和 SDK 的 `subagent_started` 事件混淆，我们用 `team_dispatch_*` 事件，详见 §7.4）。 |
| **A2A 调用** | Host 通过 `agent_dispatch` 工具向某个 Member 投递任务，Member 完成后返回结构化 reply；A2A 升级后成员间也可用 `agent_message` 互发（见 §2.1）。 |
| **群聊视图** | ChatView 在 Team Mode 下的渲染形式：每条消息标注发送者（用户 / Host / Member），含头像、名称、可点击查看 Member 配置。 |

### 2.1 成员自由交流 v2（2026-07-04 已落地）

在 A2A 深度协作基础上，成员间通信现在有四种明确模式，并由 prompt、工具 schema、后端预算共同约束：

| 模式 | 使用场景 | 运行时语义 |
|---|---|---|
| 直接答 | 成员已有足够信息 | 成员直接回复，结果返回提问方 |
| 先咨询再答 | 当前答案依赖队友输入 | `agent_message({ targetAgentId, mode: 'call' })` 在同一 turn 内同步触发队友，工具结果返回后再综合作答 |
| 转交 | 问题本该由队友继续 | 最终回复正文写 `@成员名/ID + 上下文`，`maybeAutoDispatchMentions` 自动转发并受 `MAX_AUTO_MENTION_HOPS` 管控 |
| 留言 | 对方暂不需要立即行动 | `agent_message({ targetAgentId, mode: 'note' })` 或省略 `targetAgentId` 广播，只写共享线程不触发执行 |

关键实现点：

- `agent_message` 的 `mode` 默认为 `call`；定向 `note` 会写入 `team_thread_messages.delivery='note'`，并发出 `team_peer_message.delivery='note'`。
- `TeamDiscussionRepository.renderThreadForPrompt(discussionId, tokenBudget, viewerAgentId)` 会把发给当前 viewer 的 note 移到线程片段末尾，并加 `[NOTE FOR YOU]`，防止被长讨论淹没。
- 同步咨询使用独立 `peerCallCountByTurn` 预算，不挤占 Host / workflow 的 dispatch 预算；咨询链有 `consultDepth` 上限 3 层。
- `TeamDispatchRunContext.deadlineAt` 会从外层 dispatch 传到成员工具面，剩余时间不足 30 秒时拒绝同步 call，并引导改用 note 或直接回答。
- 正文 `@` 自动链与同步咨询深度分开治理：自动链仍由 `autoMentionHops`、pair 往返上限和讨论消息总量上限兜底。
- UI 的 `team_peer_message` 气泡显示 `发送方 → 接收方`，note 显示“留言”标识。

## 3. 业界参考

实现者无需精读以下文档，但本节列出我们参考的设计点：

### 3.1 Google **A2A 协议**（agent-to-agent，2024–2025）

- 核心概念：`AgentCard`（公开 manifest）、`Task`（一次工作单元）、`Message`（多模态消息含 Part）、`Artifact`（产物）、`TaskState`（submitted/working/input-required/completed/failed/canceled）。
- 传输：JSON-RPC 2.0 over HTTPS，支持 SSE 流式。
- 鉴权：OAuth2 / API Key / mTLS。
- **本项目借鉴**：
  - `AgentCard` → 我们的 `TeamMemberCard`（从 `ManagedAgent` 投影）。
  - `Task` + `Message` → 我们的 `TeamA2ATask` + `TeamA2AMessage`。
  - `TaskState` → 我们的 `dispatchState: 'pending' | 'working' | 'completed' | 'failed' | 'canceled'`。
  - **简化**：transport 固定为 `'in-process'`（同一 Electron 主进程内调用 SessionService.executeOneShot），鉴权省略。

### 3.2 OpenAI **Swarm**（handoff 模式）

- 核心：Agent A 通过工具 `transfer_to_<B>` 把控制权交给 Agent B，B 接管对话直到下一次 handoff。
- **本项目借鉴**：保留「触发即转交」语义，但**我们用 dispatch + reply 而不是 handoff**——主 Agent 保留控制权，避免用户感受到「对面突然换人」。

### 3.3 Microsoft **AutoGen** / **CrewAI**

- 核心：编排器（Orchestrator/Manager Agent）负责轮流调用 worker。
- **本项目借鉴**：Host Agent 即编排器；**初始版本**只做 Host 显式发起的 dispatch。**A2A 升级后**（见 §2.1）：成员可经 `agent_message` 主动发起 peer 调用（受 `enablePeerMessaging` 控制），多轮讨论由 Host 用 `team_round_advance` / `team_conclude` 显式推进——仍非完全自治的 group-chat manager，但 Host 不再是唯一发起方。

### 3.4 Claude Agent SDK **Subagent**（[CLAUDE.md] / `subagent_started` 事件）

- SDK 已经有 `Task` tool 和 `subagent_started/completed` 事件（参考 [packages/protocol/src/events/index.ts:123](packages/protocol/src/events/index.ts:123)）。
- **本项目借鉴**：复用同样的事件抽象，但**新增独立事件**：`team_dispatch_requested / team_member_message / team_dispatch_completed`，避免 UI 把 Team Member 渲染成 Claude SDK 的内置 subagent。

### 4.2 核心运行时序

```
User → "帮我把这段代码翻译成 Rust 再写测试"
         │
         ▼
Host Agent (e.g. 编排 Agent)
   思考：先让 rust-coder Agent 翻译，再让 reviewer Agent 测试
         │
         ▼
   ToolCall: mcp__spark_team__agent_dispatch
     { targetAgentId: "rust-coder", task: "翻译这段 Python …", artifacts: [...] }
         │
         ▼
   [emit team_dispatch_requested]   ←— UI: 出现 "Host @ rust-coder" 卡片
         │
         ▼
   TeamDispatcher.run("rust-coder", payload)
       ├─ 加载 rust-coder 的 provider/model/skills/mcp/prompt
       ├─ 复用 ClaudeSDKExecutor 启动 one-shot turn
       │    ↓ 流式输出 → 转成 team_member_message 事件
       └─ 返回 { ok: true, content: "fn translate() {...}", artifacts: [...] }
         │
         ▼
   [emit team_dispatch_completed]   ←— UI: rust-coder 收尾卡片
         │
         ▼
   Host Agent 收到 tool result，继续推理 → ToolCall reviewer
         │
         ▼
   ...（循环直到 Host 给出最终 assistant_message）
```

### 4.3 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **不引入新的进程或新 SDK adapter** | A2A 调用本质是「在同一进程内嵌套跑一个 turn」。复用 `ClaudeSDKExecutor` 即可，零额外攻击面。 |
| D2 | **A2A 工具通过 `createSdkMcpServer` 注入** | 与 `spark_image` 同样的注入路径（[session.service.ts:1186](packages/agent-runtime/src/services/session.service.ts:1186)），不改 SDK，工具名 `mcp__spark_team__agent_dispatch`。 |
| D3 | **Member 调用是同步 + 流式**：tool 返回前阻塞 Host，但 Member 的中间输出实时流给 UI | 用户能看到 Member 在「打字」，Host 看到的是结构化结果。比纯同步体验更好。 |
| D4 | **Member 不调用工具？** Member 可调用 Skills/MCP 但 **默认禁止再次调用 `agent_dispatch`**（防嵌套递归）。可通过 `team.allowNesting=true` 开启，最大深度 `team.maxDepth=2`。**A2A 升级后：** 成员即使不开 `allowNesting`，也可在 `enablePeerMessaging=true` 时经 `agent_message` 互发消息（与嵌套 dispatch 是两个独立开关）。 |
| D5 | **Host 和 Member 的 provider/model 互不影响** | 每个 ManagedAgent 自己带 provider，dispatch 时切换。 |
| D6 | **Permission 隔离** | Member 在 dispatch 期间继承 Session 的 workspace + 自身 ManagedAgent 的 permissionMode；权限请求事件挂在 Member 名下显示。 |
| D7 | **失败的 dispatch 不让 Host 崩溃** | dispatch 返回 `{ ok: false, error }`，Host 自己决定是否重试或换 Agent。 |

### 5.2 ChatView 时间线：群聊式渲染

#### 5.2.1 消息类型与渲染

| 来源 | 渲染方式 | 头像 | 标题 |
|---|---|---|---|
| User | 右对齐用户消息，右侧显示方形圆角头像 | `settings.general.data.userAvatar`；默认 DiceBear URL | 用户名 |
| Host Agent | 左对齐主气泡，按普通群聊成员渲染，不显示“主持人”视觉标签 | Host 的 `agents.metadata.avatar`；默认 DiceBear URL | `${hostAgent.name}` |
| Dispatch 状态 | `<TeamDispatchCard />` 降级为轻量状态行，只说明 `${member.name} 收到任务` 和完成状态 | 不显示 Host 包装 | `${member.name} 收到任务` |
| Member 消息 | `<TeamMemberBubble />`：平级群聊消息行，左侧方形圆角头像，右侧显示 agent 名称和独立正文 | `agents.metadata.avatar`；默认 DiceBear URL | `${memberAgent.name}` |
| Member 返回 | 收尾的 `dispatch_completed` 用一个小型 status chip 收口（"已返回" / "失败：xxx"） | — | — |

#### 5.2.2 关键视觉规则

- **平级输出**：Member 输出不再包在 Host/主持人的卡片下，也不再使用缩进色条表达从属关系。每个 Agent 的输出都是独立消息行。
- **头像配置**：Agent 头像写入 `agents.metadata.avatar`，用户头像写入 `settings.general.data.userAvatar`。默认使用 `https://api.dicebear.com/9.x/{style}/svg?seed={nickname}` 形式的 DiceBear URL；上传图片在 renderer 端裁剪为 256px 方形 data URL。
- **配色生成**：`agentId` hash 仍用于轻量 accent（如 hover/border），但不作为头像唯一来源。
- **顺序**：所有事件按 `seq` 全局有序渲染，**不分泳道**。这样用户能看到「Host 想 → 调 A → A 回 → Host 继续 → 调 B → B 回 → Host 总结」的完整时间线。
- **折叠**：Member bubble 默认完整展开；底层 `mcp__spark_team__agent_dispatch` 工具 JSON 不在主会话区展示，由 `TeamDispatchCard` 表达状态。

## 8. 运行时改造方案

### 8.1 新文件 `packages/agent-runtime/src/services/team-dispatch.service.ts`

```ts
import type { ManagedAgent } from '@spark/protocol'
import type { TeamA2ATask, TeamA2AReply, TeamModeConfig } from '@spark/protocol'

export interface TeamDispatchContext {
  sessionId: string
  turnId: string
  workspaceRootPath: string
  hostAgent: ManagedAgent
  members: ManagedAgent[]                  // 当前 session 启用的 members
  teamConfig: TeamModeConfig
  currentDepth: number                     // 0 = 在 Host 主循环里
  emitEvent: (event: AgentEvent) => void   // 透传给 SessionService.emitAndPersist
  signal: AbortSignal                      // 由 session cancel 触发
}

export class TeamDispatchService {
  constructor(
    private readonly sessionService: SessionServiceLike,  // 暴露 executeOneShot
    private readonly repos: { teamDispatches: TeamDispatchRepository },
  ) {}

  /**
   * 单次 dispatch：
   * 1. 校验 memberId、depth、是否在 memberAgentIds 中
   * 2. 写入 team_dispatches state='working' + emit team_dispatch_requested
   * 3. 用 Member 的 ManagedAgent 配置构造一次 one-shot turn
   *    - 复用 ClaudeSDKExecutor，但 prompt = task.instruction + attachments
   *    - allowedTools/disallowedTools：禁用 agent_dispatch（除非 allowNesting && depth+1 <= maxDepth）；A2A 升级后成员还可拿到 agent_message（受 enablePeerMessaging 控制）
   *    - mcp servers：member 自身的 mcpServerIds
   *    - permissionMode：member 自身配置
   * 4. 将 SDK 流式 assistant_message → 转 team_member_message 事件（rebrand）
   * 5. 收尾：写 team_dispatches state、emit team_dispatch_completed、返回 TeamA2AReply
   */
  async run(task: TeamA2ATask, ctx: TeamDispatchContext): Promise<TeamA2AReply> { ... }
}
```

**关键约束**：

- `TeamDispatchService` **不直接 import 全部 SessionService**（避免循环依赖）。SessionService 暴露一个 `executeOneShotForMember(opts)` 内部方法，TeamDispatchService 只调它。
- `executeOneShotForMember` 不写 `session_messages`（用户视角下 Member 的对话不构成会话历史的独立 turn），但**所有事件都写到 `events` 表**，并标注 `dispatchId`，便于回放。

### 9.1 `agent_dispatch` 工具描述（注入到 Host 的 system prompt 和 SDK tool listing）

```
Tool: mcp__spark_team__agent_dispatch
Purpose: Delegate a focused subtask to a teammate agent.
When to use:
  - Task is outside your domain, or another member is clearly better suited.
  - User explicitly asks for a member by name.
When NOT to use:
  - You can answer the user directly.
  - The subtask requires the user to clarify something (ask the user instead).

Returns: Structured reply with the member's content and artifacts.
  You decide whether to call again or synthesize the final answer.

The member CANNOT call back to you or chain to another member by default.
```

### 9.2 输入 schema（zod-compatible JSON Schema）

```json
{
  "type": "object",
  "required": ["targetAgentId", "instruction"],
  "properties": {
    "targetAgentId": {
      "type": "string",
      "description": "One of the team member IDs visible to you. Use the exact id, not the name."
    },
    "instruction": {
      "type": "string",
      "maxLength": 8000,
      "description": "Clear, self-contained description of what the member should do."
    },
    "inputs": {
      "type": "object",
      "additionalProperties": true,
      "description": "Optional structured inputs (key-value)."
    },
    "attachments": {
      "type": "array",
      "maxItems": 10,
      "items": {
        "type": "object",
        "properties": {
          "type": { "enum": ["text", "file_ref", "image_ref"] },
          "value": { "type": "string" }
        },
        "required": ["type", "value"]
      }
    },
    "expectedOutput": {
      "enum": ["text", "json", "code", "mixed"]
    },
    "timeoutMs": { "type": "integer", "minimum": 5000, "maximum": 600000 }
  }
}
```

### 9.3 工具返回的 text 内容（给 Host LLM 看的）

`formatReplyForHost(reply)` 输出形如：

```
[Member Reply · rust-coder · state=completed · 1240ms · 480→820 tok]
fn translate(...) -> String { ... }

(artifacts: 1 file: ./out/translated.rs)
```

> 注意：UI 不渲染这个文本（UI 走结构化事件），它只是给 LLM 的工具结果。

### 9.4 错误约定

如果 dispatcher 拒绝调用（member 未启用 / depth 超限 / member 不存在），返回：

```
[Member Reply · ??? · state=failed · code=member_disabled]
The requested member is not enabled in this team session. Available members: [rust-coder, reviewer].
```

Host LLM 会自行调整策略（换 member 或直接回答用户）。

### 9.5 A2A 升级新增工具（Phase B/D，已落地）

| 工具 | 输入 | 行为 |
|---|---|---|
| `agent_message` | `{ targetAgentId?, mode: 'call' \| 'note', content, discussionId?, attachments? }` | **广播**（省略 `targetAgentId`）：只写共享线程，不触发任何执行。**定向 `call`**：在当前 turn 内同步触发目标 Agent 的一次 turn，工具结果返回后再由发送方继续；走独立 `peerCallCountByTurn` 预算，剩余时间 < 30s 时拒绝并提示改用 `note` 或直接回答。**定向 `note`**：写入 `team_thread_messages.delivery='note'`，发 `team_peer_message.delivery='note'`，不触发执行。 |
| `team_round_advance` | `{ discussionId, summary? }` | Host 显式推进讨论到下一轮；发 `team_round_advanced`，更新 `team_discussions.round_index`。 |
| `team_conclude` | `{ discussionId, finalSummary? }` | Host 收尾讨论；发 `team_discussion_concluded`，置 `team_discussions.state='concluded'`。 |

`agent_message` 受 `enablePeerMessaging` 控制；`team_round_advance` / `team_conclude` 仅 Host 可调。工具名统一从 `team-tool-names.ts` 引用，为后续 `spark_team → spark_orchestrate` 改名预留。

## 10. 安全、权限与资源治理

| 维度 | 策略 |
|---|---|
| Member 是否能写文件 | 沿用 Member ManagedAgent 自己的 `permissionMode` 与全局 PermissionPolicy。Member 触发的 `permission_request` 事件需要 UI 标记为「来自 Rust Coder」。 |
| 工作区隔离 | 所有 Member 共享 Host 的 `workspaceRootPath`。不引入 per-member workspace（v2 再说）。 |
| Secret 与 API Key | Member 通过自己的 provider profile 获取，不暴露给 Host。 |
| 上下文泄漏 | Host 必须显式通过 `attachments` 传递内容给 Member。**不要**把 Host 的完整 history 注入 Member。（在 TeamDispatcher 实现时强约束：Member 的 user message 只用 `instruction + attachments`。） |
| 嵌套调用 | 默认 `allowNesting=false`；启用时 `maxDepth ≤ 3`；超限返回错误。`allowNesting` 仅控制嵌套 `agent_dispatch`，**不**控制成员互聊（后者由 `enablePeerMessaging` 控制）。 |
| 工具调用风险 | Member 调用文件写入 / 命令执行时，权限弹窗 UI 标题前缀加上「[Rust Coder]」，让用户清楚是哪个 Agent 申请的。 |
| 资源（A2A 升级后） | 单 turn 内 `agent_dispatch` 预算 **10**（`DEFAULT_MAX_DISPATCHES_PER_TURN`）；peer `call` 独立预算 **20/turn**（`peerCallCountByTurn`），不挤占 Host/workflow 预算；单讨论消息总量上限 **40**（`maxMessagesPerDiscussion`）；pair/round 定向消息上限 **8**；同步咨询链 `consultDepth` ≤ **3**；正文 `@` 自动转发链 `MAX_AUTO_MENTION_HOPS=6`。多轮讨论 `maxDiscussionRounds` 默认 **6**、硬上限 **20**。超限均硬拦截并返回结构化错误。 |

## 11. 失败兜底、循环检测、并发与中止

### 11.1 循环检测

简单计数：同一 turn 内 dispatch 总次数 > `DEFAULT_MAX_DISPATCHES_PER_TURN`（=**10**）→ 拒绝并返回 `code=internal, message='Dispatch budget exceeded'`。

**A2A 升级后的多层兜底**（防止成员互聊 ping-pong）：
- 后端硬拦截：消息总量（`maxMessagesPerDiscussion=40`）、轮次（`maxDiscussionRounds` 默认 6 硬上限 20）、pair/round 定向上限 8、peer call 单独预算 20/turn、同步咨询深度 `consultDepth` ≤ 3、自动 `@` 转发 `MAX_AUTO_MENTION_HOPS=6`。
- prompt 层规则：收到 peer 消息后不立即回 ping 发起方，避免 A↔B 互 @ 占满预算。

### 11.2 并发

- **Host 主 dispatch**：串行（Claude SDK 单线工具调用本就串行）。
- **Peer `call`（A2A 升级）**：成员可在自己 turn 内经 `agent_message({mode:'call'})` 同步触发队友 turn，走 `parallel:true` 路径，**不受 `allowNesting` / 串行队列限制**，但受独立 `peerCallCountByTurn` 预算与 `consultDepth` 约束。
- 多 Member 完全并行（Host 一次提交数组）+ UI 多泳道渲染仍为未来扩展。

### 11.3 超时

每个 dispatch 的 `timeoutMs` 默认 120s。到时 dispatcher 触发 abort，返回 `code=timeout`。

### 11.4 中止

- 用户点击 Session 停止 → 所有进行中 dispatch 全部 cancel。
- Member 内部 cancel 通过 AbortSignal 传到 ClaudeSDKExecutor，复用现有取消路径。

### 11.5 Member 不可用

- Member 已 disabled 或 provider key 缺失：返回 `code=member_disabled` 或 `code=internal`。
- 在 Inspector toggle 开关变化时，**进行中的 dispatch 不会被中止**（避免半截状态）；下一个 turn 才生效。
