# 会话附件与侧栏文件夹拖拽体验设计

> 状态: 已落地 | 最后核对: 2026-08-13

## 背景与目标

当前会话内容区已经支持从系统拖入文件与文件夹，但拖拽遮罩偏实色，提示组未稳定落在可视内容区中心；已添加资源继续使用边框明显的矩形标签，信息密度较高。左侧项目菜单只能通过按钮和目录选择器添加项目，无法直接接收系统文件夹拖拽。

本次改造统一采用“清透扁平”视觉方向：优化内容区毛玻璃遮罩和附件圆头标签，并为左侧项目区域增加只接收顶层文件夹的拖拽入口。侧栏投放与内容区投放必须互斥，不能同时显示反馈或重复处理一次拖拽。

## 拖拽区域与事件路由

- 保留会话内容区现有窗口级文件拖拽能力，但在事件命中侧栏项目投放区域时主动让行。
- 侧栏项目列表外层作为独立投放区域，使用稳定的数据属性标识，负责自己的进入、悬停、离开和放下状态。
- 侧栏拖拽只处理本次 `DataTransfer` 中的顶层条目，不读取文件夹内容，不递归扫描子目录。
- 一次可以拖入多个顶层文件夹；文件与文件夹混合拖入时只添加有效文件夹，普通文件被忽略。
- 拖拽悬停阶段优先使用 `DataTransferItem.webkitGetAsEntry()` 判断是否存在目录；放下后通过 preload 路径桥接和 `statFileKind` 再做权威校验。
- 侧栏区域不处理只包含普通文件的投放；内容区仍可处理文件、图片和文件夹附件。

## 内容区毛玻璃遮罩

- 遮罩只覆盖会话主内容区，不覆盖左侧菜单栏。
- 遮罩使用浅蓝灰半透明背景、背景模糊和轻微饱和度增强，保留后方内容轮廓但降低干扰。
- 图标与两行提示组成一个居中提示组，在遮罩内同时水平和垂直居中，不依赖页面滚动位置。
- 主文案为“松开即可添加到会话”，副文案为“支持文件和文件夹”。
- 遮罩淡入，提示组伴随轻微上移动效；用户启用 `prefers-reduced-motion` 时取消位移动效。

## 会话附件标签

- 非图片文件和目录使用有底色、弱边框或无边框的扁平圆头标签，保持图标、名称和移除按钮单行排列。
- 普通文件使用低饱和浅蓝灰底色；目录使用略深的蓝色层级，以便快速区分资源类型。
- 标签采用紧凑高度和完整胶囊圆角，长名称单行省略，悬停继续通过 `title` 显示完整路径。
- 移除按钮默认弱化，悬停和键盘聚焦时提高对比度并显示清晰焦点态。
- 图片附件继续使用现有缩略图卡片，不把图片强制改为纯文字标签。
- 已发送消息中的只读附件沿用同一视觉语言，但不显示移除操作。

## 侧栏文件夹投放与项目添加

- 文件夹进入侧栏项目区域后，项目列表显示浅蓝半透明高亮、毛玻璃和虚线内轮廓，中央提示“松开以添加项目”。
- 有效投放时使用复制语义光标；离开侧栏、窗口失焦或完成放下后必须清理投放状态。
- 每个文件夹以目录 basename 作为项目名，以目录绝对路径作为项目根路径，复用现有 `openWorkspace({ create })` 创建链路。
- 新增 `addProjectsFromDirectories(paths)` 作为批量项目入口：逐项添加，单个失败不阻断其余目录。
- 已存在相同根路径的项目直接跳过，不重复创建。
- 批量处理完成后刷新项目列表，并切换到最后一个成功添加的项目；不自动创建新任务。
- 操作结束后统一显示结果摘要，包含成功数以及被忽略的普通文件、重复目录或失败目录数量。

## 侧栏新建项目弹窗

- 新建项目弹窗沿用应用主题 token，不写死背景、文字、主色、字号或间距；Modal surface、表单、提示条和投放态均从 `--panel`、`--text-*`、`--primary-*`、`--font-*`、`--pad-*` 和 `--r-*` 取值。
- 项目名称保留手动编辑；通过系统目录选择器或弹窗内拖入文件夹时，如果名称为空，则使用文件夹 basename 自动填充。
- 项目位置使用虚线投放区：点击按钮打开系统目录选择器，拖拽时只接受目录意图，放下后通过 `file:stat-kind` 做最终目录校验；普通文件和无法解析路径的投放会给出提示。
- 未选择项目位置时，继续复用原有临时目录创建逻辑；选择或拖入位置后，创建请求使用该目录作为 workspace root path。

## 异常与边界处理

- 如果拖拽声明包含文件但无法解析出任何本地路径，显示明确错误并建议改用“添加项目”按钮。
- 路径能够解析但最终没有目录时不调用项目创建接口；存在普通文件时以轻提示说明已忽略。
- 多目录中部分路径失效、无权限或创建失败时继续处理其余目录，并在汇总提示中报告失败数量。
- 连续触发嵌套元素的 `dragenter`/`dragleave` 时使用深度计数，避免高亮闪烁。
- 会话发送中仍禁止向内容区添加附件；侧栏项目添加与会话发送状态相互独立。

## 组件与测试边界

- `design/services/composer-attachments.ts` 保留共享的本地拖拽路径解析，并新增纯函数形式的目录条目识别或筛选辅助能力。
- `ComposerV2.tsx` 负责内容区拖拽让行、遮罩文案和结构；对应样式文件负责毛玻璃与居中布局。
- `SidebarSessionList.tsx` 负责侧栏拖拽交互状态和投放反馈。
- `SessionSidebarContext.tsx` 提供按目录批量添加项目且不新建任务的业务入口，避免列表组件直接拼装工作区请求。
- 先补失败测试覆盖目录识别、文件与目录混合投放、只保留顶层条目、重复路径跳过、部分失败继续和不自动新建任务，再写最小实现使其通过。
- 完成后运行相关 Vitest、Desktop 类型检查和 lint，并手工验证内容区与侧栏拖拽不会互相抢占。

## 非目标

- 不递归扫描拖入目录，也不把子目录自动创建为项目。
- 不支持将普通文件拖入侧栏创建项目。
- 不改变项目数据库结构、工作区 IPC 协议或现有按钮添加项目流程。
- 不改变附件数量上限、附件发送协议或图片预览能力。
- 不在本次改造中统一看板、快捷任务和其他页面的附件样式。
