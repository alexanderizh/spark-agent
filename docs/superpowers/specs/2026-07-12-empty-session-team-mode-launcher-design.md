# 空会话团队模式启动栏设计

> 状态: 已落地 | 最后核对: 2026-07-12

## 1. 背景与结论

团队模式目前隐藏在输入区下方的 Agent 选择器中，入口层级较深，用户容易把它理解为某种 Agent，而不是一种与“单 Agent”互斥的会话运行模式。这会降低团队模式的发现率，也让首次使用路径依赖用户主动展开 Agent 菜单。

本次设计确认有必要提升团队模式在空会话中的曝光率。采用左上角轻量启动模式栏，使用“单 Agent / 团队”分段控件表达互斥关系。该控件只配置新会话的启动方式，不成为常驻导航，也不改变已有会话的界面。

## 2. 设计目标

- 让用户在空会话首屏直接发现团队模式。
- 明确表达“单 Agent”和“团队”是两种互斥运行模式。
- 保持团队模式按会话生效，禁止从全局偏好继承 `enabled`，避免跨会话串台。
- 复用现有团队配置、Host 回退、会话持久化和关闭团队模式逻辑。
- 在无团队、团队失效、团队被删除和窄窗口场景下提供明确行为。
- 不增加历史会话的视觉负担。

## 3. 展示范围

启动模式栏仅在空会话显示，包括：

- 尚未创建 Session 的空白输入页。
- 已创建但消息数为 0、仍允许调整启动配置的会话。

以下场景不显示：

- 已存在用户或助手消息的当前会话。
- 从历史记录打开的老会话。
- 第一条消息发送成功后。

启动模式栏消失后，会话继续使用 `sessions.metadata.team` 中的会话级配置。现有 Inspector、群聊时间线、团队事件与运行时逻辑不变。

## 4. 布局与视觉

### 4.1 位置

控件位于空会话内容区左上方、窗口操作区下方，与主欢迎内容保持足够距离。它不进入输入框，也不与顶部窗口按钮组成同一工具栏。

### 4.2 分段控件

分段控件包含两个等高选项：

- `Agent`
- `团队`

视觉要求：

- 使用紧凑的 28px 左右高度，不使用大号按钮。
- 外层为低对比边框和中性背景。
- 选中项使用克制的主题色背景、清晰文字和轻微阴影。
- 不使用说明性副标题、营销文案或常驻提示。
- 不换行，不随视口宽度缩放字号。

### 4.3 团队选择器

选择 `团队` 后，在分段控件右侧显示团队选择器：

- 展示团队头像、团队名和下拉箭头。
- 默认宽度约 190px，团队名过长时省略。
- 宽屏可在右侧显示轻量“管理”入口。
- 窄窗口隐藏外部“管理”入口，将管理动作放入团队下拉菜单。

选择 `单 Agent` 时不显示团队选择器。

## 5. 状态设计

### 5.1 默认单 Agent

- 空会话默认选中 `单 Agent`。
- 输入区下方继续显示现有 Agent 选择器。
- 输入框使用单 Agent 文案。
- 不自动继承其他会话的团队启用状态。

### 5.2 开启团队且存在可用团队

用户选择 `团队` 后：

1. 优先恢复最近使用且仍然有效的已保存团队。
2. 最近团队无效时，选择列表中的第一个有效团队。
3. 应用团队的 Host、成员、深度、讨论轮数和成员通信配置。
4. 会话适配器、Provider 与模型跟随团队 Host 的 Agent 配置。
5. 隐藏输入区下方的 Agent 选择器。
6. 输入框切换为团队模式文案。

团队选择器负责切换已保存团队，不在顶部直接编辑 Host 或成员。详细配置仍由团队管理页或 Inspector 承担。

### 5.3 没有任何团队

用户选择 `团队`，但不存在有效团队时：

- 不静默拼凑临时团队。
- 不使用单个 Host 冒充团队。
- 团队选择器位置显示“创建第一个团队”入口。
- 输入区发送按钮暂不可用，并给出简短、就地的不可用原因。
- 点击创建入口进入现有团队创建流程。
- 创建成功后自动应用新团队，保持 `团队` 选中，并恢复发送能力。
- 用户取消创建时仍停留在团队状态，可手动切回 `单 Agent`。

### 5.4 团队失效或被删除

- 当前选中团队被删除时，如果仍为空会话且存在其他有效团队，自动选择第一个有效团队。
- 如果没有其他团队，进入“创建第一个团队”状态。
- 不自动切回单 Agent，避免模式在用户不知情时变化。

### 5.5 切回单 Agent

用户在空会话中选择 `单 Agent` 时：

- 关闭团队模式并解除当前会话与已保存团队的关联。
- 当前团队 Host 作为单 Agent 默认值接续。
- 输入区下方重新显示 Agent 选择器。
- 会话适配器、Provider 和模型同步为该 Host 的 Agent 配置。
- 用户可以继续从底部 Agent 选择器切换其他 Agent。

此行为沿用现有 `onDisableTeamMode` 语义，不删除团队，也不丢失已缓存的最近 Host/成员偏好。

## 6. 数据与状态边界

### 6.1 权威来源

- `teamConfig.enabled` 仍以当前会话的 `sessions.metadata.team` 为权威来源。
- 全局 composer prefs 只记录最近使用的团队、Host 或成员，用于用户显式选择团队后的便捷预填。
- 新会话和没有团队 metadata 的老会话必须以单 Agent 启动。

### 6.2 团队选择记忆

新增或复用“最近使用团队 ID”偏好时，读取后必须验证：

- 团队仍存在。
- 团队处于启用状态。
- Host Agent 仍有效，或可通过现有 Host 回退链解析。

无效偏好不得直接写入会话配置。

### 6.3 会话创建

团队模式下发送第一条消息时，创建 Session 的请求必须携带完整 `teamConfig`，保证 Session 激活与首次发送之间不会短暂回退为单 Agent。

## 7. 组件边界建议

新增独立的空会话启动控件，例如 `EmptySessionModeLauncher`，职责仅包括：

- 渲染单 Agent / 团队分段控件。
- 渲染条件团队选择器。
- 加载并校验可用团队。
- 抛出模式切换、应用团队和创建团队事件。

该组件不负责：

- 直接写 Session metadata。
- 修改 Agent 运行时配置。
- 编辑团队成员。
- 处理团队派发或消息渲染。

这些行为继续由 `ChatView` 和现有团队运行时逻辑负责。避免把顶部展示组件与团队业务状态机重新耦合。

## 8. 可访问性与交互

- 分段控件使用单选组语义，可通过方向键切换。
- 团队选择器支持键盘打开、上下选择、Enter 确认和 Escape 关闭。
- 切换模式后焦点保持在启动栏，不自动抢占输入框。
- 创建团队成功后，可将焦点返回团队选择器或输入框。
- 团队加载期间禁用重复切换，并显示轻量加载状态。
- 创建或加载失败时保留用户当前模式选择，并提供可重试提示。

## 9. 响应式规则

- 宽屏：分段控件、团队选择器、管理入口单行排列。
- 中等宽度：缩短团队选择器宽度，团队名省略。
- 窄窗口：隐藏外部管理入口；分段控件和团队选择器仍保持单行。
- 空间仍不足时，优先缩短团队名，不缩小分段控件文字，不换行覆盖窗口按钮。

## 10. 测试范围

### 10.1 状态测试

- 新会话默认单 Agent。
- 开启团队时应用最近有效团队。
- 最近团队失效时回退第一个有效团队。
- 无团队时进入创建引导且不能发送。
- 创建团队成功后自动应用并可发送。
- 切回单 Agent 后恢复底部 Agent 选择器和 Host 运行时。
- 第一条消息后启动栏消失。
- 历史会话不显示启动栏。
- 切换会话不会继承其他会话的 `enabled`。

### 10.2 视觉与边界测试

- 桌面宽屏、最小支持窗口宽度和侧边面板打开状态。
- 长团队名、省略与下拉菜单边界定位。
- 深色和浅色主题。
- 团队加载、空状态、失败状态。
- 顶部控件不得遮挡窗口控制、画布工具或主欢迎内容。

## 11. 非目标

- 不重新设计团队创建页面。
- 不修改团队派发引擎或 A2A 协议。
- 不改变历史团队会话的切换方式。
- 不把团队模式改成全局设置。
- 不在顶部直接编辑 Host、成员或讨论参数。
