# 画布模型切换参数兼容性设计

> 状态: 已落地 | 最后核对: 2026-07-16

## 背景

画布任务配置面板允许用户在同一节点上切换媒体模型。当前模型切换后会重新生成参数字段和默认值，但参数草稿合并逻辑会优先保留用户曾经编辑过的旧值，不会判断该值是否符合新模型的参数约束。

例如旧模型使用 `size=2:1`，切换到火山方舟 Seedream 4.5 后，界面仍保留 `2:1`。Seedream 4.5 的 `size` 实际只接受 `2K`、`4K` 或合法的 `宽x高` 尺寸，提交后因此收到 Provider 的 `InvalidParameter` 错误。

## 目标

- 模型切换时保留新模型仍支持的参数值。
- 新模型不支持旧值时，将该字段切换为新模型默认值。
- 支持合法自定义值的字段不能只按枚举判断；例如 `2848x1600` 应继续保留。
- 首次打开包含旧参数的历史节点时执行同样的兼容性处理。
- 使用通用的 schema 驱动机制，不为某个模型在 UI 组件中写死判断。

## 非目标

- 不改变 Provider 请求格式、媒体适配器或任务提交协议。
- 不自动修改已完成任务的历史记录。
- 不为缺少约束信息的自定义参数猜测 Provider 私有规则。
- 不重置与新模型兼容的全部参数。

## 方案比较

### 方案 A：基于 schema 约束校验参数值

参数字段保留枚举、自定义值开关和格式约束。模型切换后，用新字段约束校验当前草稿；兼容值保留，不兼容值回退到新模型默认值。

优点是行为通用、可测试，并能覆盖后续模型的相同问题。缺点是需要把 JSON Schema 的必要约束传递到 renderer 参数字段。

### 方案 B：在画布组件中写死尺寸格式

在模型切换回调中专门判断 `size` 是否为 `宽x高`。

改动较少，但只能解决当前图片尺寸问题，其他枚举或自定义参数仍可能复发，并会让模型差异进入 UI 组件。

### 方案 C：切换模型时重置全部参数

每次切换模型都重新应用默认值。

实现简单，但会丢失仍兼容的用户选择，不符合用户确认的保留策略。

采用方案 A。

## 参数兼容规则

对于新模型暴露的每个字段，按以下顺序处理：

1. 当前值为空时，使用计算出的新模型初始值。
2. 当前值与新模型枚举中的值完全相同时，保留当前值。
3. 字段允许自定义值且提供格式约束时，当前值满足格式约束则保留。
4. 字段允许自定义值但没有可用格式约束时，保持现有宽松行为，避免错误清除合法的 Provider 私有值。
5. 非自定义枚举字段的当前值不在枚举中时，回退到新模型默认值。
6. 字段已不存在于新模型参数列表时，不再保留在可见草稿中；提交阶段现有 contract 裁剪仍作为最后防线。

Seedream 的 `size` schema 增加“正整数宽度 `x` 正整数高度”的格式约束。预设的 `2K`、`4K` 由枚举直接接受，自定义的 `2848x1600` 由格式约束接受，`2:1` 则被判定为不兼容。

## 状态与数据流

1. 用户选择新模型，`selectedModelKey` 更新。
2. 面板解析新模型的 capability、参数 schema 和 defaults。
3. schema 字段转换保留自定义值格式约束。
4. 初始值解析先校验历史节点或任务中的参数；不兼容值不再覆盖模型默认值。
5. 对已编辑的内存草稿执行同样的兼容性合并，避免旧值因“用户已编辑”标记被无条件保留。
6. 控件显示处理后的值，任务保存和运行继续使用现有参数构建及 contract 裁剪流程。

## 模块边界

- `canvasParameterPresentation.ts`：扩展 `SchemaField`，承载 renderer 需要的格式约束。
- `CanvasInlineAiComposer.tsx`：从 JSON Schema 提取格式约束，并在历史参数初始化时调用兼容性判断。
- `canvasModelParamDraftState.ts`：集中实现参数值兼容性判断和模型切换草稿合并。
- `CanvasOperationPanel.tsx`：在参数字段或模型变化后调用兼容合并，不在组件内写模型特例。
- `media-model-manifest.ts`：为 Seedream `size` 声明可验证的自定义尺寸格式。

现有大型组件只接入纯函数，不继续加入大段模型规则。

## 错误与边界处理

- 无效或无法编译的格式约束按“缺少约束”处理，不阻塞模型选择。
- 默认值为空时，不兼容参数回退为空，由 Provider 或提交层应用其默认行为。
- 参数别名继续沿用现有 `aspect_ratio` / `aspectRatio` 读取逻辑。
- 全景图的 `2:1` 预设只有在新字段能表达该比例时才保留或映射为匹配尺寸；否则使用模型默认值。
- UI 中保留现有“不支持值”防御性展示，处理尚未经过兼容迁移的异常数据，但正常切换后不应再出现该状态。

## 测试策略

采用测试驱动方式添加纯函数回归测试：

- `size=2:1` 切换到允许 `宽x高` 自定义尺寸、默认值为 `2K` 的模型后得到 `2K`。
- `size=2848x1600` 在相同模型约束下继续保留。
- 当前比例在新模型枚举中存在时继续保留。
- 普通枚举字段的旧值不在新枚举中时回退到默认值。
- 允许自定义但缺少格式约束的字段保持现有值。
- 首次读取历史节点中的非法值时不覆盖 capability 默认值。
- 全景图可匹配到 `2:1` 尺寸时仍使用匹配尺寸。

验证范围包括相关 Vitest、desktop typecheck，以及 `git diff` 的调用点和变更范围核对。

## 影响与风险

GitNexus MCP 当前未暴露，无法执行专属 impact 和 detect_changes。按仓库降级规则，实施前后使用直接调用点检索、相关测试和 `git diff` 核对影响范围。

主要风险是兼容性判断过严导致合法自定义值被重置。设计通过“只有 schema 明确提供格式约束时才校验自定义值”限制该风险；Seedream 尺寸规则由 manifest 声明，而不是由通用 UI 猜测。
