# 无限画布图片反推与深度视频节点设计

> 状态: 实施中 | 最后核对: 2026-08-01

## 1. 背景与目标

无限画布需要补充两个可复用的行业工作流节点：

1. **图片反推**：读取一张输入图片，通过具备视觉能力的文本模型生成一段可直接用于文生图或图生视频的中文完整提示词。
2. **深度视频**：读取一段输入视频，在本机生成近处为白、远处为黑的灰度深度视频，为视频动作迁移、姿态参考和结构控制提供素材。

图片反推需要调用用户已经配置的多模态文本模型。深度视频不调用云端模型或大模型 API，但需要在本机运行预训练的单目深度估计模型。模型通过 Spark 自建 MinIO 制品仓库按需下载，首次下载完成后可离线运行。

本次同时从“基础任务”菜单移除“文本生成”“文本改写”“Prompt 优化”三个通用入口。底层操作类型、历史画布兼容、影视专用任务和 Agent 工具能力继续保留，避免破坏转剧本、分镜脚本与实体抽取等既有流程。

## 2. 成功标准

### 2.1 图片反推节点

- “基础任务 → 图像”中出现“图片反推”。
- 节点只接受图片输入，运行前至少连接一张图片；首版只发送第一张有效图片，额外图片在校验阶段明确提示不支持。
- 默认任务指令固定要求输出中文生成提示词，不输出分析过程、标题、Markdown 代码块或解释。
- 输出内容覆盖主体、环境、构图、镜头、光影、色彩、材质和风格；模型无法可靠判断的细节不得虚构为事实。
- 结果写回普通文本节点，并保留任务、输入、输出资产和血缘连线。
- 模型选择复用画布“图片理解”预设及现有 vision 文本调用链；未配置可看图模型时给出可操作错误。

### 2.2 深度视频节点

- “基础任务 → 视频”中出现“深度视频”。
- 节点恰好接受一段视频输入，不要求 Prompt，不显示云端 Provider、模型、Agent 或 Skill 配置。
- 首次运行时按需下载并校验本地深度模型；后续运行不访问云端。
- 输出保持原视频时长、帧率和画布尺寸，编码为 MP4/H.264，移除音轨。
- 输出语义固定为近处白、远处黑；不是普通灰度化视频。
- 处理过程显示安装、解码、深度推理、编码和完成阶段，并支持取消。
- 成功后生成普通视频资产和视频节点，建立任务血缘；失败或取消不留下半成品。

### 2.3 MinIO 制品

- 使用 Apache-2.0 许可的 Depth Anything V2 Small ONNX 量化模型。
- 将推理所需的模型、配置和许可证打成版本化归档，发布到 `artifact-repository/v1/models/depth-anything-v2/`。
- 在线 `index.json` 增加带版本、大小和 SHA-256 的模型条目；发布前备份现有清单，发布后从公网地址回读并校验。
- 发布脚本只从环境变量读取 MinIO 凭据，不把凭据写进仓库、命令输出或文档。

## 3. 非目标

- 不移除 `text_generate`、`text_rewrite`、`prompt_optimize` 的协议类型和执行能力。
- 不把图片反推接入图片生成 Provider Manifest；它属于多模态文本理解任务。
- 不用 FFmpeg 灰度滤镜冒充深度估计。
- 不在首版引入 Python、PyTorch、CUDA 或 Video Depth Anything 运行时。
- 不提供米制绝对深度、EXR/NPZ、彩色深度图或深度反转开关。
- 不在首版提供多模型质量档、GPU 专属档或批量视频处理。
- 不把模型随桌面安装包预置，避免扩大基础安装体积。

## 4. 方案选择

### 4.1 图片反推

新增显式 `image_prompt_reverse` 操作类型，而不是创建一个标题不同的 `text_generate` 节点。显式类型能让菜单、输入约束、默认提示词、预设选择、任务日志、工作流序列化和后续统计保持一致，同时继续复用成熟的文本任务执行与 vision 图片附件传输。

### 4.2 深度视频

采用 Depth Anything V2 Small 的 ONNX INT8 模型，以 Node/Electron 可用的 Transformers.js/ONNX Runtime 本地执行。选择该方案的原因是：

- 模型小、跨平台、Apache-2.0，可作为桌面产品默认能力。
- 不要求用户安装 Python 或 PyTorch。
- 能接入现有 MinIO 制品下载、校验和版本管理。
- 与逐帧 FFmpeg 解码/编码组合后可以完全离线运行。

Video Depth Anything 的时间一致性更强，但官方实现依赖 PyTorch 且硬件成本明显更高，保留为未来高质量档，不进入本次范围。

## 5. 节点与协议模型

### 5.1 操作类型

在 renderer 与 protocol 的 `CanvasOperationType` 中新增：

- `image_prompt_reverse`
- `video_depth_map`

对应节点类型与操作类型保持一一对应。旧文档反序列化不受影响，新工作流可直接序列化这两个操作。

### 5.2 菜单组织

“基础任务”菜单调整为：

- 图像：文生图、图生图 / 编辑、多图合成、图片反推。
- 视频：文生视频、图生视频、视频编辑、视频扩展、深度视频。
- 音频：文生音频、语音转写。

删除空的“文本”分组，不再展示文本生成、文本改写和 Prompt 优化。影视创作菜单及专用流水线节点不变。

### 5.3 执行分类

画布任务从现有“文本任务 / 媒体任务”二分扩展为三类：

- 文本模型任务：包含现有三类文本操作和 `image_prompt_reverse`。
- 云端媒体任务：保持现有图片、视频和音频生成操作。
- 本地媒体任务：首个操作为 `video_depth_map`。

分类逻辑集中在小型 helper 中，避免在面板、提交、重试和批量执行处重复硬编码条件。

## 6. 图片反推数据流

1. 用户创建“图片反推”节点并连接一张图片。
2. 操作面板显示输入、图片理解 Provider/模型和只读的任务说明；不要求用户填写 Prompt。
3. renderer 校验恰好一张有效图片，并将本地图片物化为安全的 base64/data URL 或已有公网 URL。
4. `canvas:task:generate-text` 沿用现有图片附件协议调用 vision 文本模型。
5. system/user 指令要求模型只输出一段中文完整提示词，禁止输出分析过程。
6. 结果沿用文本任务落库逻辑，生成文本资产、文本节点和 `generated` 血缘。

默认指令采用稳定内置值，节点仍可通过“图片理解”任务预设选择 Provider 和模型，但不把用户的普通文本预设错误继承到图片反推节点。

## 7. 深度视频数据流

### 7.1 本地模型安装

新增深度模型完整性服务，职责限定为：

- 从安装清单选择受支持的 Depth Anything V2 Small 制品。
- 检查本地缓存版本、归档内容与 SHA-256。
- 按需调用通用制品安装器下载到应用数据目录。
- 暴露 `missing / installing / ready / error` 状态和安装进度。
- 返回经过校验的本地模型目录，不直接参与视频推理。

模型制品使用新的 `model` artifact 类型，并复用现有归档下载、临时目录、校验、原子替换和进度能力。模型归档至少包含：

- `config.json`
- `preprocessor_config.json`
- `onnx/model_int8.onnx`
- `LICENSE`
- `model-package.json`，记录上游仓库、上游 revision、量化格式和文件哈希。

推理代码强制使用本地路径并关闭远程模型回退，避免模型缺失时偷偷访问 Hugging Face。

### 7.2 推理管线

主进程创建独立 worker 执行深度任务，避免 ONNX 推理阻塞 Electron 主线程。管线如下：

1. 使用 ffprobe 读取时长、帧率和尺寸。
2. FFmpeg 将源视频解码为有界队列中的 RGB 帧。
3. worker 以固定输入尺寸运行 Depth Anything V2 Small INT8 推理。
4. 将相对深度按稳健百分位归一化，方向统一为近白远黑，再缩放回源尺寸。
5. 对连续帧执行轻量时间平滑；检测到明显场景切换时重置历史帧，避免跨镜头残影。
6. FFmpeg 从灰度帧编码 MP4/H.264，不映射输入音轨。
7. 输出先写临时文件，成功后原子移动到画布媒体产物目录。

解码、推理和编码之间必须有背压，不能把整段视频帧一次性载入内存。任务取消时终止 worker 与 FFmpeg 子进程并清理临时目录。

### 7.3 画布写回

本地任务使用现有 `CanvasTask` 状态和事件结构，不另建平行数据库。成功响应提供本地文件路径、MIME、尺寸、时长和缩略图所需信息；renderer 复用媒体产物写回逻辑创建：

- `video/mp4` 资产，来源标记为本地派生产物。
- 普通 `video` 结果节点。
- 输入视频 → 深度任务 → 结果视频的血缘关系。

任务节点保留 `video_depth_map` 类型，方便重试、工作流保存和问题诊断。

## 8. UI 与交互

### 8.1 图片反推面板

- 标题为“图片反推”。
- 输入区仅接受图片节点。
- 未连接图片时禁用运行并显示“请连接一张输入图片”。
- 运行配置只展示图片理解模型选择与固定输出说明。
- 完成消息为“提示词已生成”。

### 8.2 深度视频面板

- 标题为“深度视频”。
- 输入区仅接受一个视频节点。
- 不展示 Prompt、负向 Prompt、Provider、Agent、Skill 或模型参数。
- 本地模型未安装时，主按钮显示“下载模型并运行”；已安装时显示“生成深度视频”。
- 任务节点依次显示“下载模型”“解析视频”“生成深度”“编码视频”。
- 模型下载失败时允许重试；磁盘空间不足、模型校验失败、FFmpeg 缺失和视频无法解码都显示针对性错误。

## 9. 错误处理与安全

- 图片反推拒绝无图片、多图片、损坏 data URL 和不支持的输入类型。
- 深度视频拒绝无视频、多视频、非白名单路径和无法读取的源文件。
- 所有文件读写继续经过 SafeFile 允许根目录校验；输出只能写入应用媒体产物目录或受管临时目录。
- MinIO 发布使用环境变量传入凭据；日志仅输出对象 key、大小和哈希，不输出认证信息。
- 发布脚本先备份线上 `index.json`，再上传制品和 staging 清单，最后替换正式清单并从公网地址回读验证。
- 下载时必须核对 manifest 大小与 SHA-256；归档解压必须阻止路径穿越。
- 推理异常、取消或应用退出时清理临时帧、临时视频和未完成下载。
- 用户已有未提交画布改动必须保留；实现时只修改任务相关文件并逐项核对 diff。

## 10. 测试策略

### 10.1 协议与菜单

- 新操作类型可被 protocol schema 和工作流编译器接受。
- 基础菜单包含两个新节点，不再包含三个通用文本入口，也不存在空文本分组。
- 旧文本操作仍能被协议、历史节点和影视专用流程读取与执行。

### 10.2 图片反推

- 输入约束覆盖无图、单图和多图。
- operation 分类进入文本 vision 链路。
- 请求携带第一张图片与固定指令，输出落为文本节点。
- 缺少可看图 Provider 时错误信息正确。

### 10.3 模型制品

- manifest 能解析 `model` 类型。
- 安装器验证 SHA-256、归档结构、版本和安全路径。
- 完整性服务覆盖未安装、安装成功、损坏重装、下载失败和并发安装去重。
- 发布脚本的 manifest 合并、冲突检测、备份和回读验证可在 mock S3 服务下测试。

### 10.4 深度推理

- 深度归一化方向为近白远黑。
- 时间平滑在同镜头生效，场景切换会重置。
- 有界队列遵守背压，取消会终止子进程并清理临时文件。
- 生成参数保留原帧率、分辨率和时长，不包含音轨。
- 本地任务成功、失败、取消和重试都正确更新画布任务与血缘。

### 10.5 集成验收

- 使用一段短视频生成深度视频，并通过 ffprobe 核对编码、帧率、尺寸、时长和无音轨。
- 抽取至少三帧检查前景更亮、背景更暗且无明显跨镜头残影。
- 用一张图片运行图片反推，确认结果可直接作为文生图或图生视频 Prompt。
- 从公开 MinIO 地址完整下载模型归档，核对大小和 SHA-256 与线上清单一致。

## 11. 文档与发布

实现时同步更新无限画布当前能力文档，说明：

- 基础任务菜单的新结构。
- 图片反推依赖视觉文本模型。
- 深度视频是本地模型推理而非普通灰度滤镜。
- 首次使用的模型下载、离线能力、FFmpeg 依赖和磁盘占用。

完成代码、测试、文档和 MinIO 发布后运行 GitNexus 更新索引；若 GitNexus 仍不可用，则按项目降级规则用调用点检索、相关测试与 `git diff` 完成变更范围核对，并在交付说明中记录原因。
