# Provider 渐进式配置设计

> 状态: 已落地 | 最后核对: 2026-07-02

## 目标

在不改变 Provider 保存结构和运行时路由的前提下，降低新增模型供应商时的认知成本。模板继续自动写入完整配置，普通用户只需确认名称、模型、地址和密钥；适配器、调用方式、能力清单与参数默认值归入高级设置。

## 交互

- 抽屉每次打开时，高级设置默认收起。
- 基础区保留模型类型、协议、供应商模板、显示名称、默认模型、BaseURL、API Key，以及文本模型的 Codex API 类型、连接测试/获取模型、默认 Provider。
- BaseURL 输入框下方以小字实时预览当前协议最终会命中的请求地址，避免把供应商原始地址与应用自动拼接的路径混淆。
- 高级设置包含生图接口来源、平台适配器、调用方式、媒体模型清单、能力和参数默认值，以及文本模型的上下文窗口与可用模型。
- 仅 `Anthropic 格式` 文本 Provider 展示 Claude `Haiku / Sonnet / Opus` 档位映射；`OpenAI 格式` 不再复用这套命名，直接由默认模型、模型列表和 Codex API 类型控制。
- `OpenAI 格式` 文本 Provider 的手动新建默认优先 `Responses API`，但仍保留 `Chat Completions` 作为第三方兼容选项。
- 折叠按钮显示当前自动配置摘要，让用户知道模板已经完成适配器和模型配置，无需重复操作。
- 展开或收起只改变渲染，不重置表单状态；保存继续复用现有 `handleSave` 数据流。

## 兼容性与验证

- 不修改协议类型、IPC 请求或运行时媒体路由。
- 旧 Provider 的全部字段仍加载到表单，展开高级设置即可编辑。
- 组件测试覆盖默认折叠、点击展开和摘要展示；再运行桌面端类型检查。
