# 桌面端可选能力包与后台安装设计

> 状态: 已落地 | 最后核对: 2026-08-02

> 交付范围：本轮已完成离线 Office Viewer 与本地深度处理；Computer Use 按明确要求完全跳过，现有实现和打包边界保持不变，不属于本轮验收结论。

## 背景

SparkWork 当前把本地深度推理运行时、独立 Node Runtime、Playwright MCP 和离线 Office Viewer
资源直接放入桌面安装包。相关能力虽然可用，但 macOS arm64 DMG 已从约 195.7 MB 增长到
397.6 MB。其中可选能力带来的主要增量为：

- Computer Use 引入的独立 Node Runtime，安装包压缩后约增加 34.8 MB；
- 离线 Office Viewer 的 Worker、WASM、字体和静态资源，约增加 73.1 MB；
- 本地深度能力的 Transformers/ONNX 运行时，约增加 65.4 MB。

深度模型权重已经通过 Spark MinIO 制品仓库按需下载，但推理运行时仍作为
`@huggingface/transformers` 的生产依赖进入安装包。当前 macOS arm64 产物还包含不需要的
`onnxruntime-web`、Linux x64 和 Linux arm64 ONNX 二进制。

## 目标

1. 立即裁剪基础包中不需要的 ONNX Web Runtime 和异平台 Native 二进制。
2. 建立统一的可选能力包管理器，支持离线 Office 预览和本地深度处理。
3. 应用启动时只检查远程清单；由用户选择需要的能力后后台安装。
4. 右上角统一展示下载、校验、解压和激活进度。
5. 设置「完整性」页支持安装、更新、修复、卸载和自动更新。
6. 所有远程制品使用版本、平台、架构和 SHA-256 约束，安装失败不破坏当前可用版本。
7. 基础应用在没有任何可选能力包、没有网络或下载失败时仍能正常启动和使用核心功能。

## 非目标

- 不把 Electron Framework、业务代码或安全敏感的 Computer Use Native Host 改成远程脚本。
- 不在首次启动时默认勾选或自动下载数百 MB 资源。
- 不维护三套相互独立的下载器、状态机和设置页协议。
- 不依赖“安装包内再放一个压缩包”作为主要体积优化。DMG 和 NSIS 已经压缩，这种方式通常
  不能显著降低发布文件大小。

## 方案比较

### 方案 A：首次启动自动下载全部组件

基础安装包最小，功能很快达到完整状态，但用户会在没有明确选择时消耗大量流量和磁盘。
它只转移下载时机，没有降低首次安装后的总下载量。

### 方案 B：完全等到第一次执行功能时下载

网络和磁盘消耗最小，但会在用户真正打开 Office 文档、运行深度任务或启动电脑操作时造成
明显中断。

### 方案 C：启动检查、用户勾选、后台安装（采用）

启动后静默检查几 KB 的 manifest；发现未安装能力时展示一次选择弹窗。所有大组件默认不勾选，
用户确认后后台排队安装。用户稍后也可以在功能入口或设置「完整性」页安装。这一方案同时保留
小安装包、知情下载和较平滑的首次使用体验。

## 总体架构

新增统一 `OptionalCapabilityManager`，负责：

- 获取和缓存 Spark artifact manifest；
- 将远程 artifact 聚合为用户可理解的能力包；
- 根据当前平台、架构和应用版本选择兼容制品；
- 读取已安装版本和完整性状态；
- 串行调度下载、SHA-256 校验、解压、健康检查和原子激活；
- 向主进程 IPC、右上角进度中心和设置页发布同一份状态；
- 在安装失败、取消或应用退出时保留当前激活版本。

能力定义和通用安装状态放在独立模块中，不继续增加已经超过 6,000 行的
`SettingsView.tsx`。设置页只组合独立的 `OptionalCapabilitiesCard`。

### 能力状态

每项能力使用以下状态：

`checking → missing → queued → downloading → verifying → extracting → activating → ready`

失败进入 `error`，取消回到 `missing` 或原来的 `ready`。已安装但远程存在兼容新版本时为
`update_available`；文件损坏或健康检查失败时为 `damaged`。

状态事件至少包含：能力 ID、显示名、当前版本、目标版本、阶段、已下载字节、总字节、百分比、
错误码、可重试标记和队列位置。

## 启动与交互

### 启动检查

主窗口完成加载后延迟执行 manifest 检查，不阻塞首屏。成功检查时间写入本地状态，24 小时内不
重复请求。断网或仓库不可达时不弹选择窗口，不影响启动。

当 manifest 中存在当前平台可安装、尚未安装的能力时，展示“可选功能资源”弹窗：

- 列出功能用途、下载大小和预估磁盘占用；
- 所有大体积组件默认不勾选；
- 用户可选择“后台安装所选组件”或“稍后”；
- “稍后”在相同 manifest 版本下进入 7 天冷却；
- 用户可关闭启动提醒，功能入口和设置页仍保留安装入口。

### 后台进度

用户确认后关闭选择弹窗，组件进入串行队列。右上角显示可收起的持久进度卡片，包含当前组件、
阶段、百分比、字节进度、队列位置、取消和“查看详情”。完成或失败后显示结果，点击详情进入
设置「完整性」。

如果用户在队列运行时主动使用另一个尚未安装的功能，对应组件提升到队首，但不强制中断正在
校验或激活的组件。

### 功能入口

- 深度处理：添加或选中深度节点时展示状态；执行任务前确保“本地深度处理”能力就绪。
- Office：打开 DOCX、XLSX、PPT/PPTX 时展示内联安装状态；就绪后自动重试本次预览。

## 设置「完整性」页

新增“可选功能组件”区域，统一展示：

- 未安装、排队、下载中、已安装、有更新、已损坏和失败状态；
- 当前版本、最新兼容版本、下载大小和磁盘占用；
- 安装、更新、修复、取消和卸载操作；
- 每项组件的自动更新开关；
- 上次检查时间和手动“检查更新”入口。

自动更新只针对已经安装且用户开启自动更新的组件。检查更新可以静默执行；普通更新只显示设置
入口徽标，安全或应用兼容性更新才允许重新展示明确提示。

## 能力包边界

### 本地深度处理

用户看到一个“本地深度处理”能力，内部由两个制品组成：

1. 与平台和架构匹配的 ONNX Native Runtime；
2. 平台无关的 Depth Anything V2 Small INT8 模型。

第一阶段先保留 `@huggingface/transformers` Node 路径，但在 electron-builder 产物中排除
`onnxruntime-web`，并在 `afterPack` 只保留目标平台和架构的 `onnxruntime-node/bin`。该裁剪必须
有产物测试证明 macOS 包不含 Linux/Windows 库，Windows 包不含 macOS/Linux 库。

第二阶段把推理 Runtime 做成平台制品。长期优先直接使用 `onnxruntime-node` 和本项目预处理/
后处理，避免为了单一模型携带完整 Transformers 通用框架。设置页把 Runtime 与模型的字节进度
合并成一个能力进度。

### 离线 Office 预览

基础包保留轻量 Office Viewer 加载器和文件读取安全校验。Worker、WASM、字体、DrawIO/CAD 等
静态资源组成版本化归档，安装到 `{userData}/optional-capabilities/office-viewer/<version>/`。
renderer 通过受限的 `safe-file://` 或专用只读协议访问激活目录。

构建制品时使用明确 allowlist，避免整包复制未使用格式；同一字体、WASM 和 Worker 只保留一份。
能力健康检查至少验证 DOCX、XLSX、PPTX 所需入口和文件哈希。

### Computer Use（本轮不实施）

Computer Use 明确排除在本轮代码、制品、上传和验收范围之外。其 TypeScript 控制层、Native Host、
独立 Node Runtime 和 Playwright MCP 均保持现有实现与打包方式；后续若要可选能力化，必须另行设计、
签名并验收，不能复用本轮 Office/深度已落地结论。

## 远程制品与清单

继续使用现有 Spark MinIO artifact repository。每个制品必须声明：

- 稳定 artifact ID、类型和版本；
- `platform`、`arch`；
- 下载 URL、压缩格式、大小和 SHA-256；
- 能力 ID、应用兼容范围和安全更新级别；
- 包内 manifest、逐文件 SHA-256 和健康检查入口。

上传顺序固定为：生成可重复归档 → 本地验证 → 上传版本化对象 → 从公网地址回读并校验大小和
SHA-256 → 发布 staging manifest → 审计 → 原子替换正式 manifest。凭据只通过环境变量进入发布
进程，不写入仓库、shell 历史、文档或测试快照。

## 安装、更新与回滚

- 下载写入 staging，并支持基于临时文件继续或安全重试；
- 归档 SHA-256、包内 manifest、平台/架构和健康检查全部通过后才更新 `active.json`；
- 更新失败继续使用旧版本；
- 被运行中任务占用的组件不原地替换，等待任务结束后激活；
- 卸载只删除非激活旧版本，卸载当前版本前先停止相关任务并二次确认；
- 应用升级不删除位于 `userData` 的能力包，新应用只激活声明兼容的版本。

## 安全约束

- 只接受 HTTPS 公网资源地址和允许的 Spark 资源域；
- SHA-256、归档路径穿越、防符号链接逃逸和解压大小上限沿用现有 tarball installer；
- 可执行制品必须匹配当前平台和架构；
- macOS 可执行制品需要独立 Developer ID 签名和公证，Windows 需要 Authenticode 与时间戳；
- Computer Use Native Host 继续执行现有 app/host 同身份、hash、协议和 handshake 门禁；
- renderer 不能获得 MinIO 凭据或任意文件系统读取能力。

## 测试与验收

### 单元和集成测试

- 能力聚合、平台选择、版本比较和状态机；
- 启动提示冷却、默认不勾选和关闭提醒；
- 下载队列、提升优先级、取消、失败重试和原子回滚；
- IPC 状态与设置页、右上角进度卡片一致；
- Office、深度在缺失、安装中、就绪、损坏状态下的功能入口行为；
- ONNX 目标平台裁剪产物检查；
- 三类远程归档的逐文件完整性和健康检查。

### 产物验收

- macOS arm64/x64、Windows x64 安装包均不包含 `onnxruntime-web`；
- 每个平台只包含目标 ONNX Runtime，或在 Runtime 完全远程化后不包含 ONNX Native Runtime；
- 基础包不包含 Office 大型 Worker/WASM/字体资源；
- Computer Use 维持原打包边界，本轮不对其体积或安装方式作验收承诺；
- Office 与深度两项能力可以从干净用户目录安装、立即使用、更新、失败回滚和卸载；
- 公网下载对象与正式 manifest 的 size/SHA-256 完全一致；
- 最终记录各平台安装包、首次组件下载量和安装后磁盘占用的前后对比。

## 分阶段交付

1. ONNX 产物精准裁剪，验证安装包体积回落。
2. 通用可选能力管理器、协议、启动选择弹窗、右上角进度和设置页。
3. Office 静态资源制品化、上传和按需加载。
4. 深度 Runtime 制品化，与现有模型制品组成统一能力。
5. macOS arm64 打包、安装、更新、回滚、MinIO 公网回读和体积审计；其他可信平台制品由对应 runner 后续生成。
6. Computer Use 可选能力化延期，且不影响本轮 Office/深度交付。
