# 画布普通资产节点内联改名设计

> 状态: 待开发 | 最后核对: 2026-07-17

## 背景与目标

画布中的普通资产节点缺少统一、直接的节点名称修改入口。当前标题编辑能力分散在部分内容编辑器或检查器中：文本节点能够在特定编辑形态下修改标题，分镜脚本等特殊编辑分支缺少标题输入，图片节点的编辑入口又受到类型条件限制。底部浮动工具栏虽然始终展示节点名称，但目前只是静态文本。

本次改造把底部浮动工具栏的节点名称统一为内联改名入口，让文本、Prompt、剧本、分镜、图片、视频、音频、组及人物等普通内容节点都能在同一位置修改名称。

## 交互设计

- 普通内容节点打开底部编辑器后，点击工具栏左侧节点名称进入编辑状态。
- 编辑状态使用单行输入框，并自动聚焦、选中当前完整名称。
- 按 Enter 保存；输入框失焦时同样保存。
- 按 Esc 取消本次修改，恢复进入编辑前的名称且不发起保存。
- 输入只包含空白字符时按 `null` 保存，工具栏和节点卡片恢复该节点类型的默认标题。
- 输入内容首尾空白在保存前去除；名称中间的空格保留。
- 名称没有实际变化时退出编辑状态，不发起保存。
- 保存期间阻止重复提交，并保持输入框不可再次提交。
- 保存失败时保留用户输入和编辑状态，通过现有消息组件展示错误，用户可以继续修改并重试。

## 覆盖范围

统一改名入口覆盖所有通过普通内容编辑器打开的节点，包括：

- 文本与 Prompt 节点。
- 剧本、分镜脚本等由文本节点子类型或内容格式派生的节点。
- 图片、视频与音频节点。
- 人物、场景等由资产类型或节点数据标识的普通内容节点。
- 节点组。

操作节点不切换到本次内联控件，继续沿用现有“节点设置”中的名称编辑能力，避免同时存在两个任务节点改名入口。画板名称、资源库资产名称和任务标题不属于本次范围。

## 组件与数据流

新增一个小型、受控的工具栏标题编辑组件，负责编辑态、草稿、键盘交互、保存中状态和错误后的草稿保留。`CanvasFloatingNodeToolbar` 负责决定普通节点使用该组件，操作节点继续渲染现有静态操作标题与状态。

工作区向工具栏传入改名回调。保存链路为：

1. 用户点击标题并编辑草稿。
2. 组件对草稿执行去除首尾空白和空值归一化。
3. 工具栏回调调用现有 `patchNodes([node.id], { title })`。
4. 画布快照更新后，节点卡片、底部工具栏和其他读取 `node.title` 的界面共同回显新名称。

不新增 IPC、数据库字段或资产协议。普通节点的标题仍以 `CanvasNode.title` 为唯一持久化来源，不同步修改资源库资产本身的标题。

## 状态同步与错误处理

- 未编辑时，外部画布快照中的标题变化应立即更新工具栏展示。
- 正在编辑时，不用外部快照覆盖用户尚未提交的草稿。
- 节点切换时重置编辑状态和草稿，避免把前一个节点名称提交到新节点。
- 保存成功后退出编辑状态，以最新节点标题为展示值。
- 保存失败时不退出编辑状态；错误消息包含底层异常信息，无法识别异常时使用“保存节点名称失败”。
- 组件卸载或节点被删除后，不再尝试更新已卸载组件状态。

## 样式与可访问性

- 输入框沿用工具栏高度和现有暗色主题，不改变工具栏整体布局高度。
- 标题过长时，展示态继续截断；进入编辑态后输入框提供足够的最小宽度，并受工具栏可用空间限制。
- 展示态标题使用按钮语义，可通过键盘聚焦并按 Enter 或 Space 进入编辑。
- 输入框提供明确的 `aria-label`，保存失败通过现有可感知消息提示。

## 验证方案

- 组件测试覆盖点击和键盘进入编辑、自动聚焦、Enter 保存、失焦保存与 Esc 取消。
- 覆盖首尾空白裁剪、空标题保存为 `null`、未变化不保存和重复提交保护。
- 覆盖保存失败后保留草稿与重试成功。
- 工具栏测试覆盖文本、分镜、图片、视频、音频、人物和组节点均出现统一改名入口。
- 回归测试确认操作节点仍使用现有节点设置，不出现第二个内联改名入口。
- 执行相关 Vitest、桌面端 TypeScript 检查和目标文件 diff 审查。

## 非目标

- 不支持批量改名、名称唯一性校验或节点别名。
- 不修改节点正文、媒体文件名、资源库资产名称或任务参数。
- 不重构普通节点现有内容编辑器；已有标题输入可暂时保留，但顶部工具栏作为统一入口。
- 不改变节点默认标题的生成规则。
