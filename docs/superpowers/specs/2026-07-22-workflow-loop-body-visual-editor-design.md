# 工作流循环体子图可视化编辑器设计

> 状态: 已落地 | 最后核对: 2026-07-31

## 1. 背景

Spark Agent 的工作流运行时已经支持 `loop` 节点：循环节点通过 `config.body` 保存一张独立 `WorkflowGraph`，每轮递归执行该子图，并根据 `breakCondition` 决定退出或继续。

当前桌面端工作流编辑器只提供“循环体 JSON”文本框。用户必须手写 `nodes`、`edges`、坐标、条件和节点配置，无法使用工作流主图已有的节点面板、拖拽、连线、条件边和 Inspector。这与可视化编排的产品定位不一致，也容易产生非法节点 ID、外层回边和嵌套循环等配置错误。

本功能只涉及 `WorkflowView` 中的工作流编辑器和工作流图适配逻辑，不接入、复用或修改产品的“无限画布”模块。

## 2. 目标

1. 用户可以从循环节点进入专属的循环体子图编辑画布。
2. 循环体编辑体验与工作流主图一致：添加、拖拽、复制、删除、连线、条件边、方向切换、缩放、小地图和右侧 Inspector 均可使用。
3. 子图修改立即进入页面草稿和脏状态；返回父图或保存时写回当前循环节点的 `config.body`，最终仍由工作流页面的总“保存”按钮统一持久化。
4. 现有手写 `body` JSON 的工作流无需迁移即可打开和编辑。
5. 编辑器主动阻止运行时 v1 不支持的嵌套循环，并在保存前发现节点 ID 冲突等问题。
6. 循环体可视化能力不改变 `WorkflowGraph`、`WorkflowNodeConfig.body` 或运行时执行协议。

## 3. 非目标

- 不修改无限画布、画布项目、媒体节点或 Canvas operation。
- 不支持循环体内嵌套另一个 `loop`；运行时 v1 仍保持现有限制。
- 不新增数据库表、IPC 通道或图协议版本。
- 不在本期实现跨层连线，例如从父图节点直接连到循环体内部节点。
- 不改变循环达到最大轮数后的运行时语义。
- 不把循环体单独保存为可复用工作流模板。

## 4. 方案比较

### 4.1 方案 A：工作流画布下钻编辑（采用）

用户从循环节点 Inspector 点击“编辑循环体”，当前 `WorkflowView` 的 React Flow 工作区切换为该循环节点的 `body` 子图。顶部显示面包屑和返回按钮，返回后恢复父工作流主图。

优点：完整复用工作流编辑器能力；复杂子图有足够空间；用户心智与编辑普通工作流一致；协议无需变化。

缺点：需要在同一页面维护父图和当前编辑图两层状态，并确保选择态、脏状态和方向正确切换。

### 4.2 方案 B：弹窗或抽屉编辑

在循环节点上打开包含 React Flow 的大弹窗或抽屉。

优点：父图仍在背景中，状态隔离直观。

缺点：节点面板、Inspector 和画布同时出现时空间不足；键盘快捷键、右键菜单和缩放体验较差；移动窗口尺寸下尤其拥挤。

### 4.3 方案 C：主图内嵌套分组容器

把 loop 显示成可展开的父节点，循环体节点直接位于父节点内部。

优点：父子关系最直观。

缺点：React Flow 嵌套坐标、拖拽边界、折叠、缩放、连线和序列化复杂；容易让用户误以为父图可以直接连入循环体内部；本期收益不足以覆盖风险。

## 5. 用户体验设计

### 5.1 进入循环体

选中 `loop` 节点后，Inspector 的循环配置区域显示：

- 循环体摘要：节点数、连线数、条件边数、编排方向。
- 主操作：“编辑循环体”。
- 次操作：“重置为默认循环体”，需要二次确认。
- “高级 JSON”折叠区：保留原始 JSON 编辑能力，用于导入和排错；默认收起。

点击“编辑循环体”后进入循环体子图编辑模式。

### 5.2 循环体编辑模式

页面顶部从普通工作流工具栏切换为：

```text
返回主工作流  /  工作流名称  ›  循环节点名称  ›  循环体
```

同时保留：

- 节点面板；
- 横向/纵向切换；
- React Flow 缩放、Fit View、小地图；
- 右键新增、复制和删除；
- 节点 Inspector；
- 连线条件 Inspector；
- 页面总“保存”按钮。

循环体节点面板中的 `loop` 入口显示为禁用状态，并提供提示：“运行时 v1 不支持嵌套循环”。通过节点类型切换也不能把循环体节点改成 `loop`。

### 5.3 返回父工作流

点击“返回主工作流”时：

1. 把当前 React Flow 节点、边和方向转换为 `WorkflowGraph`；
2. 校验子图；
3. 将结果写回父图目标循环节点的 `config.body`；
4. 恢复父图节点、边、方向和之前的 loop 选中态；
5. 不调用 IPC 保存，页面仍显示未保存状态。

如果子图存在阻断错误，不允许返回，并在工具栏或 Inspector 显示可定位的错误。非阻断提示不阻止返回。

### 5.4 保存与离开

- 在循环体模式点击页面总“保存”时，先把当前子图提交回父图，再调用现有 `workflow:update` 保存完整工作流。
- `Cmd/Ctrl + S` 与保存按钮行为一致。
- 页面脏状态基于包含最新 `config.body` 的完整父图快照计算。
- 用户离开工作流页面、切换工作流或关闭应用时，继续使用现有未保存更改确认机制。

## 6. 状态与组件架构

### 6.1 编辑范围模型

新增显式编辑范围：

```ts
type WorkflowEditorScope =
  | { kind: 'root' }
  | {
      kind: 'loop-body'
      loopNodeId: string
      parentSelection: { nodeId: string | null; edgeId: string | null }
    }
```

运行时仅允许一层 `loop-body`，因此不需要递归面包屑栈。

### 6.2 父图草稿

主工作流完整草稿必须始终保留，不能在进入子图后丢失。推荐拆分为：

- `rootGraphDraft`：主图的 React Flow 节点、边和方向；
- `editorGraph`：当前画布正在显示的节点、边和方向；
- `editorScope`：当前是根图还是某个 loop body。

在根图模式，`editorGraph` 与根图同步；进入循环体时冻结根图快照并用 `config.body` 初始化当前画布；提交子图后更新 `rootGraphDraft` 中对应 loop 节点。

实现中应抽出纯函数，避免把父子图转换继续堆入已经较大的 `WorkflowView.tsx`：

- `openLoopBodyEditor(...)`
- `commitLoopBodyEditor(...)`
- `validateLoopBodyGraph(...)`
- `summarizeLoopBodyGraph(...)`
- `createWorkflowNodeIdForScope(...)`

建议放入新的 `workflow/loop-body-editor.ts`，React 展示组件放入 `workflow/WorkflowLoopBodyToolbar.tsx` 和 `workflow/WorkflowLoopBodySummary.tsx`。

### 6.3 协议兼容

继续使用现有结构：

```ts
interface WorkflowNodeConfig {
  body?: WorkflowGraph
}
```

可视化编辑器只负责 `WorkflowGraph ↔ React Flow nodes/edges` 转换。数据库、导入导出、IPC 和运行时无需迁移。

## 7. 校验与错误处理

进入、返回和保存时统一校验：

1. `body.nodes` 和 `body.edges` 必须是数组。
2. 循环体不能为空；空体允许处于编辑中，但保存前必须补至少一个节点。
3. 循环体内不能出现 `loop` 节点。
4. 循环体节点 ID 不能重复。
5. 循环体节点 ID 不能与父图节点 ID 冲突。
6. 所有边的端点必须存在于循环体中。
7. 条件边的 key 不能为空。
8. 循环体外层应为可拓扑排序的无环图；发现环时阻止保存并提示相关节点。

非法旧 JSON 不应导致整个工作流页面崩溃。编辑器显示错误摘要，并允许用户在“高级 JSON”中修正或重置默认循环体。

## 8. 节点 ID 策略

循环体新增节点使用带 loop 作用域的稳定前缀：

```text
{loopNodeId}__{kind}-{timestamp/random}
```

创建前同时检查父图和循环体 ID 集合。复制节点也走同一生成器，避免运行时的 `workflow_loop_node_id_collision`。

旧工作流 ID 保持不变，不做自动重命名。

## 9. 高级 JSON 双向同步

高级 JSON 仍是编辑当前 loop `body` 的能力，而不是第二份独立数据：

- JSON 解析成功且结构合法时，立即刷新子图摘要；如果当前正在循环体画布中，则要求用户确认后重新载入画布，避免覆盖未提交的可视化编辑。
- JSON 解析失败时保留用户输入并显示错误，不写入 `config.body`。
- 从可视化画布返回后，JSON 展示最新格式化的 body。

## 10. 文档示例中的 Skill、Tool、MCP

“编码功能任务 · 全节点能力演示”中的三个并行节点是可选扩展，不是编码工作流的必选步骤：

- `skill`：固定“使用什么方法论”，例如验证完成声明是否有新鲜证据。
- `tool`：限制“允许用什么手段”，例如只允许 Read、Grep、Glob、Bash 做独立审计。
- `mcp`：连接应用之外的浏览器、官方文档、Issue 平台、知识库或远程验证服务。

官网文档应明确：普通本地编码可删除 MCP；没有独立审计需求时可删除 Tool；Skill 仅在团队有对应规范时启用。示例保留三者是为了展示工作流节点能力。

## 11. 测试设计

### 11.1 纯函数单元测试

- 从父图打开已有循环体并正确恢复方向。
- 缺失 body 时使用默认子图；显式空 body 原样打开并显示保存前校验错误。
- 子图提交后只更新目标 loop 节点。
- 父图其他节点、边和位置保持不变。
- 新增、复制节点 ID 不与父图冲突。
- 嵌套 loop、重复 ID、悬空边和有向环分别返回明确错误。
- 主图和子图在 `graphToReactFlow` / `reactFlowToGraph` 往返后保持条件边和方向。

### 11.2 React 交互测试

- loop Inspector 显示摘要和“编辑循环体”。
- 点击进入后显示面包屑、返回按钮和 body 节点。
- 循环体节点面板禁用 loop。
- 在子图中新增、移动、复制、删除节点并连线后，返回父图仍保留修改。
- 子图节点和边 Inspector 可编辑。
- 高级 JSON 与摘要双向同步。
- 子图非法时返回和保存被阻止，并显示错误。
- `Cmd/Ctrl + S` 在子图模式会提交 body 并保存父工作流。
- 未保存时离开仍触发现有确认框。

### 11.3 回归测试

- 普通非 loop 工作流编辑、保存、导入和导出保持不变。
- 现有 loop JSON 工作流可直接打开并保存。
- 工作流运行时 loop 测试继续通过。
- 横向和纵向主图、循环体均可独立保存方向。

## 12. 验收标准

1. 用户不手写 JSON 即可完成循环体节点和连线编排。
2. 主图与循环体之间可以稳定往返，修改不会丢失或污染其他 loop 节点。
3. 保存、重载和导入导出后循环体保持一致。
4. 条件边、节点配置、方向和坐标完整保留。
5. 编辑器不能创建嵌套 loop，能在保存前发现 ID 冲突、悬空边和环。
6. 现有工作流协议、数据库和运行时无需迁移。
7. 官网文档明确 Skill、Tool、MCP 是可选审计扩展及各自用途。
8. 相关单元测试、React 交互测试、desktop typecheck 和 production build 通过。

## 13. 风险与缓解

- **父子图状态覆盖**：所有进入、返回、保存流程通过纯函数和单一提交入口处理，不在多个组件中分别拼接 body。
- **WorkflowView 继续膨胀**：新增状态转换与 UI 拆到独立模块，主页面只负责协调。
- **旧 JSON 非法**：容错加载并提供高级 JSON 修复和重置入口，不让页面崩溃。
- **保存时仍停留子图**：保存前强制提交当前 editorGraph，再序列化 rootGraphDraft。
- **用户误以为循环体可连父图**：子图画布仅展示 body，面包屑和循环边界说明持续可见。
