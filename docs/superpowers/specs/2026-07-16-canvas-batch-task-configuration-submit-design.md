# 画布任务节点批量配置与提交设计

> 状态: 已落地 | 最后核对: 2026-07-17

## 背景

当前画布支持单节点任务配置和部分右键任务操作，但缺少以下连续工作流：

- 单个任务节点无法直接通过右键提交运行。
- 多选任务节点后无法统一设置模型和参数。
- 不同任务类型混选时缺少可理解、可定位的批量配置界面。
- 参数草稿保存与任务提交没有明确分离的批量动作。
- 批量运行缺少提交前总览、整批校验和可恢复的确认偏好。

本设计扩展现有单节点右键菜单和多选右键菜单，不新增平行的画布操作体系。

## 目标

- 单个任务节点支持右键直接提交运行。
- 多选任务节点支持批量配置参数和批量提交运行。
- 同类型节点支持共享参数编辑，不同类型节点支持按类型分组的列表式配置。
- “保存参数草稿”只保存节点配置，不创建任务、不进入运行队列。
- 批量提交默认打开确认面板，并支持用户级“下次不再确认”偏好。
- 任一节点不可运行时整批阻止，强制打开面板并定位问题节点。
- 批量编辑、校验和提交逻辑拆分为独立模块，避免继续扩大画布工作区组件。

## 非目标

- 不新增 DAG 调度器或改变现有节点依赖执行规则。
- 不改变 Provider 请求格式、模型能力协议或现有单节点任务语义。
- 不承诺后端未提供的事务型任务创建和运行回滚。
- 不把普通画布节点转换为任务节点。
- 不让批量确认偏好影响单节点右键运行。

## 已确认决策

1. 批量运行默认先打开确认面板。
2. 确认面板提供“下次不再确认，校验通过后直接提交”复选框。
3. 该偏好为全局用户级，对该用户的所有项目生效。
4. 设置中提供“恢复批量提交确认”入口。
5. 即使用户跳过确认，任一节点校验失败时仍整批阻止并强制打开面板。
6. 批量提交前的参数修改先写回节点草稿，再创建运行任务。
7. 单独保存只保存批量参数草稿，绝不提交运行。
8. 采用双栏审阅面板，不采用分步向导或参数矩阵作为主交互。

## 方案比较

### 方案 A：双栏审阅面板

左侧展示按类型分组的节点和校验状态，右侧展示类型共享参数或单节点覆盖参数。配置完成后在同一面板切换到提交确认状态。

优点是节点、类型、参数和错误始终处于同一上下文，适合同类型和混合类型批次，也便于定位问题。缺点是需要清晰处理共享值、混合值和单节点覆盖。

### 方案 B：分步向导

按选择、配置、确认依次推进。首次使用容易理解，但频繁批量操作步骤多，跨类型对照和错误修正效率较低。

### 方案 C：参数矩阵

使用行列式表格同时编辑节点参数。大量同构节点时扫描较快，但复杂 Schema 和混合任务类型会产生大量空列、横向滚动和定制单元格。

采用方案 A。参数矩阵可以作为未来大规模同构任务的增强视图，但不进入本期范围。

## 入口与菜单

### 单节点右键

任务节点右键菜单新增“提交运行”：

1. 读取节点当前生效草稿。
2. 执行单节点运行校验。
3. 校验通过后调用现有单节点提交链路。
4. 校验失败时打开现有节点配置入口并定位首个错误。

该动作不读取批量提交确认偏好，也不打开批量面板。

### 多选右键

当选区全部为任务节点时，新增：

- “批量配置参数…”：打开批量配置面板。
- “批量提交运行”：对当前选择快照执行整批校验，并按确认偏好进入确认态或直接提交。

当任务节点与普通画布节点混选时，批量任务操作禁用，并通过菜单说明不可用原因。不同任务类型的任务节点允许混选。

右键菜单不单独提供“保存参数草稿”。用户进入面板并产生编辑内容后，面板底部提供该动作，避免在没有新内容时出现语义不清的保存项。

## 双栏面板

### 面板头部

显示选中任务数量、任务类型数量、就绪数量、异常数量和关闭入口。

面板打开时固定节点选择快照。用户随后改变画布选区不会静默改变当前批次。

### 左栏

- 按任务类型分组展示节点。
- 分组和节点均展示就绪、异常、已修改等状态。
- 存在校验问题时，异常节点优先展示，并自动选中首个问题节点。
- 支持按节点名称搜索。
- 大列表使用虚拟滚动。

### 右栏

右栏提供“类型共享参数”和“节点覆盖”两个层级：

- 选择类型分组时编辑该类型的共享模型和参数。
- 选择具体节点时查看有效配置，并设置该节点的覆盖值。
- 共享字段值相同则显示该值，不同则显示“多个值”。
- 只有用户明确触碰的共享字段才写入选中节点；未触碰字段保留各节点原值。
- 模型变化继续使用现有模型能力、Schema、默认值和参数兼容规则，不在批量组件内添加 Provider 特例。

同类型批次默认选中类型共享参数。混合类型批次按类型分组，右侧始终渲染当前类型对应的配置表单，不合并不兼容字段。

### 底部动作

- “保存参数草稿”：写回所有已修改节点，不运行。
- “检查并提交”：先写回草稿，再执行整批运行校验。
- 存在运行校验错误时，提交按钮展示错误状态并返回配置态。

关闭含未保存编辑的面板时，提示保存草稿、放弃更改或继续编辑。已通过“检查并提交”写回的草稿不再视为未保存。

## 保存语义

面板编辑首先保存在独立的批量编辑会话中，不在每次输入时直接改动画布节点。

点击“保存参数草稿”时：

1. 根据节点基础草稿、类型共享补丁和单节点覆盖计算最终草稿。
2. 只写入用户明确修改的字段。
3. 将所有节点更新作为一次画布历史操作提交，以便一次撤销。
4. 允许保存缺少必填运行参数的未完成草稿。
5. 不调用任何任务创建、队列或 Provider 接口。

点击“检查并提交”时执行相同的草稿写回。即使后续运行校验或网络提交失败，用户本次参数修改仍保留在节点中。

## 校验与确认

校验分为两级：

- 草稿校验：保证草稿结构可序列化、字段值可写回。该级别不要求任务立即可运行。
- 运行校验：检查节点类型、模型可用性、必填参数、输入资源、现有依赖约束和提交协议要求。

批量提交执行以下流程：

1. 捕获节点 ID、节点修订信息和有效配置。
2. 写回本次参数草稿。
3. 对所有节点执行运行校验。
4. 任一节点失败时不创建任何任务，打开配置态并定位问题。
5. 全部通过时生成不可变的提交快照。
6. 若全局偏好要求确认，切换到确认态；否则直接进入提交准备。
7. 真正发出请求前再次检查节点是否被删除、外部修改或失效。
8. 二次校验通过后提交批次。

确认态展示：

- 任务总数和类型总数。
- 按类型分组的节点、模型和关键参数摘要。
- 校验通过状态。
- “下次不再确认，校验通过后直接提交”复选框。
- “返回修改”和“确认提交 N 个任务”动作。

确认复选框默认不选中。用户点击确认提交时写入全局用户偏好；取消或返回修改不改变偏好。设置页提供恢复确认的开关。

跳过确认只跳过合法批次的人工总览，不跳过任一级校验。

## 提交与失败处理

每次批量提交生成一个 `batchId`，用于关联节点和提交结果。

“整批阻止”保证提交前校验阶段不产生部分任务。如果后端提供事务型批量创建接口，应优先使用该接口；如果现有接口只能逐节点创建，则采用受控并发提交，并明确处理网络阶段的部分成功：

- 已成功创建或运行的任务不回滚。
- 失败节点保留错误原因和提交快照。
- 结果面板按成功、失败、未提交汇总。
- 提供“仅重试失败节点”动作，重试前重新校验失败节点。
- 重试继续关联原 `batchId`，并为每个节点使用稳定的幂等键，避免重复创建。

不以 UI 文案暗示后端不存在的全有或全无事务保证。

## 状态模型

批量编辑会话至少包含：

- 选择快照：节点 ID、类型和打开面板时的修订信息。
- 基础草稿：打开面板时每个节点的模型和参数。
- 类型共享补丁：按任务类型记录用户触碰的字段和值。
- 节点覆盖补丁：记录单节点差异。
- 脏字段集合：区分“多个值但未修改”和“用户明确覆盖”。
- 校验报告：按节点和字段记录严重级别、错误码与可读说明。
- 提交快照：校验通过后冻结的有效参数和摘要。
- 提交结果：按节点记录等待、成功、失败和可重试状态。

全局偏好独立于画布项目数据存储，例如 `skipCanvasBatchSubmitConfirmation`。偏好读取失败时采用安全默认值，即继续展示确认面板。

## 模块边界

沿用现有菜单体系并新增聚焦模块：

- `CanvasNode.tsx`：只接入单节点“提交运行”菜单动作。
- `CanvasContextMenu.tsx` 与 `canvasContextMenuModel.ts`：展示多选菜单项、可用状态和禁用原因。
- 新批量面板组件：负责配置态、确认态和结果态的展示，不拥有底层提交规则。
- 新批量编辑会话模型：负责分组、混合值、脏字段、补丁合并和选择快照。
- 新批量校验协调器：复用现有单节点运行校验，汇总为节点和字段级报告。
- 新批量提交协调器：负责二次校验、`batchId`、受控并发、幂等键和结果汇总。
- 新用户偏好适配层：读取、写入和恢复批量确认偏好。
- `CanvasWorkspaceView.tsx`：仅保留必要的面板挂载和已有画布状态接线，不加入大段批量业务逻辑。

若现有参数表单可以通过受控草稿接口复用，则抽取共享表单壳层；不复制模型选择、Schema 字段渲染和参数兼容逻辑。

任何超过 3000 行的现有代码文件都不继续承载新的完整功能模块。

## 边界情况

- 节点在面板打开后被删除：标记为过期，整批阻止并允许从批次移除。
- 节点被其他入口修改：比较修订信息，要求重新载入或重新校验，不用旧快照覆盖新值。
- 模型目录加载失败：允许保留草稿，但运行校验失败并展示可恢复错误。
- 节点无可用模型：允许保存，禁止提交。
- 批量选择为空：关闭面板或返回画布，不保留空会话。
- 数量超过后端限制：在校验阶段按后端能力返回明确错误，不在前端硬编码猜测上限。
- 用户偏好读取失败：展示确认面板。
- 用户偏好写入失败：本次仍可提交，但提示偏好未保存，下次仍确认。
- 关闭结果态：任务继续由现有任务系统运行，不与面板生命周期绑定。

## 可访问性与性能

- 面板、分组、错误列表、标签页和底部动作支持键盘导航。
- 错误提示关联到具体字段，并提供文本说明，不只依赖颜色。
- 确认按钮包含准确任务数量。
- 大列表采用虚拟滚动，搜索和分组计算使用纯模型层。
- 逐节点提交使用受控并发，避免瞬时创建大量 IPC 或网络请求。

## 测试策略

### 纯模型测试

- 同类型字段值一致与“多个值”计算。
- 共享补丁只覆盖脏字段。
- 节点覆盖优先于类型共享补丁。
- 混合类型不合并不兼容字段。
- 保存草稿允许缺少运行必填项。
- 运行校验按节点和字段聚合。
- 选择快照过期检测。
- `batchId`、幂等键和失败重试集合计算。

### 菜单与组件测试

- 单任务节点显示“提交运行”。
- 全任务节点多选显示批量动作。
- 普通节点混选时动作禁用且原因正确。
- 配置态、确认态、结果态切换。
- 异常节点置顶并聚焦首个错误。
- 保存草稿不调用提交接口。
- “检查并提交”先保存草稿再校验。
- 确认复选框默认未选中，返回修改不写偏好。
- 全局偏好启用后合法批次跳过确认。
- 全局偏好启用后异常批次仍强制打开面板。
- 键盘导航和字段错误关联。

### 集成测试

- 多节点草稿写回形成一次撤销记录。
- 二次校验检测节点删除或外部修改。
- 合法批次生成同一 `batchId`。
- 网络阶段部分失败时成功项保留、失败项可单独重试。
- 偏好跨项目生效，并能从设置恢复。
- 现有单节点提交、参数裁剪、模型兼容和任务结果链路保持通过。

## 验收标准

1. 用户可从单任务节点右键直接运行。
2. 用户可多选同类型或不同类型任务节点并打开批量配置面板。
3. 共享参数不会覆盖未触碰字段，单节点覆盖结果可预览。
4. “保存参数草稿”不会创建任何任务。
5. 批量提交默认显示确认态。
6. 用户可选择全局跳过后续合法批次的确认，并从设置恢复。
7. 任一节点不可运行时整批阻止并定位问题，不受跳过确认偏好影响。
8. 节点状态过期时不会按旧快照提交。
9. 部分网络失败结果可见且可只重试失败节点。
10. 新逻辑以独立模块实现，不继续显著扩大现有大型画布组件。

## 影响与风险

主要风险位于节点草稿合并、现有单节点校验复用、画布历史记录和提交链路。实现时优先以纯函数和现有单节点能力组合批量行为，避免复制业务规则。

当前环境未暴露 GitNexus MCP 工具。按仓库降级规则，实施前使用源码阅读和 `rg` 核对直接调用点，完成后使用相关测试、`git diff` 和调用点复查确认影响范围。

工作区当前存在与画布媒体任务校验相关的未提交修改。实施时保留这些修改，逐文件核对重叠区域，不回退或覆盖用户已有工作。
