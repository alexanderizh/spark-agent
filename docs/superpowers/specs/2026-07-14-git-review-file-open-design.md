# Git 审查文件打开设计

> 状态: 已落地 | 最后核对: 2026-07-14

## 背景

Git 审查侧面板当前支持展开 diff 和通过文件树定位文件，但无法直接把变更文件交给系统默认应用或指定编辑器打开。会话文件卡片已经通过 `SessionFileOpenPicker` 提供了统一的打开方式菜单。

## 目标

- 在变更列表和文件树的文件行都提供紧凑的“打开 + 选择应用”入口。
- 主按钮使用系统默认应用打开；下拉菜单继续提供默认应用、文件夹定位、文档应用、编辑器和终端。
- 保留原有整行点击展开或选择 diff 的行为。
- 已删除文件不显示打开入口。
- 使用当前 Git 审查 workspace 的根目录解析相对路径，避免会话 worktree 与全局当前 workspace 不一致时打开错误文件。

## 方案比较

1. **复用 `SessionFileOpenPicker`（采用）**：交互和会话内容一致，只需给审查面板传入正确的绝对路径；改动范围最小。
2. 在审查面板复制一套打开菜单：布局可完全定制，但会重复工具探测、错误处理和菜单定位逻辑。
3. 让文件名本身双击打开：视觉最轻，但与单击选择/展开 diff 的行为冲突，也不能自然承载“选择应用”。

## 组件与数据流

`ChatView` 将 `gitWorkspace.rootPath` 传给 `GitReviewPanel`。审查面板把根目录与 Git 返回的相对路径安全拼接为目标路径，然后将该路径交给 `SessionFileOpenPicker`。文件列表和文件树使用同一目标路径规则，删除状态统一隐藏入口。

文件行不嵌套按钮：原有行按钮与打开控件改为同级元素，避免无效 HTML 和键盘交互冲突。打开控件点击不会触发展开或选择操作。

## 错误处理与测试

继续复用 `SessionFileOpenPicker` 的 toast 错误处理。测试覆盖两处入口、根路径解析、删除文件隐藏，以及点击打开控件不触发 diff 展开。
