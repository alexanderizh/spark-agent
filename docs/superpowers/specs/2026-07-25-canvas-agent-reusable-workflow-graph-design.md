# 画布 Agent 可复用工作流图构建设计

> 状态: 已落地 | 最后核对: 2026-07-25

## 目标

让用户在无限画布左侧 Agent 面板中通过自然语言创建可复用的真实画布流程。Agent 不再依赖多次低层节点调用自行记忆连线、坐标和检查步骤，而是提交一份语义化流程图，由程序完成输入占位、节点配置、连线、布局、原子落图和创建后复核。

本能力仅属于无限画布工作流，不涉及应用工作台 Workflow。创建结果默认只存在于当前画布；只有用户明确要求保存时，才调用现有 `canvas_workflow_extract_selection` 或工作流 CRUD 工具写入项目工作流库。

## 节点边界

校验范围是 Agent 本次创建或用户明确指定的“流程子图”，不要求画布上的所有节点都有连线。

- `input`：可替换的输入边界，支持文本、Prompt、空图片、空视频和空音频占位节点。
- `operation`：执行 AI 能力的处理节点，必须具备合法操作类型、必要输入和可运行配置；终点操作通过 `isOutput` 和 `expectedOutputTypes` 声明产物边界。
- `note`：说明、注释或示例节点，允许不连线，不参与流程完整性判定。

流程节点不要求每一个都有入边和出边：输入节点可以没有入边，终点操作可以没有出边，允许存在多个输入、多个输出、分支和汇合。除显式标记为 `note` 外，操作节点必须位于至少一条从输入边界到终点操作的有效路径中。运行时会由终点操作生成真实产物节点，因此不预建无法被运行时回填的空输出卡片。

## Agent 工具

### 统一工具契约与调用可靠性

本次问题并非只存在于工作流工具。所有 `spark_canvas` 工具共用同一条 JSON Schema → MCP Zod → IPC → 渲染端处理链，因此采用统一防线：

- MCP Schema 转换必须保留 `oneOf` / `anyOf`、`const`、嵌套对象、数组约束、数值约束和 `additionalProperties` 语义，不能把复杂节点退化为 `unknown`。
- 渲染端 `executeCanvasTool` 在进入具体 handler 前按原始 JSON Schema 统一校验参数，错误必须包含精确字段路径；无效参数不得触发 workspace 写操作。
- `canvas_describe_tool(toolName)` 提供只读的自描述入口，返回工具说明和精确 `inputSchema`。Agent 字段不确定或校验失败时必须查询契约，禁止通过源码、shell 或解包应用猜测参数。
- IPC 已成功但渲染端结果为 `undefined` 时，MCP 层返回非空完成结果，避免 SDK 映射成无信息的 `completed with no output`。写操作若仍出现空输出，Agent 必须先用只读工具核对状态，避免重复写入。
- 空输出本身不代表画布 detach。只有桥接层明确返回 attach/detach 错误时才能判断连接中断；画布工具调用不得委派给不持有当前画布上下文的子 Agent。

### `canvas_create_reusable_workflow_graph`

输入为语义化节点、依赖引用、输入/输出角色和配置，不要求模型计算真实坐标。工具执行以下步骤：

1. 规范化节点引用并根据依赖生成边。
2. 对需要用户后续提供图片、视频或音频的输入生成空媒体节点。
3. 检查端点、环路、操作输入类型、输入/输出边界和必需配置。
4. 使用从左到右的 DAG 分层布局计算稳定坐标，并避让当前画布已有节点。
5. 通过现有 `applyTemplate` 一次性创建节点、任务和连线。
6. 从新快照提取本次创建子图，再运行一次结果校验。
7. 返回节点 id、连线数量、输入/输出节点、诊断和是否可复用，不返回完整快照。

存在阻断错误时不写入画布。警告不阻止创建，例如一个可选输入尚未指定模型；返回结果必须明确告知 Agent 不得在存在错误时声称流程已完成。

### `canvas_validate_workflow_graph`

只读校验用户指定节点，或默认校验当前选区。它检查：

- 连线端点是否存在，是否存在自连或不支持的环路。
- 输入和输出边界是否与节点类型、操作能力契约一致。
- 非 `note` 操作节点是否位于输入到输出的有效路径中。
- 操作节点是否有 operation、提示词/消息、输入绑定及必要模型参数。
- 空媒体输入是否被正确标记为可替换占位，而不是误判为缺失资产。
- 节点是否严重重叠，流程方向是否明显逆序。

诊断采用 `error | warning | info`，包含代码、节点引用、可读消息和修复建议，便于 Agent 精确调用低层工具修复。

## 布局

布局以流程依赖为准，不按 Agent 提供顺序简单横排：

- 输入节点位于最左层，操作按拓扑深度分层，显式输出位于最右层。
- 同层节点纵向排列；分支保持相邻，汇合节点位于其来源节点的视觉中线附近。
- 使用节点真实或默认尺寸、稳定水平/垂直间距，并将整组移动到当前画布空白区域。
- 用户显式给出的坐标只作为整体锚点，不允许破坏流程层级或造成严重重叠。

布局结果完全确定，同一语义图应产生一致的相对坐标，便于测试和后续提取复用。

## 原子性与修复

规划和预校验均为纯函数，不产生画布副作用。只有通过阻断校验的蓝图才进入 `applyTemplate`。已有模板 API 在一次数据库写入中创建全部节点、任务和边，避免“节点建了一半但连线失败”。

创建后复核若发现实现层异常，工具返回错误诊断和本次创建节点 id，Agent 应调用校验或低层修改工具修复。低层 `canvas_create_*`、`canvas_connect_nodes`、`canvas_update_*` 继续保留，适合对现有流程做局部调整，不作为新建完整流程的首选路径。

## 测试与验收

- 文本输入到文生图输出的单链路完整创建。
- 空图片占位到图生图/图生视频操作的输入类型正确。
- 多输入、分支、汇合和多输出图的边与布局稳定。
- `note` 节点允许独立，流程操作节点断链会报错。
- 缺端点、重复引用、环路、错误输入类型、缺操作配置时拒绝落图。
- 创建后快照中的节点、任务、输入绑定和边均已重映射为真实 id。
- 新子图避让已有节点且无严重重叠。
- Agent 工具注册描述明确优先使用高层工具，并在创建后校验。
- MCP 暴露的工作流节点联合类型包含每个分支的必填字段，不接受猜测字段或额外字段。
- 任一画布工具缺少必填参数时，在 handler 和 workspace action 之前返回带字段路径的校验错误。
- `canvas_describe_tool` 能返回目标工具的完整 Schema，未知工具返回明确错误。
- 渲染端返回 `undefined` 时 MCP 仍产生非空文本和结构化完成结果。
