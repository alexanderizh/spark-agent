# 会话中间活动段自动折叠设计

> 状态: [已落地] | 最后核对: 2026-07-11

## 背景

单轮 Agent 会话可能交替产生多段正文、思考和工具日志。当前运行中会逐条展示已完成的“查看文件”“执行命令”“修改文件”和阶段性思考；只有整轮结束后，顶部“思考和工具日志”总开关才会隐藏这些内容。长任务因此会在正文中间积累大量已完成日志摘要，挤占阅读空间。

本设计采用已确认的方案 B：**下一段正文或新活动开始时，将上一段已完成活动自动折叠为一行摘要**。当前活动保持展开；用户手动展开过的活动段不再被自动折叠。每个活动段独立维护交互状态。

## 术语

- **活动块**：阶段性 `thinking`、`tool_call`、`terminal` 以及与工具执行直接关联的文件变更/检查点等辅助块。
- **活动段**：时间线上连续的一组活动块。正文、子 Agent 卡片、权限问题、最终交付等可见业务内容会结束当前活动段。
- **折叠**：活动段仍保留一行摘要，用户可以展开查看明细。
- **隐藏**：整轮结束后由现有“思考和工具日志”总开关控制，活动段摘要和明细都不显示。

折叠与隐藏是两层独立状态。活动段组件不得修改或替代现有 `tool-logs-hidden` 总隐藏逻辑。

## 交互规则

### 运行中的活动段

1. 当前最后一个活动段只要包含 streaming thinking、pending/running tool 或 streaming terminal，就视为运行中。
2. 运行中的活动段默认展开，持续显示其内部思考和工具状态。
3. 同一活动段内部继续沿用现有工具类别分组，例如“查看 3 个文件”“执行 2 条命令”。

### 阶段边界与自动折叠

1. 活动段全部完成后暂不立即折叠，避免工具结果到达时产生瞬时跳动。
2. 当其后出现正文、子 Agent 卡片、权限/问答卡片或交付结果等边界内容时，上一活动段成为“已封闭段”。
3. 已封闭且无人工接管的活动段，在 `autoCollapseTools` 开启时自动折叠。
4. 新活动段独立展开，旧段保持一行摘要；各段不会互相切换状态。
5. 整轮结束时，现有总开关继续执行隐藏逻辑，不由活动段组件重复处理。

### 用户控制权

1. 用户点击一个折叠段将其展开后，该段记录 `userExpanded=true`。
2. `userExpanded=true` 的段落此后不再响应自动折叠，即使块状态更新或整轮仍在运行。
3. 用户可以再次手动收起该段；这只改变当前 `open`，不清除人工接管标记。
4. 用户操作只影响被点击的段，不能改变其他活动段。
5. 整轮结束后的总隐藏开关优先级更高：总开关关闭时，即使某段曾由用户展开也仍被隐藏；重新显示总日志时恢复各段自己的展开状态。

## 摘要文案

折叠段采用一行自然语言摘要，不展示内部事件名。摘要按实际存在的内容组合：

- `查看了 5 个文件`
- `运行了 3 条命令`
- `修改了 2 个文件`
- `调用了 4 个工具`
- `进行了思考`

多个类型使用 `·` 连接，例如：`查看了 5 个文件 · 运行了 3 条命令 · 进行了思考`。运行中的段落在右侧显示 spinner 和“进行中”，完成段不重复显示绿色对勾，以减少视觉噪声。

## 组件与数据流

### 独立模块

新增小型活动段模块，避免继续增大超过 3000 行的 `ChatView.tsx`：

- 纯函数：识别活动块、切分活动段、生成稳定段 key、计算运行状态和摘要。
- `ActivitySegment`：维护单段的 `open` 与 `userExpanded` 状态，渲染摘要和明细。
- 样式文件：复用现有 activity log 的图标、字号、颜色和箭头规则。

`ChatView.tsx` 只负责把已有 `renderBlocksGrouped` 的结果接入活动段模块，不在主文件增加新的状态机实现。

### 稳定身份

活动段 key 必须优先由段内首个 block 的现有稳定身份生成，例如 thinking 的 `segmentId`、tool/terminal 的 `toolCallId`；不能只使用数组序号或内容文本。实时事件插入或历史 hydration 合并后，同一活动段必须保留 React 组件实例，从而保留用户展开状态。若极端旧历史块没有稳定身份，才允许使用该 turn 内的段序号作为有界降级；不得因此修改持久化事件顺序。

## 状态模型

单段状态由以下输入决定：

- `running`：段内是否存在进行中的活动块。
- `sealed`：该段之后是否已经出现边界内容或另一个活动段。
- `autoCollapseEnabled`：外观设置 `autoCollapseTools`。
- `userExpanded`：用户是否曾主动从折叠态展开该段。
- `open`：当前是否展示明细。

状态转换：

| 当前条件                                         | 动作            | 结果                            |
| ------------------------------------------------ | --------------- | ------------------------------- |
| 新活动段且 `running`                             | 自动打开        | `open=true`                     |
| 段完成但未 `sealed`                              | 保持            | 避免瞬时跳动                    |
| `sealed && !userExpanded && autoCollapseEnabled` | 自动折叠        | `open=false`                    |
| 用户从折叠态点击展开                             | 人工接管        | `userExpanded=true, open=true`  |
| 用户再次点击                                     | 手动收起        | `userExpanded=true, open=false` |
| 总日志被隐藏                                     | 仅 CSS/父级隐藏 | 单段状态不变                    |

## 兼容边界

- 不改变 AgentEvent、SDK 适配器或事件持久化合同。
- 不改变单个 `ToolCall` 和 `ToolLogGroup` 的内部展开能力。
- 不把正文、错误、权限请求、子 Agent 卡片、后台任务卡片或最终文件交付收入活动段。
- 历史会话重放使用同一切分算法；首次加载时已封闭活动段默认折叠。
- Canvas `ChatPanel` 和 ProjectView 当前没有与主会话一致的复杂活动段布局，本次只改主 `ChatView`；共享事件归约器不增加视图状态。

## 验证

### 纯函数测试

- 连续 thinking/tool/terminal 合并为一个活动段。
- 正文和子 Agent 卡片切断活动段。
- 多个活动段获得稳定且不同的 key。
- 摘要正确合并查看、命令、修改、通用工具和思考计数。

### 组件测试

- 运行段默认展开。
- 已完成但未封闭的段保持当前状态。
- 段被封闭后自动折叠。
- 用户手动展开后，后续更新不再自动折叠。
- 用户手动操作只影响当前段。
- `autoCollapseTools=false` 时不自动折叠。
- 父级隐藏再显示后，单段展开状态不被重置。

### 集成与视觉测试

- 复现“正文 → 多批工具/思考 → 正文 → 新思考”的长会话，确认旧段压成一行而新段保持展开。
- 验证流式事件更新时不发生明显高度闪烁。
- 验证浅色/深色主题和窄窗口下摘要截断、状态标签及箭头不重叠。
- 保留现有整轮结束后的“思考和工具日志”总隐藏行为。
