# Playwright 浏览器按需下载设计

> 状态: 待开发 | 最后核对: 2026-07-18

## 背景

开发模式下，桌面应用启动约六秒后会检查 Playwright 完整性。只要浏览器来源不是应用内置 Chromium，当前逻辑就会静默下载约 150MB 的 Chromium。即使系统 Chrome、Edge 或 Playwright 默认缓存中的 Chromium 已经可用，也会产生这次隐式网络请求。

## 目标

- 应用启动时只检测 Playwright 完整性，不自动下载 Chromium。
- 系统浏览器或 Playwright 缓存浏览器可用时直接使用，不额外下载。
- 用户真正使用 Playwright 且浏览器缺失或版本不匹配时，Agent 可以按需下载匹配的 Chromium 并重试。
- 自动恢复失败时，引导用户前往“设置 → 完整性 → 浏览器自动化”手动下载。
- 完整性页面继续提供明确的手动下载入口，并说明系统浏览器回退与内置 Chromium 的关系。

## 设计

### 启动流程

删除桌面主进程开发模式下调用 `installBrowser` 的启动任务。启动后仍执行 `detectIntegrity` 并向渲染进程推送 Playwright 状态，但不触发下载、安装或其他网络请求。

### Agent 按需恢复

保留 `browser-use` 内置技能已有的 Playwright 安装和 Chromium 下载能力，并补全以下路径：

1. 优先使用已注册且启用的 Playwright MCP。
2. Playwright MCP 启动浏览器失败时，识别浏览器缺失、可执行文件不存在或版本不匹配等错误。
3. 系统 Chrome、Edge 或现有 Chromium 可用时直接使用，不下载。
4. 确认没有可用浏览器时，Agent 说明将进行约 150MB 的按需下载，然后执行 `playwright install chromium`。
5. 下载完成后重试原 Playwright 操作。
6. 下载失败时报告关键错误，并引导用户前往“设置 → 完整性 → 浏览器自动化”手动下载或修复。

Agent 的内置浏览器自动化系统提示词同步提供上述恢复原则，使未显式加载 `browser-use` 技能的会话也能给出正确引导。

### 完整性页面

保留现有“下载浏览器/重新下载”操作。使用系统浏览器时，文案说明当前浏览器自动化可用，同时提示遇到兼容性问题可下载与 Playwright 匹配的 Chromium；没有可用浏览器时，明确提示可在此手动下载。

## 错误处理

- 启动完整性检测失败只记录日志并推送不可用状态，不恢复为启动时下载。
- Agent 按需下载失败不得循环重试官方源；按照现有技能的镜像降级策略尝试后停止，并向用户报告。
- 手动下载继续复用现有 IPC、进度事件和安装服务，不新增下载实现。

## 测试

- 静态或单元测试确认启动流程不再引用 Chromium 自动安装逻辑。
- Session 运行时测试确认浏览器自动化系统提示词包含按需下载与“设置 → 完整性”引导。
- 技能内容测试或静态检查确认 `browser-use` 同时保留自动下载能力和手动恢复引导。
- Playwright 完整性页组件测试确认系统浏览器与无浏览器状态的说明准确，下载按钮仍可用。

## 非目标

- 不新增 Playwright 专属错误卡片或设置页深链。
- 不修改 Playwright MCP 的注册格式或浏览器优先级。
- 不在应用启动阶段安装 MCP 包、Chromium 或其他依赖。
