# Canvas 图片标注编辑器升级设计

> 状态: 实施中 | 最后核对: 2026-07-19

## 1. 结论

把当前「手写 Canvas 2D + 单个大组件 + 只输出 PNG」的图片标注弹窗，升级为一套面向沟通标注的轻量编辑器：

- 使用 **Fabric.js 7.x** 作为交互与对象渲染内核，不使用 Fabric 自带 UI，也不直接套用通用图片编辑器皮肤。
- UI 以微信、飞书截图标注的低学习成本为基线：工具少而明确、属性就近出现、画完立即可调整、键盘操作完整。
- 首期覆盖选择、箭头、矩形、椭圆、画笔、荧光笔、文字、马赛克、裁剪、编号、撤销/重做、缩放/平移和导出。
- 新增「扩展底板」能力：可选白色底板，分别设置或拖动调整上、右、下、左留白，标注可以放在原图之外。
- 同时保存可编辑标注文档和烘焙后的 PNG；未完成草稿再次打开时恢复编辑，已完成结果默认以当前 PNG 作为新一轮原图，历史侧车文档仍保留用于追溯。
- 继续沿用「生成新图片节点 + 建立来源连线」的安全模型，不默认覆盖原图。

这不是一个 Photoshop 替代品。它的核心任务是在 10–30 秒内快速圈重点、打码、写说明并回到无限画布。

## 2. 现状与主要问题

当前实现集中在：

- `CanvasImageAnnotationModal.tsx`：约 1279 行，自行实现对象模型、命中检测、8 点缩放、文字浮层、马赛克、橡皮、裁切、历史和导出。
- `CanvasImageAnnotationModal.less`：约 363 行，使用顶部工具栏、中央舞台和底部操作栏。
- `CanvasWorkspaceView.tsx`：负责把标注结果保存成新图片资产和节点，并建立 `derived_from` 来源连线。

已有能力并不算少，但难用来自交互模型和架构边界，而不是单纯缺少按钮：

1. 所有工具和属性挤在同一条顶部栏，用户要在图像、工具、颜色和粗细之间反复移动视线。
2. 图形画完自动切回选择，连续画多个框或箭头效率低。
3. 属性只能在绘制前设置；选中已有对象后缺少完整的颜色、粗细、字体、透明度和层级调整。
4. 文字是独立 HTML 浮层，提交后不能像真正文本对象一样顺畅双击编辑，中文输入体验也依赖手写同步。
5. 马赛克、橡皮、裁切和矢量对象混用同一状态模型，后续增加模糊、编号、聚光灯、组合和复制会持续放大复杂度。
6. 缺少多选、复制粘贴、方向键微调、层级排序、锁定比例和吸附等基础编辑能力。
7. 只输出 PNG，没有保存可编辑场景；关闭后无法修改某个文字或箭头，只能从头再做一次。
8. 原图就是整个输出画布，不能在图片外增加说明、标题、箭头终点或评审意见。
9. 工具按钮多为 32–36px 命中区，不满足触摸和高 DPI 环境下更稳妥的 44px 目标。
10. 标注逻辑已形成一个大组件，继续直接追加功能会显著提高回归风险。

## 3. 产品目标

### 3.1 核心目标

- 新用户不看说明，也能在 10 秒内完成「画箭头 + 写字 + 完成」。
- 熟练用户可以只用快捷键完成选择工具、绘制、撤销、复制、删除和提交。
- 任意已添加的矢量标注都可以再次选择、移动、缩放和修改样式。
- 用户可给原图增加白色外边空间，并直接在留白处写说明或放置编号。
- 保存后既有可直接使用的 PNG，也保留后续可继续编辑的标注文档。
- 4K 图片和 100 个普通标注对象仍保持顺畅的拖动和缩放体验。

### 3.2 非目标

首期不做：

- Photoshop 式图像调色、曲线、通道、蒙版和复杂滤镜。
- 多人实时协同编辑同一张标注图。
- 改写系统级截图功能或跨窗口截图捕获。
- 默认覆盖源图片资产。
- OCR、翻译、智能人脸/昵称打码等在线能力；这些作为后续增强，不阻塞基础标注升级。

### 4.1 为什么选 Fabric.js

当前最难维护的部分，正是 Fabric 已经解决的通用编辑器基础设施：对象命中、选区、控制点、旋转缩放、图层顺序、对象事件、视口、文本编辑和场景序列化。

Fabric 官方文档明确支持：

- 选择、对象交互、层级重排、序列化/反序列化、图片/SVG 导出和视口控制。
- `IText` 的中文/日文 composition 输入、光标、选区、复制粘贴和双击编辑。
- 通过 `setDimensions()` 改变真实画布尺寸，通过 `toJSON()` / `loadFromJSON()` 保存和恢复场景，通过 `toDataURL()` 导出图片。
- 自定义对象控制点和控制逻辑，便于把默认控制器调整为更接近 IM 标注工具的视觉。

本项目仍自行维护工具状态、属性栏、历史命令、底板、马赛克和保存协议，使产品体验不会被第三方编辑器 UI 锁死。

## 5. 信息架构与页面布局

编辑器继续以覆盖工作区的沉浸层打开，但从「通用 Ant Modal」调整为「全视口编辑工作台」。用户仍可收起回到无限画布查看上下文。

│                         │     白色扩展底板     │                          │

│                         └─────────────────────┘                          │
│                                                                          │
│              ┌────────────────────────────────────────────┐              │
│              │ 选择 箭头 形状 画笔 文字 编号 马赛克 裁剪 留白 │ 主工具栏   │

布局原则：

- 主工具栏浮在舞台底部中间，靠近鼠标常用区域；工具顺序按使用频率排列。
- 属性栏只在当前工具或选中对象需要时出现，不让颜色和粗细永久占据首层空间。
- 顶栏只保留离开、标题、视图和完成，不混入绘制属性。
- 高级属性放入轻量弹出面板，不默认常驻右侧，避免把图片压小。
- 宽度不足时主工具栏允许横向滚动，最常用的箭头、形状、文字和马赛克保持首屏可见。

## 6. 核心交互设计

### 6.1 打开与退出

- 图片节点右键菜单、悬浮工具栏和资源详情中的「图片标注」使用同一入口。
- 如果节点已有可编辑标注文档，入口文案显示为「继续标注」；菜单另提供「基于此图重新标注」。
- 打开后图片自动适应可用区域，最大不超过 100%，避免小图默认被过度放大。
- 草稿有修改时自动写入项目侧车文件；退出只需提示「保留草稿」或「丢弃草稿」，不再把用户逼到“继续标注/放弃全部”的二选一。
- 完成后默认生成新节点并与源节点连线；顶栏完成按钮旁的下拉菜单提供「复制到剪贴板」「下载 PNG」，后续再考虑「替换当前节点」。

### 6.2 工具选择

- 单击工具后保持该工具激活，可连续绘制多个同类标注。
- 绘制完成的对象立即选中，属性栏切换为该对象属性，但工具仍保持；在空白处继续拖动即可画下一个。
- `V` 切换选择，`Space` 按住临时平移，`Esc` 按层级执行：结束文字编辑 → 取消当前绘制 → 取消选中 → 返回选择工具。
- 双击文字进入编辑；双击形状或箭头不进入隐藏模式，仍保持选择，避免误操作。
- `Alt/Option + 拖动` 复制对象；方向键移动 1px，`Shift + 方向键` 移动 10px。
- 复制、粘贴、重复、删除、多选和层级操作使用通用桌面快捷键。

### 6.3 选择与属性修改

- 控制点视觉尺寸 10px，鼠标命中区至少 18px；触控/高 DPI 模式命中区提高到 24px。
- 单选显示移动框、四角等比缩放点、边中点和旋转点；箭头额外显示首尾端点。
- `Shift + 点击` 多选；框选从舞台空白区域开始。
- 选中对象后可修改颜色、粗细、填充、透明度、字体、字号、对齐和层级，修改立即反映在对象上。
- 白色描边或文字自动显示深色外轮廓预览，但导出是否保留轮廓由「增强对比」属性明确控制，不做不可见的永久样式修改。

### 6.4 形状与箭头

- 主工具栏只放一个「形状」入口；最近使用的形状作为图标，长按/小箭头选择矩形、圆、直线和圆角矩形。
- 默认形状为空心红色描边；可选半透明填充。
- 箭头默认实线、单向、圆角端点；属性栏可选双向、直线/折线、箭头大小。
- 按住 `Shift` 约束为正方形/正圆/45° 箭头，按住 `Alt/Option` 从中心绘制。

### 6.5 画笔与荧光笔

- 画笔采用平滑路径，支持压感时使用 `pointer.pressure`，无压感时保持稳定宽度。
- 荧光笔与画笔共用入口，默认 35% 透明度和较宽笔触；使用正常混合模式，保证导出一致。
- 连续轨迹在 pointer up 后做点简化，减少场景文件大小。

### 6.6 文字

- 点击舞台直接输入，输入框宽度随文本增长；拖出文本框时自动换行。
- 中文输入法 composition 期间不提交历史、不响应工具快捷键。
- `Cmd/Ctrl + Enter` 在文字编辑状态下完成文字；全局完成改为 `Cmd/Ctrl + Shift + Enter`，避免冲突。
- 提供字号、字重、颜色、对齐、背景胶囊和「增强对比」描边。
- 背景胶囊支持透明、半透明深色、白色和当前颜色，解决复杂图片上的文字可读性问题。

### 6.7 马赛克与隐私遮挡

马赛克提供两种模式：

- 画笔马赛克：适合沿头像、昵称或不规则区域涂抹。
- 矩形马赛克：一次拖出区域，选中后仍可调整范围。

实现上保留原始图片不变，把马赛克描述为可编辑对象；预览和导出时从原图层取样并像素化。这样移动马赛克对象不会叠加劣化，也能在再次打开时继续修改。

首期不把「橡皮擦」理解为擦除原图。橡皮只擦除自由笔迹；删除任意矢量对象使用选择 + Delete。若未来需要抠透明背景，应放入独立的图片编辑能力，避免与标注语义混淆。

### 6.8 编号标记

- 新增高频的「编号」工具，按点击顺序生成 `1, 2, 3...` 圆形标记。
- 删除中间编号后默认不自动重排，避免已经写在说明里的引用发生变化；属性栏可手动修改编号。
- 可选择实心圆、描边圆和带引线的编号气泡。

### 6.9 裁剪

- 裁剪只改变原图可见区域和输出画布，不立即把已有矢量对象烘焙进背景。
- 进入裁剪模式时其他对象仍可见但不可交互；提交裁剪后统一调整图片 frame 和对象坐标。
- 裁剪与扩展底板是两个明确工具：裁剪减少图片内容，留白增加输出画布空间，避免一个工具同时承担相反语义。

## 7. 白色扩展底板

### 7.1 用户入口

主工具栏增加「留白」工具。点击后在图片四边显示可拖动边界，同时打开一个紧凑面板：

```text
扩展底板  [开启]
背景      [白色]     （首期固定白色，结构上预留自定义色）
留白      上 64   右 64   下 128   左 64   [链条：联动]
快捷      [无] [窄 32] [中 64] [宽 128]
原图对齐  [九宫格：默认居中]
输出尺寸  2048 × 1272 px
```

### 7.2 操作规则

- 默认关闭；开启后初始使用四边 64px，或恢复用户上次使用的项目内偏好。
- 拖动某一条边只改变该方向的留白。
- 开启「四边联动」后修改任一数值会同步四边；关闭后可分别输入。
- `Alt/Option + 拖动边界` 同时调整对边，适合保持图片居中。
- 数值支持 0–4096px；拖动时以 8px 为视觉吸附步长，按住 `Cmd/Ctrl` 暂时取消吸附。
- 九宫格对齐决定原图在底板扩容时固定在哪个锚点。例如选择左上角后，增加右/下留白不会移动原图。
- 图片外的留白属于有效编辑区域，所有矢量工具均可在其中绘制。
- 舞台背景继续使用棋盘/暗色工作区，白色底板有 1px 边界和轻阴影，用户能明确区分「输出区域」与「编辑器背景」。

### 7.3 坐标与对象迁移

文档使用三个坐标概念：

- `artboardRect`：最终输出区域，原点固定为导出图左上角。
- `imageFrame`：原图在底板内的位置与可见区域。
- `objects[]`：标注对象，以 artboard 坐标保存。

当上/左留白变化时，默认平移 `imageFrame` 和全部已有标注对象，使它们相对原图的位置保持不变；右/下留白变化只增加输出空间。用户已经在留白中放置对象后，再次调整上/左留白也遵循同一规则，避免原图与标注错位。

### 7.4 导出行为

- 开启白色底板时，先绘制纯白 `artboard`，再绘制原图和标注，输出 PNG 不含透明边缘。
- 关闭底板时，输出尺寸等于裁剪后的图片 frame；位于图外的对象会触发确认：「缩回原图会裁掉 3 个标注」。
- 完成按钮旁实时显示尺寸变化，例如 `1920×1080 → 2048×1208`。
- 对超大尺寸进行像素预算保护；当宽 × 高超过安全阈值时，提示降低留白或导出倍率，避免 Chromium Canvas 分配失败。

| 复制/粘贴/重复 | `Cmd/Ctrl + C / V / D`                                       |
| 删除           | `Delete` / `Backspace`                                       |
| 微移           | 方向键；`Shift` 为 10px                                      |
| 完成标注       | `Cmd/Ctrl + Shift + Enter`                                   |
| 关闭/逐级取消  | `Esc`                                                        |

快捷键只在编辑器拥有焦点且不处于文字 composition 时生效。所有图标按钮都必须有 tooltip、`aria-label` 和可见焦点环。

## 9. 数据模型

不要把完整 Fabric JSON 直接塞进节点快照。4K 图片、自由笔迹和撤销历史会让项目 JSON 迅速膨胀。采用「轻量节点引用 + 项目侧车文档 + 烘焙资产」：

```ts
type CanvasImageAnnotationRef = {
  schemaVersion: 1
  documentPath: string
  sourceNodeId: string
  sourceAssetId?: string
  renderedAssetId?: string
  artboard: {
    width: number
    height: number
    background: '#ffffff' | null
    padding: { top: number; right: number; bottom: number; left: number }
  }
  updatedAt: string
}

type CanvasImageAnnotationDocument = {
  schemaVersion: 1
  source: {
    nodeId: string
    assetId?: string
    url: string
    width: number
    height: number
    contentHash?: string
  }
  artboard: {
    width: number
    height: number
    background: string | null
    imageFrame: { x: number; y: number; width: number; height: number }
    crop?: { x: number; y: number; width: number; height: number }
  }
  scene: {
    engine: 'fabric'
    engineVersion: string
    json: unknown
  }
  app: {
    nextCounter: number
    lastTool?: string
  }
  createdAt: string
  updatedAt: string
}
```

建议在 `CanvasNodeData` 增加 `imageAnnotation?: CanvasImageAnnotationRef`。侧车文件存放在项目资源目录的 `annotations/<node-or-document-id>.spark-annotation.json`，图片资产 `metadata` 同时写入来源文档引用，便于从资产中心继续编辑。

不持久化撤销栈；恢复编辑后以当前场景作为新的历史起点。自动草稿与已完成版本使用不同文件状态，完成时采用临时文件 + 原子替换，避免 Electron 进程退出留下半个 JSON。

## 10. 技术架构

现有组件超过 1200 行，升级时不继续向原文件堆功能。建议拆为：

```text
canvas/image-annotation/
├── CanvasImageAnnotationWorkspace.tsx    # 工作台外壳、加载/完成/退出
├── CanvasImageAnnotationTopbar.tsx       # 返回、视图、完成
├── AnnotationToolDock.tsx                # 主工具栏
├── AnnotationPropertyBar.tsx             # 上下文属性栏
├── AnnotationArtboard.tsx                # Fabric canvas 容器
├── AnnotationStatusBar.tsx               # 草稿、尺寸、提示
├── AnnotationPaddingPanel.tsx             # 白色底板和四边留白
├── annotation.types.ts                    # 业务文档与工具类型
├── annotationToolRegistry.ts              # 工具描述、快捷键、适用属性
├── annotationDocument.ts                  # schema、迁移、序列化
├── annotationHistory.ts                   # 命令历史与合并策略
├── annotationExport.ts                    # PNG/Blob/剪贴板导出
├── fabric/
│   ├── createAnnotationCanvas.ts          # Fabric 生命周期与默认控制器
│   ├── fabricObjectCodec.ts               # 业务对象 ↔ Fabric 对象
│   ├── fabricViewport.ts                  # 适应、缩放、平移
│   ├── MosaicObject.ts                    # 可编辑马赛克对象
│   ├── CounterObject.ts                   # 编号标记
│   └── annotationBrushes.ts               # 画笔、荧光笔
└── __tests__/
```

### 10.1 React 与 Fabric 边界

- React 管理工具、属性、文档状态、保存状态和布局。
- Fabric 实例通过独立 controller/hook 管理，不把鼠标移动中的每一帧对象坐标同步进 React state。
- `object:modified`、`path:created`、`text:editing:exited` 等稳定事件才提交命令和刷新属性摘要。
- 编辑器使用动态 `import('fabric')` 懒加载，避免增加桌面应用首屏包体和启动时间。
- 销毁工作台时显式解绑事件、释放 Canvas、图片位图和离屏马赛克缓存。

### 10.2 历史模型

采用业务命令历史，不在每次 pointer move 时保存完整场景：

- `AddObject`
- `RemoveObjects`
- `TransformObjects`
- `UpdateStyle`
- `EditText`
- `ChangeCrop`
- `ResizeArtboard`

同一对象在一次拖动过程中的变化合并为一个命令；颜色滑杆连续变化在 300ms 内合并。历史默认 100 步，超过后丢弃最旧命令，但当前文档不受影响。

### 10.3 马赛克实现

- 原图单独位于不可选择的 image layer。
- 马赛克对象保存区域或笔刷路径，不保存重复像素。
- 预览时把原图绘制到受 clipPath 限制的离屏层，使用低分辨率采样后 nearest-neighbor 放大。
- 导出时按最终分辨率重新渲染，保证缩放视图不影响马赛克质量。
- 对自由马赛克路径做缓存；仅路径、原图、裁剪或像素块大小改变时失效。

## 11. 与无限画布的集成

保持当前主流程：

```text
源图片节点
  → 打开/创建标注文档
  → 自动保存草稿侧车文件
  → 完成后导出 PNG 并保存为 CanvasAsset
  → 创建新的全幅图片节点
  → 写入 imageAnnotation 引用
  → 建立 derived_from 来源边
  → 选中新节点并关闭工作台
```

调整点：

- `CanvasWorkspaceView.tsx` 只保留打开状态与完成回调接线，不再承载标注编辑业务。
- 保存逻辑抽到 `useCanvasImageAnnotationPersistence.ts`，处理侧车文件、PNG 资产、节点创建和失败回滚。
- 标注完成结果继续使用现有 `fitImageNodeSize()` 和右侧自动放置；启用留白后按新的输出宽高比创建全幅图片节点。
- 如果 PNG 保存成功但节点创建失败，保留侧车草稿和已保存资产并给出重试入口，不静默丢失。
- 标注节点作为下游 AI 图片输入时仍只传烘焙 PNG，不把 Fabric 场景 JSON传给模型。

## 12. 响应式、可访问性与视觉约束

- 桌面按钮视觉尺寸 36–40px，但透明命中区不小于 44×44px，相邻命中区至少留 8px。
- 图标统一使用项目现有 Lucide/SVG 图标；不用 emoji 充当工具图标。
- hover/active/focus/disabled 四种状态都必须可区分，颜色不是唯一状态信号。
- 普通文字对比度至少 4.5:1；焦点环不低于 3:1。
- 微交互 150–220ms；拖动、画笔和缩放不加过渡，避免指针延迟感。
- 尊重 `prefers-reduced-motion`，关闭面板位移和淡入外的非必要动画。
- 视口宽度小于 760px 时，属性栏改为底部抽屉；工具栏横向滚动，不压缩成难以点击的小图标。
- 标注对象的控制点颜色与图片内容冲突时增加双层描边，保证深浅图片上都清楚。

## 13. 性能与安全预算

- Fabric 编辑内核仅在工作台打开时加载。
- 原图解码优先使用 `createImageBitmap`，不支持时回退 `HTMLImageElement`。
- 工作预览按设备像素比和视口尺寸限制渲染，最终导出使用原始分辨率重放场景。
- 自由笔迹在保存前简化点；单路径设置合理最大点数，超限时自动拆分。
- 马赛克预览使用缓存，拖动时不反复创建临时 canvas。
- 导出前计算像素总量和预计内存；超过阈值时阻止直接导出并提供 1×/0.5× 选项。
- 加载侧车 JSON 时执行 schema 校验，只允许白名单对象类型和属性；不执行文档中的任意函数或 URL。
- 外链图片仍受 Canvas taint 限制；进入编辑器前统一通过现有安全资源 URL/本地缓存流程解析。

## 16. 验收标准

1. 用户可以在原图外增加任意一侧白色留白，并在留白中添加和编辑标注。
2. 箭头、形状、文字、编号、画笔和马赛克保存后再次打开仍可逐个编辑。
3. 所有主工具能通过鼠标完成，也有明确快捷键；文字输入法不会触发工具切换。
4. 画多个同类标注不需要每次重新选择工具。
5. 选中已有对象后可以调整样式、复制、删除、移动、缩放和层级。
6. 完成后生成的新节点尺寸比例与最终输出图一致，并保留源节点血缘。
7. 普通 4K 图片、100 个矢量对象的选择和拖动没有明显卡顿；导出不会导致界面无响应。
8. 意外关闭后可恢复当前节点最近自动保存的未完成草稿；已完成结果再次标注时从当前 PNG 开始，侧车文档损坏时仍可打开烘焙 PNG。
9. 旧图片节点和旧标注 PNG 无需数据迁移即可继续使用。
10. 新增标注代码不继续扩大 `CanvasWorkspaceView.tsx` 和旧的 1200 行标注组件。

## 17. 风险与应对

| 风险                                        | 应对                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------- |
| Fabric 7 与当前构建链或 Electron 版本兼容性 | Phase 0 先做隔离原型；失败则回退 Konva，不在业务代码中半迁移                 |
| 4K/超长图导出内存峰值                       | 预览与最终导出分离、像素预算、倍率降级、导出进度和取消                       |
| 马赛克对象在缩放/裁剪后取样错位             | 统一 artboard/imageFrame 坐标，原图单独图层，基于文档坐标重渲染              |
| Fabric JSON 版本升级不兼容                  | 外包一层自有 schemaVersion 和对象 codec，不把原始 Fabric JSON 当长期公共协议 |
| 自动草稿产生大量文件                        | 同一文档原子覆盖、完成后清理过期草稿、项目关闭时做孤儿扫描                   |
| 第三方包增加启动体积                        | 动态 import、只在标注入口加载、构建阶段记录 chunk 预算                       |
| UI 功能再次膨胀                             | 主工具栏限定沟通标注；照片调整、AI 识别和高级效果进入独立阶段                |
