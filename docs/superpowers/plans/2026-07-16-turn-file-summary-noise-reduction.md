# 会话文件变更汇总降噪方案

> 状态: 实施中 | 最后核对: 2026-07-16

## 目标

“本次修改完成”只展示高可信的本轮修改文件；构建、测试、缓存等副作用文件按目录聚合隐藏；Agent 通过 `present_files` 显式选择的成果文件继续走独立的交付文件卡片。Git 和工作区快照保留为兜底发现机制，但不再直接决定主列表。

## 当前实现

- `file_change` 事件默认视为 Agent 直接修改，保留在主列表。
- checkpoint、工作区快照、Git 状态兜底事件携带来源标记，进入低可信候选集合。
- 低可信文件命中已知生成目录（例如 `.gitnexus`、`dist`、`build`、`.next`、`coverage`）时按目录聚合。
- 低可信文件在同一目录达到 20 个时按目录聚合，避免构建产物形成数千条 UI 行。
- 聚合批次显示目录、文件数和增删统计；真实路径仍保留在事件历史中，便于后续审计和扩展。

## 后续演进

1. 为命令执行增加 turn 范围的文件变化 journal，并关联 toolCallId，减少仅依赖 mtime 的误报。
2. 让生成器/MCP 返回结构化输出目录或成果文件，自动提升为交付物。
3. 增加项目级 `.sparkignore`，覆盖非 Git 工作区的构建和缓存目录。
4. 将 `present_files` 扩展为支持目录交付，适用于静态网站和打包产物。
