# 无限画布工作流执行闭环实施计划

> 状态: 实施中 | 最后核对: 2026-07-24

**目标:** 在 Phase 1 管理与提取能力上补齐可编辑、可运行、可恢复、可追溯的完整画布工作流闭环；全部验收通过前不作为正式功能发布。

**边界:** 本功能只使用 `CanvasWorkflow*`、`canvas:workflow:*`、`canvas_workflow_*` 命名和持久化，不复用应用工作台的 `workflows` / `workflow_runs`。执行层复用无限画布现有任务提交、Provider Manifest、输入绑定和产物节点能力。

## 发布门槛

- [x] 定义编译器能阻止重复 ID、悬空引用、DAG 环、子工作流递归与无效契约进入执行。
- [x] 定义读取经过运行时校验；发布版本有不可变快照，草稿更新不会覆盖历史运行版本。
- [x] 运行与步骤独立持久化，支持取消、失败步骤重试、恢复和已完成产物保留。
- [x] 用户能在当前画布通过选区编辑定义、暴露自定义输入与参数，并保存、更新、发布版本。
- [x] 用户能从项目抽屉填写输入、预检依赖、运行，并在画布看到输出节点。
- [x] 输出节点与资产能追溯 definition、version、run、step；运行创建使用幂等键。
- [x] 框选提取保留端口句柄和必要配置，规则分析后可选 AI 语义增强，并必须人工确认。
- [x] 项目删除、账号归属、分页、忙碌/错误态、焦点陷阱与键盘操作符合当前本机资料域要求；有运行历史的定义只允许归档，不能破坏追溯记录。
- [ ] 协议、存储、桌面单元测试、类型检查、生产构建与 Electron 关键路径 E2E 全部通过。

## 阶段 1：可执行定义

- [x] 以失败测试定义结构化编译诊断和冻结执行计划。
- [x] 实现节点、边、契约唯一性及引用校验。
- [x] 实现稳定拓扑排序、环检测和子工作流递归检测。
- [x] 修复框选提取的句柄与配置保真，并在发布/运行前统一编译。
- [x] 拒绝未知画布操作；同一子工作流的不同固定版本分别展开校验，不能用版本切换绕过依赖检查。

## 阶段 2：版本与运行持久化

- [x] 新增不可变 `canvas_workflow_versions`。
- [x] 新增 `canvas_workflow_runs` 与 `canvas_workflow_run_steps`，迁移和 Repository 先测后写。
- [x] 定义 run/list/get/cancel/retry/resume IPC 与运行时请求校验。
- [x] 定义状态机、幂等键、步骤输出和 provenance 数据契约。

## 阶段 3：画布执行与产物

- [x] 将编译计划转换为现有画布任务提交，按 DAG 释放就绪步骤。
- [x] 输入契约绑定到用户自定义值和上游产物，运行前完成依赖检查。
- [x] 将步骤输出回写为画布可见节点，保存运行与步骤血缘。
- [x] Provider 预检把画布操作映射为真实 Manifest 能力 ID，运行输出按 `sourceHandle` 精确投影。
- [x] 支持取消、失败重试、断点恢复和部分结果保留。

## 阶段 4：编辑与应用体验

- [x] 工作流详情包含概览、输入输出、依赖、版本和运行记录。
- [x] 当前画布选区可保存回现有草稿并形成新版本。
- [x] 运行面板提供按类型生成的输入控件、预检、进度与错误恢复。
- [x] 管理页补齐导入、导出、复制、归档、删除和稳定错误反馈。
