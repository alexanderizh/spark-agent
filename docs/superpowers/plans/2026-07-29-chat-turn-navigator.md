# 对话轮次导航条实施计划

> 状态: 已落地 | 最后核对: 2026-07-30

## 目标

在主对话区左侧留白中增加一条轻量的“轮次导航条”：每个短横线代表一轮用户与 Agent 的对话；当前轮次用更长、更亮的横线表示；悬浮或键盘聚焦时预览该轮双方的正文；点击后平滑跳转到该轮。交互需要在长会话虚拟列表、历史懒加载、流式输出和深浅主题下保持稳定。

本功能只增强主会话浏览，不改变消息、事件或轮次的持久化结构，也不在侧聊面板和窄内容区强行显示。

## 落地结果

- 已新增独立的轮次派生工具、导航组件和 Less 样式，并只在主 `ChatStream` 开启。
- 已接入现有完整轮次分页、历史哨兵、虚拟列表索引跳转、自动贴底状态和“回到最新”入口。
- 已实现共享活动长线的轻弹簧动画、悬浮/焦点预览、点击脉冲及减少动态降级。
- 已在真实 Electron 开发窗口验证左侧布局、双方预览、键盘切换和点击跳转；浅色主题预览对比度已按实测结果调整。
- 聚焦与 Renderer 集成测试共 40 项通过，Desktop TypeScript、ESLint、Prettier、生产构建及 `git diff --check` 通过。

## 现状与可复用能力

- `UIMessage` 已包含 `turnId`，`MessageBuilder` 会把同一轮的用户消息与 Assistant 消息关联到同一个 `turnId`，无需新增数据库字段。
- `ChatStream` 已集中持有 `messages`、滚动元素 `streamRef`、用户上滚状态和历史懒加载状态，是挂接轮次导航的正确边界。
- `VirtualMessageList` 已统一为静态列表和 40 条以上的虚拟列表提供 `scrollToIndex()`，可以复用为跳转入口。
- 历史接口已按完整轮次分页，当前首屏每次加载 6 轮；向上翻页不会切碎一轮对话。
- `motion/react` 已是 Desktop 直接依赖，可用于活动指示器和预览浮层的 transform/opacity 动画，不需要增加依赖。

## 产品范围与关键决策

### 第一版包含

1. 主会话存在至少 2 个已加载轮次，且消息内容左侧有足够留白时显示导航条。
2. 每个标记对应一个完整 `turnId`；点击标记定位到该轮第一条用户消息，没有用户消息时定位到该轮第一条消息。
3. 悬浮、键盘聚焦标记时显示用户正文和 Agent 正文预览；正在执行的轮次显示实时更新的已有正文和“执行中”状态。
4. 当前轮次随正文滚动而更新；点击跳转后暂停自动贴底，并保留现有“回到最新”按钮行为。
5. 仍有更早历史时，在轨道顶部显示“更早轮次”哨兵；点击后调用现有懒加载，旧轮次加载完成后追加到导航条。
6. 支持深色、浅色、键盘操作、焦点态和 `prefers-reduced-motion`。

### 第一版不做

- 不一次性读取完整事件历史来构建全会话索引。大会话中的单轮可能包含上千个工具事件，这会破坏现有窗口化加载的性能目标。
- 不在未加载轮次上展示虚假的空标记。导航条只表示当前已加载的完整轮次，并用“更早轮次”哨兵明确剩余历史。
- 不在侧聊面板、空会话 Hero、内容区左侧可用空间不足或触控粗指针环境中显示悬浮式导航。
- 不把工具调用、思考过程和文件摘要全文塞入预览卡；预览聚焦双方最终可读正文。

如果后续需要“一步跳到任意未加载轮次”，再单独设计轻量 `session:get-turn-outline` 与双向历史窗口，不在本次功能中用全量历史读取绕过性能边界。

## 交互规格

### 导航条布局

- 导航层是 `chat-stream-viewport` 的绝对定位子层，与右侧 `ChatOverlayScrollbar` 同级，不占用正文宽度，也不随消息内容滚动。
- 导航条固定贴近会话视口左边缘 `12px`，不跟随正文左缘移动；标记宽度为 `32px`、轮次中心间距为 `11px`，默认所有视觉短线均为 `6px × 2px`。
- 悬浮或键盘聚焦某一轮时，该线通过宽度过渡展开到约 `28px`，相邻三轮按距离依次展开到约 `20px / 14px / 10px`；不使用横向缩放，以保持 `2px` 高线条两端始终为真实半圆。当前轮次在静止状态只提高亮度，不常驻长线。
- 轨道垂直居中，最大高度 `min(220px, 36vh)`；轮次较多时轨道自身可滚动但隐藏原生滚动条，并自动保证当前标记在轨道可见区内。
- 只有导航层与正文左边缘之间至少有 `28px` 可用空间时显示；结合正文自身的内边距，足够容纳展开后的标记而不遮挡文字。右上角环境悬浮面板打开时，正文与输入框最大宽度收敛为 `min(900px, 视口宽度 - 56px)`，先真实生成左右各 `28px` 的安全区，再执行右侧退让，不能只修改 margin 计算或降低可见阈值。使用 `ResizeObserver` 测量 `chat-stream-viewport` 与 `.chat-stream-inner` 的真实矩形，适配侧栏、浏览器面板、审查面板和窗口缩放，不能只依赖全局媒体查询。
- 预览卡出现在标记右侧，宽度为 `min(360px, 可用宽度)`，顶部位置在视口内夹紧，不能被 Tabbar 或 Composer 截断。

### 轮次预览

- 第一段是用户正文，使用主文字色和中等字重，最多 2 行。
- 第二段是 Agent 正文，使用次级文字色，最多 3 行。
- 文本来源仅为 `text` block；合并连续空白、保留必要换行，并按 Unicode 字素安全截断，避免拆断 emoji 或组合字符。
- 用户只发附件时显示“发送了 N 个附件”；Agent 暂无正文但正在运行时显示“正在处理…”；只有工具活动而无最终正文时显示“本轮主要包含工具执行”。
- 预览浮层为非交互内容，`pointer-events: none`，避免鼠标从标记移向卡片时形成新的焦点陷阱。

### 点击与滚动同步

1. 从 `messages` 派生 `ChatTurnNavItem[]`，记录 `turnId`、显示序号、起始消息索引、用户/Agent 消息引用和状态。
2. `turnId` 缺失的旧数据使用稳定的 `message:${message.id}` 作为降级键；相邻孤立的用户/Assistant 消息不强行错误合并。
3. 点击后先把 `userScrolledRef` 设为 `true`、显示“回到最新”按钮，再调用 `VirtualMessageList.scrollToIndex(startIndex, 'start')`。
4. 扩展 `scrollToIndex` 以接受 `behavior`；虚拟列表先按估算位置滚动，目标行挂载并测量后再做一次精确校正。普通动画使用 `smooth`，减少动态使用 `auto`。
5. 目标行使用约 `24px` 的顶部视觉留白，并短暂点亮对应标记；不修改消息本身的背景，避免对正文造成闪烁干扰。
6. 用户手动滚动时以视口上方约 32% 的参考线判定当前轮次：在一次 `requestAnimationFrame` 内读取已挂载的 `[data-virtual-message-index]` 行，选择穿过参考线或距离参考线最近的消息索引，再映射到 `turnId`。该方法同时兼容静态列表和虚拟列表。
7. Agent 自动贴底且用户未上滚时，当前轮次保持为最后一轮；用户点击旧轮次后，现有自动贴底逻辑不得把视图立即抢回底部。

### 动画规格

动画只作用于 transform 和 opacity，避免触发布局与消息虚拟测量抖动。

- 导航条首次出现：整体 `opacity: 0 → 1`、`translateX(-4px) → 0`，160ms ease-out；不为几十个标记做长时间逐项级联。
- 活动标记：使用一个共享的绝对定位高亮条，在轮次切换时通过 `translateY` 移动；采用约 200–260ms 的轻弹簧（建议 `stiffness: 420`、`damping: 34`、`mass: 0.45`），长度与明暗在 160ms 内过渡。
- 标记悬浮/聚焦：短线以左侧为原点 `scaleX(1 → 1.8)`，160ms ease-out；热区尺寸不变化，因此无布局位移。
- 预览卡：延迟约 100ms 打开，`opacity: 0 → 1`、`translateX(-6px) → 0`、`scale(.985) → 1`，160ms ease-out；离开后约 80ms 淡出，避免快速划过时连续闪烁。
- 点击反馈：活动条执行一次 280ms 的亮度脉冲；正文只做平滑滚动，不做缩放或大面积高亮。
- `prefers-reduced-motion: reduce` 下禁用弹簧、脉冲和位移动画，预览只做不超过 60ms 的透明度切换，跳转改为立即定位。

## 组件与文件拆分

`ChatView.tsx` 已超过 3000 行，本功能只在其中增加最小装配代码，所有计算、组件和样式必须拆出：

- 新建 `apps/desktop/src/renderer/design/views/chat/chat-turn-navigation.ts`
  - 定义 `ChatTurnNavItem`。
  - 实现轮次分组、正文摘要、附件/工具活动降级文案和消息索引映射。
- 新建 `apps/desktop/src/renderer/design/views/chat/ChatTurnNavigator.tsx`
  - 渲染轨道、标记、更早历史哨兵和预览卡。
  - 管理悬浮/焦点、轨道内自动滚动、共享活动指示器和响应式可见性。
- 新建 `apps/desktop/src/renderer/design/views/chat/ChatTurnNavigator.less`
  - 独立维护导航条、预览卡、主题、焦点态和减少动态样式，避免继续扩大 `ChatView.less`。
- 修改 `apps/desktop/src/renderer/design/views/chat/VirtualMessageList.tsx`
  - 为 `scrollToIndex` 增加可选滚动行为与虚拟行挂载后的精确校正能力。
- 最小修改 `apps/desktop/src/renderer/design/views/ChatView.tsx`
  - 给 `ChatStream` 增加 `showTurnNavigator?: boolean`，只在主会话传 `true`。
  - 传入 `messages`、`streamRef`、`virtualMessageListRef`、`hasMoreHistory`、`isLoadingOlder` 和加载更早回调。
  - 复用现有 `userScrolledRef`、`setShowScrollToBottom`，避免建立第二套滚动状态。

## 实施顺序

1. 先实现并测试纯函数：按 `turnId` 分组消息、提取双方预览、计算起始索引与异常数据降级。
2. 实现静态 `ChatTurnNavigator` 视觉与键盘交互，完成深浅主题、可用空间判断和减少动态样式。
3. 扩展 `VirtualMessageList` 的跳转句柄，接入静态列表与虚拟列表的平滑定位和二次校正。
4. 在主 `ChatStream` 装配导航条，接入活动轮次检测、用户上滚状态和“更早轮次”懒加载。
5. 补齐集成测试与 Electron UI 验证，检查现有会话切换、自动贴底、滚动到底部和侧聊没有回归。

## 测试计划

### 单元测试

- 同一 `turnId` 的用户与 Assistant 消息正确合并为一个标记。
- 仅用户消息、仍在流式、仅附件、仅工具活动、缺失 `turnId`、消息删除后的降级结果正确。
- 摘要不会包含 thinking/tool_call/file summary，截断不会拆断 Unicode 字素。
- 当前轮次从可见消息索引正确映射，首轮/末轮和虚拟列表部分挂载时无越界。
- `VirtualMessageList` 的静态和虚拟分支都支持 `behavior`，并保持稳定 key 和现有测量逻辑。

### 组件与集成测试

- hover 和 focus 都能打开同一预览；blur、Escape 和会话切换能关闭。
- ArrowUp/ArrowDown、Home/End 移动活动标记，Enter/Space 跳转，使用 roving tabindex 避免长会话制造大量 Tab 停靠点。
- 点击旧轮次后 `userScrolledRef` 保持上滚状态，流式消息不会立刻把视图抢回底部。
- 有更早历史时显示哨兵，加载中不可重复触发，加载后标记数量和顺序更新且当前轨道位置不突跳。
- 侧聊 `ChatStream`、空态、窄窗口和左侧空间不足时不渲染导航层。

### 视觉与性能验证

- 深色/浅色分别检查 2、6、20、100 个已加载轮次，预览卡不越过视口。
- 375、768、1024、1440 宽度及打开浏览器/审查侧栏的组合下无正文遮挡和水平滚动。
- 普通动态与减少动态两种模式录屏检查活动条、悬浮卡和点击跳转。
- React Profiler 检查流式输出：滚动监听按帧节流，导航派生不造成整棵消息列表额外重渲染。

## 验收标准

1. 主会话中每个可见标记都能预览该轮双方正文并准确跳转。
2. 活动长线会随滚动平滑移动，悬浮卡出现/消失无闪烁、无布局抖动。
3. 40 条以上消息启用虚拟列表后仍能定位未挂载轮次，误差校正后目标轮顶部偏差不超过约 24px。
4. 点击旧轮次不会被流式自动贴底抢回；“回到最新”仍可恢复跟随。
5. 更早历史状态明确且可继续加载，不把最近 6 轮伪装成完整会话。
6. 导航条不会覆盖正文、Composer、Tabbar、侧聊或右侧自定义滚动条。
7. 键盘、焦点可见性和减少动态模式可用，深浅主题文字对比满足现有设计令牌标准。

## 风险与处理

- **虚拟列表动态高度导致跳转偏差**：索引跳转后等待目标行挂载和测量，再做一次精确校正；测试 Markdown、代码块和图片撑高场景。
- **活动轮次与自动贴底互相争抢**：导航跳转必须进入现有 `userScrolledRef` 状态机，不能单独维护“锁定轮次”。
- **历史 prepend 导致轨道突跳**：标记使用稳定 `turnId` key，旧轮次插入后按当前活动项恢复轨道自身 scrollTop。
- **超长预览拖慢流式更新**：摘要只读取 text block 并限制字符数；派生结果用 `useMemo`，活动检测按 `requestAnimationFrame` 节流。
- **现有未提交的 ChatView 改动冲突**：实现时只做最小装配，先核对工作区差异，不覆盖当前空态主题等用户改动。
