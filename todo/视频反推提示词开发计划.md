# 视频反推提示词开发计划

> 状态: 待开发 | 最后核对: 2026-08-12

## 1. 目标与范围

新增一个画布操作 `video_prompt_reverse`，让用户选择一段视频并输入希望反推的内容，由专用 Agent 在受控工具范围内读取视频资产、规划采样、生成带编号的关键帧宫格图，使用支持多图视觉输入的文本模型进行联合识别，最后生成可直接用于文生视频或图生视频的提示词，并回写为文本资产和画布文本节点。

第一版必须满足：

- Agent 可以读取当前画布授权范围内的视频资产列表和媒体元数据。
- 多个视频候选不能静默选择第一个；需要用户选择，或由操作节点明确绑定唯一输入。
- Agent 不得任意读取系统文件、根据文件名猜测视频内容或绕过画布资产授权。
- 视频先按采样间隔抽帧，再按全局顺序组成宫格图。
- 每次视觉识别请求必须同时携带多张按时间排序的宫格图；禁止退化为逐宫格单图调用。
- 关键帧编号按从左到右、从上到下递增，并带全局帧号和时间戳。
- 长视频按连续窗口分批，批次之间保留一张重叠宫格图，保证跨批次动作连续性。
- 选用的文本模型必须声明支持图片识别和至少两张图片的同请求输入；能力缺失或不完整时阻止执行，不猜测默认值、不自动切换模型。
- 复用现有 IPC、图片附件协议、任务状态、文本产物回写、血缘关系和安全路径校验能力。
- 第一版不分析音频、对白、音乐和音效，不根据画面臆造声音内容。

不在本期范围内：通用 Agent 任意操作文件系统、逐帧视频理解、音频转写、自动保存全部中间宫格图到画布、无用户确认的多视频选择、通过降低画质或采样步数换取性能。

## 3. 核心设计决策

### 3.1 Agent 模式

采用“Agent 负责决策，专用工具负责执行”的模式。

Agent 可以：

1. 列出当前画布可见且已授权的视频资产。
2. 获取视频时长、尺寸、帧率、编码和文件可读性。
3. 根据用户要求、视频时长和模型多图上限选择采样间隔与联合识别批次。
4. 请求工具生成关键帧与宫格图。
5. 请求工具按连续窗口联合识别宫格图。
6. 根据所有批次结果请求最终提示词汇总。
7. 将最终提示词回写为文本资产和文本节点。

Agent 不可以：

- 直接拼接任意本地路径提交给模型。
- 读取画布授权范围之外的目录、文件或环境变量。
- 把一个宫格图拆成多个独立视觉请求。
- 在模型能力未声明时自行假设图片数量上限。
- 在多个视频候选之间静默选择。
- 绕过任务取消、路径校验、模型能力预检或文本产物回写流程。

第一版不开放任意用户自定义 Agent Prompt。使用固定的专用视频反推 Agent 系统提示词；用户可以选择符合能力要求的视觉文本模型，并输入反推要求。这样保留 Agent 的规划能力，同时保证多图顺序、任务阶段、成本和输出格式可控。

### 3.2 视频采样与限制

| 项目 | 规则 |
|---|---|
| 默认最长视频 | 60 秒 |
| 硬上限 | 180 秒 |
| 采样间隔 | 0.2～5 秒，默认 0.5 秒；提供 0.2、0.5、1、2、5 秒预设和 0.1 秒步进的自定义值 |
| 最大采样帧数 | 120 |
| 单张宫格 | 12 帧，4 列 × 3 行 |
| 宫格顺序 | 从左到右、从上到下 |
| 单次联合视觉输入 | `min(模型 maxVisionImages, 12)` 张宫格图 |
| 最少视觉输入 | 2 张宫格图；模型只支持 1 张时阻止执行 |
| 批次关系 | 按时间连续切分，批次之间重复上一批最后一张宫格图 |
| 汇总调用 | 1 次文本模型调用，输入为所有批次结构化结果，不再发送原视频 |
| 音频 | 第一版忽略，不生成对白、音乐、音效描述 |

帧数估算使用探测到的时长和采样间隔，并在提交前再次以实际元数据校验。预计帧数超过 120 时直接阻止提交，提示用户提高间隔或缩短视频；不得静默修改用户设置。视频超过 60 秒时面板显示警告，超过 180 秒时阻止执行。

### 3.3 宫格与顺序契约

每帧记录：

```ts
type VideoPromptReverseFrame = {
  frameId: string       // F0001、F0002……
  globalIndex: number   // 从 1 开始
  timestampSec: number
  imagePath: string
}
```

每张宫格记录：

```ts
type VideoPromptReverseSheet = {
  sheetIndex: number
  totalSheets: number
  frames: VideoPromptReverseFrame[]
  firstFrameId: string
  lastFrameId: string
  startTimeSec: number
  endTimeSec: number
}
```

宫格图片必须在每个格子内叠加短标签，例如 `F0023 · 00:11.0`。工具同时返回机器可读的 `frames` 元数据，模型提示词明确说明：图片按左到右、上到下阅读，宫格编号是时间顺序，不是独立镜头编号。

物理宫格图之间不重复帧，避免浪费视觉输入；联合识别批次之间重复上一批最后一张宫格图，并标记 `overlap=true`。最终汇总按 `globalIndex` 去重，保留重叠宫格提供的连续性说明。

### 3.4 多宫格联合识别

批次规划必须先读取模型能力：

```ts
type VisionInputCapability = {
  supportsVision: boolean
  maxVisionImages: number | null
}
```

`maxVisionImages` 必须来自有效的模型 manifest、模型目录或等价的运行时能力描述；缺失、非正数或无法确认时阻止执行。不能使用图片生成能力的 `maxImages` 代替视觉文本输入上限。

批次示例：模型最多接收 4 张宫格图时：

```text
批次 1：S01、S02、S03、S04
批次 2：S04、S05、S06、S07
批次 3：S07、S08、S09、S10
```

每个批次是一次请求，图片数组顺序和提示词中的宫格说明顺序完全一致。批次默认按顺序执行，便于 Agent 根据上一批结果判断是否需要继续；如果后续实现并行请求，仍必须保持每批独立、可取消，且最终按 `batchIndex` 排序。

### 3.5 结构化分析与最终提示词

联合识别结果使用稳定的版本化契约：

```ts
type VideoPromptReverseBatchAnalysis = {
  schemaVersion: 1
  batchIndex: number
  totalBatches: number
  sheetIndices: number[]
  timeline: Array<{
    frameId: string
    timestampSec: number
    subject: string
    action: string
    scene: string
    camera: string
    lightingAndStyle: string
    confidence: 'high' | 'medium' | 'low'
    uncertain: string[]
  }>
  transitions: Array<{
    fromFrameId: string
    toFrameId: string
    description: string
  }>
  continuity: {
    persistentElements: string[]
    majorChanges: string[]
    transitionNotes: string[]
  }
}
```

视觉模型必须返回 JSON；解析失败、缺少批次号、帧号越界或结果无法按 schema 收窄时，任务在对应阶段失败，并保留脱敏错误摘要，不无限重试。

最终汇总输入包括用户反推要求、视频元数据、全局帧顺序、宫格覆盖范围、所有批次分析和重叠关系。最终输出只保留可复制的提示词正文，不输出分析过程、标题或 Markdown 包装。提示词至少覆盖主体与外观、场景环境、动作时间线、景别与角度、焦段和运镜、构图、光影、色彩、材质、节奏、连续性及不确定内容边界。

## 4. 工具与运行时边界

### 4.1 受控工具

优先复用已有 Canvas 工具；新增视频反推领域工具时，工具只接受已校验的资产 ID、任务 ID 和结构化参数，不接受任意系统路径作为公开 Agent 输入。

建议工具职责如下：

| 工具 | 职责 | 关键约束 |
|---|---|---|
| `canvas_list_video_assets` | 列出当前画布授权范围内的视频候选 | 返回 asset/node ID、标题、MIME、项目内路径和可用状态；不返回密钥 |
| `canvas_probe_video_for_prompt_reverse` | 探测视频元数据并计算估算帧数 | 只解析授权资产；执行最长时长、间隔和帧数校验 |
| `canvas_prepare_video_prompt_reverse` | 按计划抽帧并生成宫格图 | 安全路径校验、FFmpeg 可用性、全局编号、时间戳和临时目录均由工具负责 |
| `canvas_analyze_video_prompt_reverse_batch` | 联合识别一批宫格图 | 必须接收至少 2 张有序宫格图；工具内部绑定视觉模型和附件协议，禁止单图退化 |
| `canvas_synthesize_video_prompt` | 汇总所有结构化分析 | 按 `batchIndex` 排序并按 `globalIndex` 去重，输出纯提示词 |
| `canvas_materialize_video_prompt_reverse` | 创建文本资产、文本节点和 generated 血缘 | 复用现有文本产物回写，不把临时宫格图默认落到画布 |
| `canvas_cancel_video_prompt_reverse` | 取消任务 | 中止 FFmpeg、视觉请求和后续回写，保持 cancelled 状态 |

如果现有工具已经覆盖其中的职责，应扩展现有 schema，不创建同义重复工具。工具 schema、Agent MCP 注册和主进程 IPC 必须使用同一份协议类型。

### 4.2 任务阶段

任务状态至少包含：

```text
preflight
probing
sampling
composing
planning_batches
analyzing_batch
synthesizing
materializing
completed
failed
cancelled
```

进度事件至少带 `taskId`、`stage`、`completed`、`total`、用户可读 message 和当前批次/总批次。任务详情保存实际采样间隔、实际帧数、宫格数、批次数、模型标识、视觉输入上限和失败阶段；不保存 API key、Authorization、Cookie、完整 base64 或未经脱敏的外部 URL。

### 4.3 文件与中间产物

- 输入只能来自当前画布资产或用户明确绑定的文件节点。
- 所有本地路径经过现有安全目录校验；网络 URL 仅在现有输入协议明确允许时使用。
- 抽帧和宫格写入任务专属临时目录，目录名与 task ID 绑定，避免并发任务互相覆盖。
- 成功、取消和普通失败结束后清理临时文件；清理对象必须是本任务创建的临时产物，不触碰用户已有文件或用户可见资产。
- 第一版不自动创建宫格图节点；后续如需导出，设计为用户主动触发的独立动作。

### 5.2 主进程视频反推运行时

新增目录：

```text

├─ videoPromptReverse.types.ts
├─ videoPromptReverseLimits.ts
├─ sampleTimes.ts
├─ contactSheet.ts
├─ batchPlanner.ts
├─ videoPromptReversePrompts.ts
```

职责划分：

- `sampleTimes.ts`：根据时长、采样间隔和帧数上限计算采样计划，处理浮点误差、0 秒视频和边界时间点。

每个公共函数先补失败测试，再实现最小逻辑。运行时不得直接写入 `main/ipc/index.ts` 大分支；IPC 注册拆到专用 `registerVideoPromptReverseIpc.ts`，只负责参数解析、权限校验、任务注册和事件转发。

## 6. 分阶段实施任务

### 阶段 A：预检、隔离与协议

1. 在独立 worktree 中确认当前分支、未提交改动和并行文件所有权；不得覆盖现有三处并行修改。
2. 阅读并记录实际符号调用方；复杂公共符号修改前运行 GitNexus impact。若 GitNexus 未暴露、索引过期或查询失败，按 `AGENTS.md` 规则使用 `rg`、测试和 `git diff` 降级，并在交付说明注明。
3. 新增 `video_prompt_reverse` 及共享类型，先写 schema 测试再实现 schema。
4. 为采样参数、模型视觉能力、任务阶段和批次分析增加运行时校验测试。
5. 运行协议包相关 typecheck/test，确保旧的 `image_prompt_reverse`、媒体操作和 IPC schema 不回归。

### 阶段 B：采样、宫格和批次规划

1. 编写采样时间计算失败测试：0 秒、负间隔、浮点间隔、超过硬上限、预计帧数 120 和 121、最后时间点不越界。
2. 复用 `probeVideo` 和统一 FFmpeg 执行层；实现最小的一次性均匀抽帧路径，确保可取消、可报告进度并返回真实时间戳。
3. 编写宫格合成测试：12 帧 4×3 排列、全局编号、时间戳标签、最后不足 12 帧、跨任务临时目录隔离。
4. 编写批次规划测试：全部宫格一次联合、超过模型上限时连续分批、批次 overlap、按 batchIndex 和 globalIndex 稳定排序、`maxVisionImages < 2` 拒绝。
5. 对本阶段运行主进程服务单测和短视频 FFmpeg 集成测试；FFmpeg 不可用时测试必须明确标记环境阻塞，不得伪报成功。

### 阶段 C：联合视觉识别和汇总

1. 编写模型调用器测试，断言一次批次请求收到有序 `images[]`，不会被拆成多个单图调用。
2. 编写视觉结果 JSON 解析和 schema 收窄测试：合法结果、非法 JSON、缺字段、错误 frameId、重复 overlap 和模型输出超长。
3. 实现按批次顺序的视觉识别；每个请求包含宫格索引、全局帧范围、时间范围、阅读顺序和 overlap 说明。
4. 实现最终汇总调用；输入只包含结构化批次结果和用户要求，输出去除 Markdown 包装后的纯提示词。
5. 编写取消、视觉请求失败、汇总失败和错误阶段记录测试；不得无限自动重试。

### 阶段 D：Agent 工具与任务 IPC

1. 增加资产列表、视频预检、准备宫格、联合识别、汇总和取消工具的协议注册；优先扩展已有 Canvas 工具，不创建重复的文件读取工具。
2. 将工具实现绑定到 task/plan ID 和当前画布授权上下文，拒绝任意绝对路径、未授权 assetId 和多个未确认输入。
3. 增加专用 Agent Prompt，使 Agent 先读资产列表和元数据，再调用受控媒体工具；明确“多张宫格同一次请求”和“不能臆造音频内容”。
4. 增加独立 IPC 注册器和事件转发；接入现有 Canvas task lifecycle、AbortController、任务详情和诊断。

### 阶段 E：画布节点和面板

## 7. 验收标准

### 功能验收

- 用户可以从画布视频资产列表选择唯一视频，并填写反推要求。
- Agent 能读取资产列表并规划任务，但不能访问授权范围外的文件。
- 面板能显示时长、预计帧数、宫格数、批次和调用次数。
- 关键帧在宫格中按左到右、上到下编号，模型能收到对应的全局帧号和时间戳。
- 每个识别批次至少携带两张有序宫格图；长视频批次之间有明确 overlap。
- 最终提示词包含动作时间线和连续性，且不会把模型不确定内容写成确定事实。
- 成功后创建文本资产、文本节点和正确的 `generated` 血缘；失败或取消不会创建伪成功产物。

### 安全与可靠性验收

- 视频输入、路径、URL、模型、图片附件和任务 ID均经过协议与运行时双重校验。
- 不支持视觉或多图输入的模型无法提交任务。
- FFmpeg/ffprobe 不可用时显示可执行的环境提示，不伪造抽帧结果。
- 取消能终止 FFmpeg 和后续视觉调用，并最终进入 `cancelled`。
- 任务失败能定位到 `probing`、`sampling`、`composing`、`analyzing_batch` 或 `synthesizing` 等阶段。
- 日志、任务快照和错误摘要不包含 API key、Authorization、Cookie、完整 base64 或敏感 URL。
- 不删除用户可见文件，不覆盖其他 Agent 的并行改动。

### 回归验收

- 图片反推仍然只接受一张图片，并继续复用现有 vision 附件协议。
- 既有文本生成、媒体任务、视频工作台抽帧和画布任务取消测试通过。
- 相关 renderer typecheck、主进程测试、协议测试和短视频集成测试通过。

## 8. 风险与处理策略

| 风险 | 处理 |
|---|---|
| 模型多图上限不完整 | 能力字段缺失时阻止执行；不使用图片生成的 maxImages 代替 |
| 宫格压缩导致细节损失 | 采用固定 4×3、保持宽高比、保留编号和时间戳；后续可增加用户主动导出单帧复核，不在第一版逐帧调用 |
| 长视频请求过多 | 60 秒默认提醒、180 秒硬上限、120 帧硬上限、面板显示预计成本和调用次数 |
| 跨批次动作不连贯 | 同一次请求发送连续多张宫格图；批次之间重复上一批末张宫格并在结构化结果中记录 continuity |
| Agent 自由度过高 | 只暴露画布资产和领域工具；工具绑定授权上下文、任务 ID和模型能力校验 |
| FFmpeg 可选依赖不可用 | 预检阶段明确显示缺失；复用现有安装/能力提示，不在任务中静默降级为低质量方案 |
| 并行 Agent 修改共享入口 | 开发使用 worktree 和文件所有权；提交前检查工作树、diff 和预期符号范围 |

## 9. 交付顺序

按以下顺序合并，确保每一阶段都能独立验证：

1. 协议、schema、采样和批次规划。
2. 宫格合成与主进程运行时。
3. 多图视觉调用、结构化结果和最终汇总。
4. Agent 工具桥、任务 IPC、取消和产物回写。
5. 画布操作节点、配置面板和 UI 状态。
6. 真实短视频验收、回归检查和文档更新。

本计划只定义开发范围和验收门槛；开始编码前仍需重新读取当前源码、对实际待修改符号做影响分析，并根据并行工作树调整具体文件拆分。
