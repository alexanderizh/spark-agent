# 服务端上传文件定时清理需求（edu-server /upload）

> 状态: 已落地（生产桶已创建并验证，待 .env 配置 + 重启生效） | 最后核对: 2026-08-29

## 背景

桌面端（Spark-Agent）的媒体生成链路会把本地素材上传到 Spark 平台，作为第三方媒体渠道（xAI / 火山方舟 / MiniMax / APIMart / 百炼）的公网 URL 中转：

- 接口：`POST {baseUrl}/api/v1/upload`（multipart 字段 `file`，Bearer token）
- 客户端链路：`SparkMediaUploader` → `AuthService.uploadFile` → `EduServerClient.uploadFile`
- 原实现：文件落 MinIO 主桶 `edu-prod/uploads/` 前缀，永久保留，存储量随使用无界增长

## 最终方案：临时桶 + MinIO Lifecycle（替代最初设想的 DB 记录 + 定时任务）

**方案变更说明**：本文件初稿设想「/upload 落库 expires_at + 每小时定时任务删过期记录」。调研 edu-server 后发现 `/upload` 本来就不写任何数据库记录，且服务端已存在更优机制（commit `31d444c0`）：`?tmp=1` 上传到独立临时桶，**整桶由 MinIO Lifecycle 自动过期**（`MINIO_TMP_RETENTION_DAYS`，默认 15 天）。桶生命周期由 MinIO 原生执行，无需应用层定时任务、无 DB 写入，遂废弃原设想。

### 链路分工

| 层                    | 机制                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| 客户端（Spark-Agent） | `purpose='media-transfer'` 的上传自动以 `?tmp=1` 调用 `/upload`（`EduServerClient.rawUpload`） |
| 服务端（edu-server）  | `?tmp=1` 落临时桶；启动时 `ensureTmpBucket()` 幂等建桶 + 公开读策略 + 整桶 Lifecycle 过期规则  |
| MinIO                 | Lifecycle 到期自动删除对象（默认 15 天，`MINIO_TMP_RETENTION_DAYS` 可调，重启服务即刷新规则）  |
| 本地缓存              | 客户端对中转 URL 缓存 6 天（`SparkMediaUploader`），始终短于服务端保留期                       |

### 本次落地的改动（2026-08-29）

**edu-server：**

- `?tmp=1` 在临时桶链路未就绪（未配桶名，或 `AI_TMP_STATIC_URL`/`BASE_TMP_STATIC_URL` 均未配）时，从返回 400 改为**告警日志 + 回退主桶上传**——修复原注释与代码矛盾，并消除「桶已配但访问基址未配 → 返回指向主桶的 404 URL」的隐患（`StorageService.tmpUploadReady()`）。
- 临时桶上传**跳过 sharp 压缩**：临时桶文件是交给第三方模型消费的中间态（生成参考图、音视频），2048px JPEG 重压缩会无声降质参考素材；主桶（用户可见文件）行为不变。
- `.env.example` 补齐临时桶配置说明与生产示例。

**Spark-Agent：**

- 删除上一轮加的 `purpose`/`expires_after_seconds` multipart 字段（服务端从不消费），改为 `purpose='media-transfer'` → `?tmp=1` query。
- `isEduUploadAssetUrl` 扩展：同时匹配主桶回退形态与临时桶形态（桶名含 tmp），画布 inspector 提示条两种形态都能命中。

## 运维待办（生产上线前必须）

**生产桶 `edu-prod-tmp` 已于 2026-08-29 在生产 MinIO 实例创建并验证完毕**：匿名公开读策略、整桶 15 天 Lifecycle 过期均已生效，`https://www.yiqibyte.com/edu-prod-tmp/...` 与 `https://minio.yiqibyte.com/edu-prod-tmp/...` 两条公网路由实测 200（openresty 通用 path-style 转发，无需改 nginx）。

服务器 `.env.prod`（不在仓库，运维手工维护）需增加以下变量，并部署包含上述改动的版本后重启 edu-server：

```ini
MINIO_TMP_BUCKET_NAME=edu-prod-tmp
MINIO_TMP_RETENTION_DAYS=15
BASE_TMP_STATIC_URL=https://www.yiqibyte.com/edu-prod-tmp
AI_TMP_STATIC_URL=https://www.yiqibyte.com/edu-prod-tmp
```

未配置时无功能损失：客户端 `?tmp=1` 自动回退主桶（文件永久保留，即现状行为），服务端有告警日志可观测。

## 兼容性影响

| 场景                           | 影响                                                    |
| ------------------------------ | ------------------------------------------------------- |
| 新客户端 + 服务端未升级/未配置 | `?tmp=1` 被旧服务端忽略，走主桶永久保留，行为与现状一致 |
| 新客户端 + 服务端已配置        | 中转文件落临时桶，15 天自动清理                         |
| 旧客户端 + 新服务端            | 不带 `?tmp=1`，主桶永久保留，无影响                     |
| 存量文件                       | 无 purpose 标记、位于主桶，一律永久保留，不追溯清理     |

## 明确的边界

- **禁止**给主桶 `edu-prod` 配置整桶 Lifecycle：会连头像、用户资产等永久文件一起清掉；只允许临时桶整桶过期。
- 临时桶保留期调整后重启 edu-server 即可（`ensureTmpBucket` 幂等刷新 Lifecycle 规则）。
