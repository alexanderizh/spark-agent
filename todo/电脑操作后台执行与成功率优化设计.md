# 电脑操作（Computer Use）后台执行与成功率优化设计

> 状态: 已落地（代码完成+测试通过，待用户真机验收）| 最后核对: 2026-08-29

## 1. 问题定义

用户反馈两个核心痛点：

1. **强制前台**：被操作的应用必须在前台聚焦，agent 一执行动作就抢走用户正在使用的窗口焦点；用户一动鼠标键盘就触发 takeover，任务直接中断（handoff_required）。
2. **成功率低**：动作频繁失败（focus_mismatch / stale_frame / action_noop），很难完成一个完整任务。

### 1.1 用户期望的形态

"像其他 agent 一样，屏幕共享 + 辅助操作协作：被操作应用不在前台也能观察界面，并通过多种方式完成输入和点击。"

## 2. 根因分析（代码级）

### 2.1 架构现状

三层链路：`ComputerTaskOperator`（决策循环）→ `ComputerControlBroker.dispatch`（治理转发）→ native host（SparkComputerHost，Swift）。

关键事实：**Broker 层 dispatch 已明确不检查前台**（`ComputerControlBroker.ts:324` 注释），前台强制完全发生在 native host 层。

### 2.2 观察层已经不要求前台（无需改）

- 截图：`MacScreenCaptureProvider.captureObservedWindow` 用 ScreenCaptureKit `SCContentFilter(desktopIndependentWindow:)`，可捕获**非前台、被遮挡**的窗口（最小化除外）。
- 结构树：`MacAccessibilityController.observe` 用 AX API 遍历，不需要目标前台；且已做 Chromium `AXManualAccessibility` 运行时激活。

### 2.3 执行层是瓶颈：坐标/键盘动作全部走全局 HID 注入

- 通道分配（`packages/protocol/src/computer-use/action.ts:238` `computerExecutionLaneForAction`）：
  - `background_semantic`（AX 直操作，不要求前台）：仅 `invoke_element` / `set_value` / `select_text` / `app_command` 四种。
  - `foreground_input`（全局 CGEvent 注入）：`click` / `move` / `drag` / `scroll` / `keypress` / `type_text` —— **模型最常产出的动作全部在此通道**。
- 前台强制的直接代码（`MacScreenCaptureProvider.swift` executeAction）：

  ```swift
  if envelope.executionLane == .foregroundInput && !before.descriptor.focused {
      _ = try focusWindow(processID: before.processID)   // activate + AXRaise，抢用户焦点
  }
  ```

- 事件注入机制（`MacCGEventController.postTagged`）：`event.post(tap: .cghidEventTap)` 注入**系统全局 HID 事件流**，事件按焦点路由，只能到达当前聚焦窗口。这是"必须前台"的根本机制——不是权限问题，是通道选择问题。
- Windows 端同样：`windows_host.rs:167` 要求 `target.foreground`，坐标输入前 `focus_window`（L640-645）。

### 2.4 成功率低的叠加因素

| #   | 因素                                                                                                                      | 位置                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 1   | 每个动作（及 drag 每一步、文本每个 chunk）都全量 `listWindows` + SecCode 签名校验，窗口 Z 序/焦点抖动即 `focus_mismatch`  | `validateTarget` 闭包                |
| 2   | `frameID`/`treeVersion` 严格匹配；AX observer 对任何界面变化（动画、光标闪烁）markDirty → `stale_frame`/`stale_tree` 频发 | executeAction 前置校验               |
| 3   | 用户物理输入即 takeover → `handoff_required` 终止任务（前台通道下用户和 agent 互斥使用键鼠）                              | `MacUserInputMonitor`                |
| 4   | `keyCode` 表符号不全（`~!@#$%^&*()_+{}:"<>?` 等需 shift 组合的键缺失 → 直接 `action_not_allowed`）                        | `MacCGEventController.keyCode`       |
| 5   | AX 树为空的应用（Canvas、游戏、自绘 UI）只有截图 + Vision OCR 文本，无结构，坐标点击命中率天然低                          | `accessibilityOrVisualTree` 视觉回退 |
| 6   | 决策提示词只在失败后提示换方式，没有引导模型优先用 elementId 语义动作                                                     | `computer-use-system-prompt.ts`      |

### 2.5 "别的 agent 是怎么做到的"——技术真相

macOS 上不要求前台的 GUI 自动化只有一条成熟路径：**AX（辅助功能）语义操作**（`AXPress` / `AXSetValue` / `AXPick` / `AXScroll*` 等）。这些 API 直接对目标进程的 UI 元素生效，不经过窗口服务器的焦点路由，因此不需要前台、不需要窗口可见、与用户物理输入完全并行。业界"屏幕共享 + 辅助操作"的产品形态 = 窗口捕获（观察）+ AX 语义操作（执行）+ 前台事件注入（兜底）。

本项目观察层已对齐，执行层的 AX 通道只开了窄口（4 种语义动作），**差距就在：坐标类动作没有被翻译成 AX 后台操作，而是全部落到全局 HID 注入**。

## 3. 改造方案

总体思路：**把 AX 通道从"窄语义口"扩展为坐标动作的默认执行引擎，前台 CGEvent 降级为兜底**。改动集中在 native host，协议层向后兼容微调。

### Phase 0（核心）：坐标动作后台 AX 化 — macOS host

新增「坐标 → 元素命中」后台执行通道：

1. **几何命中测试**：模型给出归一化坐标 → 映射到目标窗口 AX frame 全局坐标（无需前台）→ 在已缓存 AX 树的元素 bounds 中做包含测试，取包含该点、面积最小、支持可执行动作的元素。
   - 不用 `AXUIElementCopyElementAtPosition`（它按屏幕 Z 序命中，目标被遮挡时会命中遮挡窗口的元素）；用自有树几何命中**不受遮挡影响**。
2. **动作翻译**：
   - `click` → 命中元素 `AXPress`（或 `AXConfirm`/`AXPick` 按可用动作选择）。
   - `scroll` → 命中滚动容器执行 `AXScroll*` 系列动作。
   - `type_text` → 命中/AX 聚焦元素 `AXSetValue`。
   - `move`/`drag`/`keypress` → 不做后台化（hover/拖拽/快捷键依赖真实事件流），保留前台通道。
3. **自动降级**：命中失败（树为空、无可执行动作、AX 超时——后台 app 可能被 AppNap 限速，已有 2s messaging timeout）→ 回退现有前台 CGEvent 路径，行为完全向后兼容。
4. **解除后台通道的前台约束**：走 AX 通道的动作不再强制 `focusWindow`，不再逐步执行全局 `validateTarget`（后台 AX 不触碰用户输入流，无需用户输入静默检查；takeover 监控仅保留给前台通道）。
5. **通道透明化**：`NativeActionStatus` 扩展实际执行通道字段（`background_ax` / `foreground_cg`），经 observation 回传，写入 `recentActions` 与 `ComputerUseMetricsCollector` 指标，用于统计后台执行占比与两通道成功率。

落地方式（最小协议改动）：`executionLane` 枚举与校验不动（仍表示动作的保证级别），host 在 `foreground_input` envelope 上自主尝试后台 AX 执行、失败降级前台。TS 层仅透传通道回报字段（optional，向后兼容）。

### Phase 1：前台兜底的体验优化 — 焦点租约

必须前台的动作用「租约」模式把打扰降到最低：

1. 记录当前前台应用 → `focusWindow`（目标）→ 执行 → 恢复原前台应用。
2. 做成会话级策略开关（默认开启；用户明确要"看着我操作"的场景可关）。
3. 前台期间 takeover 语义保留（安全边界不变）。

### Phase 2：成功率专项

1. **keyCode 表补全**：shift 组合符号全量映射，消除 `action_not_allowed` 硬失败。
2. **校验轻量化**：动作执行中的 `validateTarget` 从"全量 listWindows + 签名校验"降为"windowID + bounds 缓存比对"，签名校验保留在会话绑定建立时一次性完成。
3. **stale 容忍**：窗口身份未变时，host 端 treeVersion 不匹配自动重新取树并重试一次（broker 侧 `relocateStaleFrame` 已有对应逻辑，补齐 host 侧对称路径）。
4. **决策提示词**：引导模型优先选择 elementId 语义动作（`invoke_element`/`set_value`），坐标点击作为树不可用时的次选，而非等失败后回退。
5. **type_text IME 兼容**：后台 `AXSetValue` 优先可绕开大部分 IME 拦截问题；前台回退路径中 `postUnicode` 遇 IME 激活时的行为单独验证。

### Phase 3：Windows 端对齐（后续）

Windows UI Automation 天然支持后台 `Invoke`/`SetValue`（`uia.rs` 已有语义通道），按 Phase 0 同样思路把坐标点击翻译为 UIA 元素命中 + `Invoke`，解除 `windows_host.rs` 的前台强制。

## 4. 风险与边界

| 风险                                                                                                | 评估 | 对策                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AXPress` 与真实鼠标事件语义差异：依赖 mousedown/mouseup 细节的组件（自绘 UI、部分 web 组件）不响应 | 中   | 命中失败/noop 自动降级前台通道；指标监控两通道成功率差异                                                                                                    |
| 后台窗口进程被 AppNap 限速导致 AX 调用超时                                                          | 低   | 已有 2s messaging timeout，超时即降级前台                                                                                                                   |
| 后台操作对用户不可见，误操作感知弱                                                                  | 中   | policyContext 敏感应用/secure field 拦截已有；timeline 记录补执行通道字段；前台/后台通道策略一致性由 policy 层保证（policy 基于动作类型而非通道，不受影响） |
| 最小化窗口：截图无帧（ScreenCaptureKit 限制）                                                       | 已有 | 观察层已有捕获失败处理路径；AX 树对最小化窗口通常仍可读                                                                                                     |
| 后台 `AXSetValue` 覆盖 contentEditable 等复杂输入框的能力                                           | 中   | settable 检查已有；不可 settable 即降级前台                                                                                                                 |

## 5. 验证方式

1. **单元测试**（Swift，复用 `SparkComputerHostCoreTests` 基建）：
   - 几何命中纯函数（树命中、最小面积选择、边界坐标）。
   - 通道选择逻辑（AX 可用/不可用/超时的降级路径）。
   - `NativeHostRequestHandlerTests` 补通道回报字段断言。
2. **指标验证**：`ComputerUseMetricsCollector` 增加执行通道维度，对比改造前后 `focus_mismatch`/`stale_frame`/`handoff_required` 发生率与后台通道执行占比。
3. **真机验收**：由用户手动完成（约定：agent 不得以自动化或隔离实例宣称通过）。验收场景：
   - 目标应用置于后台/被遮挡，执行点击、输入、滚动，全程不抢焦点、不中断用户当前操作。
   - 无 AX 树的应用（Canvas/游戏类）自动降级前台且行为与现状一致。
   - 敏感应用（密码管理器等）拦截与 secure field 保护不回退。

## 7. 实施与验收记录（2026-08-29）

### 7.1 交付概况

Phase 0+2 由 ZCode 完成初版，阿杜复核审查后修复 3 处缺陷。关键新增文件：
`NativeAXHitTest.swift`（几何命中+后台策略+shift 符号表的纯函数）、`NativeBackgroundAXPolicyTests.swift`。

实现要点与设计一致：自有树几何命中（禁用 `AXUIElementCopyElementAtPosition`）；click/scroll/type_text 后台 AX 化，move/drag/keypress 保留前台；命中失败/AX 超时自动降级前台 CGEvent；`sensitiveInputBlocked`/`sessionCanceled` 不降级直接上抛；后台通道不再 focusWindow、takeover 监控仅前台；`resolveActionBinding` 窗口身份不变时容忍 stale 版本自动重取树一次；`validateTarget` 轻量化为 CGWindowList 的 windowID+bounds 比对（SecCode 校验保留在会话绑定建立时）；keyCode 补全 shifted 符号映射；`executionChannel` 经 wire/recentActions/指标全链路透传（字段 optional，旧 host 字节兼容）。

### 7.2 审查确认并已修复的缺陷

1. **TS 编译错误 TS2540**（`ComputerUseMetricsCollector.ts`）：对 readonly `share` 字段二次赋值。vitest 不做类型检查所以 ZCode 的测试全绿但 `tsc -p` 构建必挂。已改为构造时一次性计算（先汇总 total 再建数组）。
2. **通道归因错误**（`MacScreenCaptureProvider.swift`）：`backgroundSemantic` 通道的语义动作（invoke_element/set_value/select_text）实际走 AX 后台执行，却被标为 `foreground_cg`，后台执行占比被低估；`wait_for`/`observe` 等被动动作也会进前台成功率分母。已改为：语义动作标 `background_ax`，被动动作不报通道；backend 仅在 host 回报通道时记入通道指标。
3. **指标不可观测**：`executionChannelSnapshot()` 采集后无任何消费方。已接入 `ComputerUseNativeHostDiagnostics` 报告（协议 `ComputerUseNativeHostDiagnosticReport.executionChannels` optional 字段，旧报告兼容）。

审查中撤销一个疑似缺陷：type_text 后台路径"未用坐标命中元素"——经复核 `type_text` 协议本身不含坐标（`{type, text, sensitive?}`），坐标命中无从谈起，聚焦元素是唯一可实现语义，精确输入应走 `set_value`（提示词已引导）。属设计文档「命中/AX 聚焦元素」表述含混，非实现缺陷。

### 7.3 postUnicode IME 行为代码级结论（Phase 2 第 5 项）

前台回退路径 `postUnicode`（MacAccessibilityController.swift）以 virtualKey 0 + `keyboardSetUnicodeString` 向 HID 流投递文本事件，**不检测、不切换**当前输入源（无 TISInputSource 调用）。当 CJK 输入法激活且处于组合态时，事件可能被 IME 吞掉或进入组合缓冲，行为因应用/输入法而异，无法自动化验证——真机验收时需覆盖「中文输入法激活状态下前台回退输入」场景。缓解：Phase 0 的后台 `AXSetValue` 路径天然绕开 IME（不走键盘事件流），该场景首选后台通道。若真机确认前台路径 IME 吞字，再评估检测非 ASCII 输入源时强制走 AX/告警的加固（不自动切换用户输入源，避免侵入）。
