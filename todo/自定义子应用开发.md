# 自定义子应用开发

> 状态: 实施中 | 最后核对: 2026-08-17

## 1. 产品定位

自定义子应用是 SparkWork 内置的一套长期存储、可开发、可运行的应用能力，不是某个会话的附属物，也不是一次性的 Agent 产物。

子应用与会话完全解耦：会话只是操作入口，任何会话都可以在用户明确表达意图后创建、查看、修改、预览、发布或管理任意子应用。删除会话不影响子应用；只有删除子应用才进入应用级数据删除确认流程。

子应用至少包含以下长期资源：

- manifest：名称、图标、路由、入口、状态和版本引用；
- source code：应用源代码及其构建产物；
- config：应用配置和用户可编辑设置；
- data：应用业务数据；
- permissions：应用能力和数据访问权限；
- versions：草稿、已发布版本和历史版本；
- runtime state：启动、停止、运行实例和错误状态。

本阶段的质量目标不是“能加载一个 HTML 页面”，而是让本地子应用具备可长期使用的产品质量：数据可靠、状态可恢复、主题一致、权限可解释、运行可观测、窄屏和无障碍可用，并且一个应用的异常不能拖垮 Spark 主窗口或其他应用。

## 2. 已确认的产品边界

以下决策来自本轮需求确认，后续实现不得重新引入“开发会话绑定应用”的模型：

1. 子应用是独立、长期存储的资源，不与创建它的会话绑定。
2. 子应用开发与管理能力作为所有 Agent 可调用的内置工具 / Skill 存在。
3. `/spark-app-*` 命令只是强制触发子应用工具链的显式入口，不创建特殊会话，也不限制后续只能在当前会话中操作。
4. 用户在普通会话中明确要求开发或管理 SparkWork 内部子应用时，同样可以进入子应用能力链路。
5. “帮我写一个网页”等未明确指向 SparkWork 内部子应用的请求，继续按普通 Agent 任务处理。
6. 应用代码和配置的修改先进入草稿；发布产生不可变的新版本，不直接覆盖已发布版本。
7. 菜单只展示“已发布且已启用”的应用；应用运行状态与发布状态分开管理。
8. 应用在现有内容区打开，菜单负责展示和启动，不与某个会话的页面状态耦合。

## 3. 目标能力与接口草案

工具调用必须显式携带 `appId` 或经过明确解析的目标应用，不依赖当前会话隐式推断：

| 能力                                     | 作用                                  | 是否改变持久化状态 |
| ---------------------------------------- | ------------------------------------- | ------------------ |
| `spark_app_create`                       | 创建应用及初始草稿                    | 是                 |
| `spark_app_list`                         | 列出应用、状态和版本摘要              | 否                 |
| `spark_app_get`                          | 获取应用 manifest、配置和指定版本信息 | 否                 |
| `spark_app_update`                       | 修改草稿代码、配置、manifest 或权限   | 是                 |
| `spark_app_preview`                      | 启动草稿预览并返回预览状态            | 可能               |
| `spark_app_build`                        | 校验并构建草稿                        | 产生构建结果       |
| `spark_app_publish`                      | 将已通过检查的草稿发布为新版本        | 是                 |
| `spark_app_enable` / `spark_app_disable` | 启用或禁用应用                        | 是                 |
| `spark_app_start` / `spark_app_stop`     | 启动或停止运行实例                    | 是                 |
| `spark_app_rollback`                     | 将草稿或发布指针恢复到历史版本        | 是                 |
| `spark_app_archive`                      | 归档应用，使其退出常规菜单            | 是                 |
| `spark_app_delete`                       | 删除应用及其数据                      | 是，必须二次确认   |

接口设计要求：

- `appId`、版本号、操作类型和目标环境显式传递；不能使用当前会话 ID 代替应用 ID。
- 所有工具返回结构化状态、可读错误、变更摘要和下一步建议。
- 目标应用不存在、同名应用无法唯一确定或状态不允许当前操作时，阻止静默执行并要求选择/确认。
- `preview`、`build`、`publish` 的校验结果要可追踪，不能只返回一个布尔值。
- `publish` 必须记录源草稿版本、构建摘要、发布时间和发布结果。
- `delete`、`archive`、`disable` 等会影响可见性或数据的操作，必须遵守平台现有确认语义。
- 对重复调用提供幂等策略，避免 Agent 重试导致重复发布、重复启动或版本号错乱。

## 4. 渲染与运行时细化

### 4.1 应用入口与导航

- 增加稳定的应用内容区入口，目标形式为 `/apps/:appId`；最终路由命名以现有路由实现为准。
- 菜单读取应用目录，不从会话列表推导应用。
- 只向常规菜单暴露“已发布 + 已启用”的应用；草稿通过开发入口、预览入口或明确的管理操作访问。
- 切换会话、删除会话、重新打开工作台后，应用菜单和应用路由仍可恢复。
- 应用不存在、已归档、已禁用、版本不可用时显示明确的空态或错误态，并提供回到应用列表/管理入口。

### 4.2 运行表面与挂载模式

子应用不能只支持“内容区页面”一种形态。manifest 需要声明应用需要的运行表面，宿主负责解析权限、创建容器、分配层级和回收实例；应用代码永远不能自行决定把 DOM 插到宿主哪个节点。

| 运行表面        | 典型用途                           | 生命周期                   | 宿主控制重点                                           |
| --------------- | ---------------------------------- | -------------------------- | ------------------------------------------------------ |
| `content`       | 完整业务应用、表格、看板、编辑器   | 随应用路由挂载             | 内容区路由、尺寸、滚动、返回和版本                     |
| `panel`         | 侧栏工具、详情面板、快捷操作       | 随宿主面板开关             | 面板宽度、折叠、焦点、滚动和快捷键                     |
| `overlay`       | 当前窗口内的浮层、通知、快捷 Agent | 随主窗口常驻或按需唤起     | 专用 overlay root、遮罩、焦点陷阱、层级和点击穿透      |
| `global-window` | 跨页面悬浮助手、全局快捷工具       | 独立于当前路由，随应用启停 | 独立窗口边界、显示器/DPI、置顶、关闭和权限             |
| `desktop-pet`   | 桌面宠物、透明陪伴组件             | 可跨主窗口运行             | 透明窗口、位置记忆、点击穿透、拖拽、性能和系统级可见性 |

建议的 manifest 运行声明至少包括：`surfaces`、入口文件、最小/最大尺寸、默认位置、是否允许调整大小、是否允许拖拽、是否需要键盘焦点、是否允许点击穿透、是否允许系统级置顶、是否支持后台运行、窗口关闭后的实例策略和主题/语言/密度适配声明。

必须明确以下规则：

- `content`、`panel`、`overlay` 默认只能在 Spark 主窗口内运行；`global-window`、`desktop-pet` 需要单独的高风险能力授权和用户可见的启用状态。
- 同一个应用可以声明多个表面，但每个表面有独立的 `surfaceId` / `instanceId`；关闭一个浮层不能误停主应用或其他实例。
- 宿主统一处理窗口边界、安全区、刘海/菜单栏避让、多显示器、缩放比例和最小窗口尺寸；应用只接收解析后的布局上下文。
- 应用可请求布局变化，但最终尺寸、位置、置顶和点击穿透由宿主裁决并可拒绝，避免应用遮挡系统确认框、权限弹窗或其他关键平台 UI。

### 4.3 渲染容器

需要从当前实现中确认并统一应用的渲染容器策略。`packages/shared/src/html-sandbox.ts` 和 `docs/design/chat-html-render-tool.md` 可作为安全构造参考，但 HTML 渲染工具是一次性内容预览能力，不能直接等同于可持久化、可调用平台 API 的子应用 runtime；尤其不能无条件复用其允许外部网络的 CSP。

重点核对：

- 草稿预览与已发布运行是否使用同一套入口和资源解析规则；
- 应用代码是否始终运行在受控 iframe / 独立运行容器中，是否经过显式能力授权才能访问宿主 API；
- 应用之间是否严格隔离 DOM、存储、消息通道和运行实例；
- 刷新、路由切换、窗口关闭和应用停止时，运行实例及资源是否正确清理；
- 构建失败、入口缺失、资源加载失败、运行时异常和超时是否能被用户看见；
- 窄窗口、长内容、加载中、空数据、无权限和错误页面是否具备完整 UI 状态。

运行容器基线：

- 不向应用暴露 Electron Node 集成、宿主 `window`、主窗口 DOM、任意 IPC 或内部路径；应用只能使用版本化的 `Spark App Bridge`。
- 默认使用不透明 origin 的 sandbox iframe，禁止 `allow-same-origin`、顶层导航、任意弹窗、下载、表单提交和嵌套 frame；需要放宽某一项时必须有单独能力和审计记录。
- CSP 默认采用应用自身资源包和能力 allowlist；网络、文件、媒体、剪贴板、通知、系统窗口等能力都按声明逐项开放，不以“开发模式”绕过正式边界。
- 应用异常、卡死、超时和资源超限必须由宿主捕获并展示可行动的错误状态；不能因为 iframe 内部异常让整个 Spark 主窗口失去响应。
- 应用静态资源、缓存和运行时消息按 `appId + versionId + instanceId` 隔离；发布版本的资源哈希和入口清单必须可核对。

### 4.4 主题、Design Token 与宿主视觉适配

子应用必须适配 SparkWork 当前主题系统，而不是自带一套与平台冲突的颜色和组件基线。适配对象包括浅色/深色、高对比度（如平台支持）、字体、字号密度、圆角、间距、阴影、动效偏好、滚动条和系统安全区。

建议将主题桥分成三层：

1. **宿主解析层**：由平台统一解析当前 `resolvedTheme`、主色、字体、密度、`prefers-reduced-motion`、语言和系统缩放；应用不能自行读取或修改宿主设置存储。
2. **语义 token 层**：通过只读的 `--spark-*` CSS 变量和主题快照提供背景、表面、边框、文字、强调、危险、成功、警告、焦点环、间距、圆角、字体和层级等语义值；应用组件只能消费 token，不依赖 antd/Lobe 私有变量。
3. **应用组件层**：应用定义自己的组件尺寸和布局，但必须基于语义 token，并提供浅色、深色、窄屏、键盘焦点、禁用、加载、空态和错误态；应用自定义品牌色只能作用于应用边界内。

主题桥需要支持：

- 不重载整个应用即可响应主题、字体、密度和 reduced-motion 变化；主题变化通过版本化事件或 `MessagePort` 推送，并带 `appId`、`instanceId` 和 token 版本。
- 宿主 token 缺失或版本不兼容时有稳定 fallback；不能出现白底黑字、透明文字、低对比度按钮或弹层层级错乱。
- 应用自己的 CSS 只能作用于应用容器/iframe 文档；不能修改宿主 `html`、`body`、全局 token 或其他应用的样式。
- 主题预览、已发布运行、独立全局窗口和桌面宠物使用同一套语义来源；独立窗口不能因为脱离主 renderer 而回退到硬编码主题。
- 设计 token 建立兼容版本、必需字段、可选字段和废弃策略；升级宿主主题时保留旧版本应用的可渲染能力。

实现时优先复用 `apps/desktop/src/renderer/design/styles/styles.css` 的语义变量来源、`LobeThemeProvider` 的 resolved theme 逻辑和现有外观设置；不能把某个页面的私有 Less 选择器直接暴露为公共 API。

### 4.5 DOM 沙箱、顶层浮层与焦点治理

“应用需要浮在平台界面顶层”不等于“应用可以访问或改写平台 DOM”。顶层能力应由宿主提供受控挂载点，应用仍在隔离容器中渲染：

- 主窗口内的 `overlay` 统一挂到宿主专用 overlay root，采用平台登记的层级区间（普通浮层、应用浮层、确认/权限浮层、系统提示各自隔离），禁止应用自行写任意超大 `z-index` 抢占平台 UI。
- overlay root 不受页面 `overflow`、`transform`、局部 stacking context 影响；宿主负责与 Git 面板、Toast、Modal、权限弹窗、命令面板等现有顶层组件排序，避免遮罩之上/之下错误。
- 每个浮层声明 `modal`、`dismissible`、`clickThrough`、`captureKeyboard` 和 `escToClose` 等行为；模态浮层必须有焦点陷阱、恢复焦点和屏幕阅读器语义，非模态浮层不能吞掉宿主快捷键。
- 点击穿透只能作用于明确的透明区域或 idle 状态，不能让鼠标事件穿透到危险操作；拖拽区域由宿主声明并过滤，不能把整块窗口误设为不可交互。
- 应用不能直接调用 `document.body.appendChild`、`window.top`、宿主 `querySelector` 或依赖宿主节点 class；宿主只提供有限的能力组件和消息 API。
- 应用卸载、版本切换、窗口关闭和异常终止时，必须清理监听器、定时器、MessagePort、portal、焦点锁和窗口句柄，不能留下幽灵浮层或全局快捷键。

全局应用分两类实现：

- **主窗口 overlay**：适合右下角快捷 Agent、通知、轻量工具。与主窗口共享宿主状态，但仍使用应用 iframe 和 `Spark App Bridge`；主窗口关闭即停止或按 manifest 策略转为独立窗口。
- **独立 global window**：适合跨页面工具或桌面宠物。使用独立、最小权限的窗口壳，显式管理透明、置顶、显示器边界、DPI、位置持久化、系统休眠和关闭行为；不得因为“全局”而获得文件系统、任意网络或 Node 权限。

桌面宠物还需要专门处理：暂停/降频、低电量或系统性能保护、点击穿透切换、键盘无障碍入口、屏幕录制/隐私提示、窗口位置越界恢复和用户一键停止所有全局应用。

### 4.6 预览、运行与发布

预览和生产运行必须明确区分：

```text
草稿代码 / 配置
    ↓ preview
受控预览实例（可调试，不改变已发布版本）
    ↓ build
构建产物 + 校验报告
    ↓ 用户确认 publish
不可变发布版本
    ↓ start
应用运行实例
```

- 预览默认指向草稿，不能误展示旧的已发布版本。
- 运行实例必须记录 `appId`、版本号、实例 ID、启动时间、当前状态和最近错误。
- 停止实例后，晚到的事件、定时器、订阅和消息监听不得继续影响应用。
- 发布失败不得移动当前发布指针，也不得损坏现有可运行版本。
- 回滚优先切换到已验证的历史版本；回滚前后的指针变化和运行实例重启行为必须可见。

### 4.7 功能质量与运行可观测性

本地应用以功能质量优先，不能只完成“能打开一个页面”。每个应用运行表面都需要具备：

- 加载骨架、空数据、无权限、离线/资源不可用、运行异常、版本不兼容和恢复操作；错误信息要指出阶段、实例和可执行下一步。
- 首次加载、切换表面、主题切换、数据查询、保存和发布的状态反馈；长任务使用可取消、可重试且不重复提交的任务模型。
- 应用级日志、性能摘要和错误事件，默认脱敏并按 `appId + instanceId + versionId` 关联；日志不能泄露宿主密钥或其他应用数据。
- 后台应用的资源预算、可见性降频、重复订阅去重和异常实例回收；一个应用不能拖慢主窗口或阻塞其他应用。
- 键盘导航、焦点可见、屏幕阅读器标签、触控/鼠标操作、窄窗口和高缩放下的可用性；真实验收不能只看默认宽屏正常态。

## 5. 持久化与版本模型

实现时优先复用项目现有持久化层和迁移机制，不新增与现有平台数据平行的隐式存储。建议按以下关系核对现有模型：

```text
SubApp
├── identity / manifest
├── draft
│   ├── source snapshot
│   ├── config snapshot
│   └── validation/build result
├── releases[]
│   ├── immutable source/config snapshot
│   ├── build artifact
│   └── publish metadata
├── data namespace
├── permissions
└── runtime instances[]
```

必须满足：

- 草稿修改不改变历史发布版本；
- 发布版本可独立读取、预览和回滚；
- 应用数据默认按 `appId` 隔离，不能因版本切换而意外丢失；
- 保存、发布、回滚和删除具有原子性或可恢复失败语义；
- 应用目录、版本目录和运行状态重启后可以恢复；
- 旧数据或字段缺失时提供兼容迁移，不以静默重置代替迁移；
- 删除前明确列出将受影响的代码、配置、版本、数据和运行实例。

应用数据需要与应用代码版本解耦：

- 默认提供 `kv`、结构化 `collection`、文档/资源引用三类存储；具体类型以现有 storage 能力为准，不允许每个子应用自行创建 SQLite、IndexedDB 或隐式文件目录作为第二套事实来源。
- 数据记录带 `appId`、命名空间、schemaVersion、revision/etag、更新时间和来源；应用代码只能访问自己的命名空间。
- 草稿预览默认使用隔离的临时数据或显式测试数据集，不能把预览写入生产数据；正式运行才使用应用正式数据命名空间。
- schema 升级必须有可重复执行、可回滚或可恢复失败的迁移记录；版本回滚不能盲目把新数据按旧结构覆盖。
- 删除应用前给出数据量、集合、文件引用、备份/导出状态和运行实例影响范围；应用归档只改变可见性和启动策略，不自动删除数据。

## 6. 平台能力与 Agent 路由

### 6.1 两种触发方式

```text
明确 /spark-app-* 命令
        ↓
明确要求开发或管理 SparkWork 内部子应用
        ↓
普通 Agent 任务
```

命令解析需要覆盖：创建、列出、修改、预览、构建、发布、启用、禁用、启动、停止、回滚、归档和删除；自然语言路由需要识别“内部子应用 / 我的某个应用 / 发布某应用”等明确指向。

路由验收重点：

- 命令优先级高于普通任务路由，但不能跳过权限、参数和破坏性操作确认；
- 普通自然语言只有在“内部子应用”意图足够明确时才进入应用工具链；
- 指定名称无法唯一映射时列出候选，不静默选择；
- 切换会话后仍能通过 `appId`、名称或菜单找到相同应用；
- Agent 不应把普通网页代码、附件或一次性文本产物自动注册成子应用。

### 6.2 平台接口边界

应用工具应通过平台统一服务访问应用目录、持久化、构建和运行时，不允许 Agent 直接绕过平台写数据库、改菜单或拼接宿主内部路径。需要补齐：

- 应用目录查询与状态过滤；
- manifest、草稿、版本和运行实例的读写协议；
- 构建/预览任务状态及事件回传；
- 应用级权限检查和调用审计；
- 跨会话继续操作的目标解析；
- 统一错误码、用户提示和可重试标记。

### 6.3 Spark App Bridge 协议

renderer 中的应用代码、主进程服务、Agent 工具和独立 global window 必须共用同一份版本化能力协议。建议每次请求至少包含：

```ts
{
  ;(protocolVersion, appId, versionId, instanceId, requestId, capability, operation, payload)
}
```

主进程不能信任应用自行传入的 `appId`、版本号或权限；这些字段必须由已签名/已解析的运行上下文和宿主实例绑定后再校验。响应需要统一携带 `requestId`、成功/失败状态、结构化错误码、是否可重试、当前 revision 和审计摘要。

Bridge 至少要具备以下能力域，实际开放以 manifest 权限为准：

| 能力域                        | 示例接口                                                | 默认策略                       |
| ----------------------------- | ------------------------------------------------------- | ------------------------------ |
| `runtime`                     | 获取应用上下文、监听生命周期、报告健康状态              | 只读/默认开放                  |
| `theme`                       | 获取主题快照、订阅主题/token 变化、读取字体/密度/语言   | 只读/默认开放                  |
| `ui`                          | 打开/关闭 surface、调整受限尺寸、请求焦点、通知、确认框 | 按 surface 权限                |
| `data`                        | KV、collection 查询/写入、事务、订阅变化、导入导出      | 仅本应用命名空间               |
| `navigation`                  | 打开应用路由、返回、打开受控平台页面                    | allowlist                      |
| `files`                       | 用户选择文件、读取/写入用户明确选择的资源               | 默认关闭，逐项确认             |
| `clipboard` / `notifications` | 复制文本、展示平台通知                                  | 默认关闭或按系统权限           |
| `agent`                       | 请求一次有界 Agent 操作、提交结构化上下文               | 默认关闭，必须用户可见         |
| `canvas` / `media`            | 读写授权的画布节点、调用多媒体任务                      | 默认关闭，按现有平台能力确认   |
| `browser`                     | 打开受控浏览器页面或提交受限导航                        | 默认关闭，不能取得任意宿主权限 |

所有能力都要定义输入上限、返回数据上限、超时、取消、并发、重试和敏感字段脱敏规则；不能只定义一个“万能 invoke”。能力协议还需要区分 `read`、`write`、`execute`、`global` 四类风险，供权限界面和审计使用。

### 6.4 应用数据的双向访问

应用数据不是只能由子应用自己读取的黑盒。平台和 Agent 需要在权限边界内访问同一套应用数据服务，才能支持“在任意会话中让 Agent 查询/修改我的记账数据”“平台导出应用数据”“多个平台入口观察应用状态”等真实场景。

数据访问方向应统一为：

```text
子应用 Bridge ─┐
               ├─> App Data Service ─> appId 命名空间 / schema / revision
Agent 工具 ────┘
```

建议补齐以下管理能力（名称可按现有工具命名调整）：

- `spark_app_data_schema`：查看 schema、字段、索引、迁移版本和兼容状态；
- `spark_app_data_query`：按 appId、集合、过滤条件、排序、分页读取，禁止 Agent 直接提交任意 SQL；
- `spark_app_data_get`：按稳定记录 ID 和 revision 读取单条数据；
- `spark_app_data_upsert` / `spark_app_data_delete`：带幂等键、乐观并发条件和影响摘要的写入/删除；
- `spark_app_data_export` / `spark_app_data_import`：带格式、范围、校验报告和冲突策略的备份迁移；
- `spark_app_data_changes`：按 revision/cursor 获取变更，供跨会话和多表面同步；
- `spark_app_data_inspect`：只读查看数据规模、健康状态、失败迁移和孤儿资源，不返回不必要的敏感正文。

双向访问必须满足：

- Agent 访问应用数据时显式携带 `appId`、命名空间、版本/快照或 cursor，不能因为当前会话曾打开过该应用就隐式扩大范围。
- 读数据默认遵守应用的数据权限；写入、删除、批量导入和跨命名空间操作显示影响范围并按平台确认语义执行。
- 应用运行时和 Agent 同时写入时使用 revision/etag 或事务检测冲突，返回冲突记录和可执行的合并/重试建议，不静默覆盖。
- 数据变更通过 `appId + namespace + revision` 广播给相关实例；应用被关闭或切换会话后，重新打开仍能从 cursor 恢复，而不是依赖内存事件。
- 平台可以读取应用数据，但不能把应用数据自动注入普通会话上下文；只有用户明确要求、应用授权或工具契约明确需要时才携带，并且对大字段和敏感字段做裁剪/脱敏。
- 导出、清空、批量删除、跨应用复制等高风险操作必须独立确认；删除会话、删除运行实例和禁用应用不应删除应用数据。

### 6.5 全局应用专用平台接口

为了支持右下角快捷 Agent、全局通知和桌面宠物，不能把 `global-window` 当成普通 `content` 路由加一个更大的 `z-index`。需要单独的受控接口：

- `surface.open/close`：申请或释放指定表面，返回宿主分配的 `surfaceId` 和实际状态；
- `surface.setBounds`：请求尺寸/位置变化，宿主进行显示器边界、安全区和最小尺寸校验；
- `surface.setVisibility`：显示、隐藏、最小化、后台运行，明确是否继续订阅数据；
- `surface.requestFocus` / `surface.setClickThrough`：焦点和点击穿透切换，必须受 manifest 和当前系统状态限制；
- `surface.setAlwaysOnTop`：仅对用户明确启用的全局应用开放，并能被全局设置一键关闭；
- `platform.openDialog` / `platform.notify`：复用 Spark 的主题、确认语义、焦点和层级，不允许应用自己画一个绕过平台确认的伪弹窗；
- `runtime.shutdown`：主动释放全局应用资源，平台退出、权限撤销和版本切换时也必须强制可用。

快捷 Agent 应用如果要读当前会话、发送消息或发起 Agent 运行，必须使用显式的 `session:read` / `agent:invoke` 能力，并让用户看见目标会话、发送内容、模型/Agent 和是否产生外部副作用；桌面宠物默认只能使用自身数据、主题和 surface 能力。

## 7. 权限与安全隔离

- 应用只能访问自身数据命名空间和声明过的宿主能力。
- 应用代码、配置、日志和错误展示中不得出现 Provider API Key、系统密钥或未授权文件内容。
- 宿主 API 必须按应用权限和调用来源校验，不能只依赖 renderer 传来的 `appId`。
- 应用之间的消息、存储、任务和运行实例必须隔离。
- 禁止应用通过路径拼接、任意脚本、未校验 URL 或隐藏 IPC 访问宿主任意文件和系统能力。
- 预览环境与正式运行环境都要执行同等的边界校验；开发模式不能成为生产权限绕过入口。
- 记录创建、修改、构建、发布、启停、回滚、归档和删除的审计摘要，敏感字段统一脱敏。
- 记录主题变化、surface 创建/销毁、置顶/点击穿透切换、平台数据读写、Agent 调用和文件/网络/媒体使用；审计事件关联 `appId`、版本、实例、能力和结果。
- 全局应用必须有独立的“运行中应用”管理入口，支持查看、暂停、停止、撤销权限和关闭全部全局 surface；应用不能通过后台重启或隐藏窗口绕过用户停止操作。
- 应用数据导出、Agent 读取和跨应用复制均按最小字段原则返回；日志、错误、通知和模型上下文不得默认携带完整业务数据。

- [ ] 进行至少一次“任意会话查询并修改应用数据”的端到端验收，确认 UI、Agent、Bridge 和持久化服务看到同一份结果。

## 9. 验收清单

### 功能验收

- [ ] 新建应用后可在任意会话中继续修改，不依赖创建会话。
- [ ] 草稿可预览、构建并在用户确认后发布。
- [ ] 已发布且已启用的应用出现在菜单，并能在内容区打开。
- [ ] 禁用应用后不再出现在常规菜单，也不能被普通启动操作拉起。
- [ ] 可启动、停止、回滚和归档应用，状态展示与真实状态一致。
- [ ] 应用数据与会话生命周期无关，删除会话不会删除应用。
- [ ] 在任意会话中，Agent 能按明确 `appId` 读取和修改应用数据；冲突时不会静默覆盖，变更能同步回已运行实例。
- [ ] 同一应用可按权限运行在内容区、侧栏或主窗口 overlay，实例互不误杀，主题和布局上下文一致。
- [ ] 右下角快捷 Agent 等全局应用可在主窗口内稳定显示，且不会遮挡平台确认/权限 UI。
- [ ] 桌面宠物在重启、显示器切换、DPI 变化和用户停止后都能恢复或退出，不产生幽灵窗口。

### 稳定性与安全验收

- [ ] 重复调用不会重复创建发布版本或产生孤儿运行实例。
- [ ] 构建/发布/运行失败时，当前可用版本和应用数据保持完整。
- [ ] 应用不能越权读取其他应用数据、宿主密钥或未授权文件。
- [ ] 预览、正式运行和 Agent 工具入口遵守同一套权限边界。
- [ ] 所有破坏性操作有明确确认和可核对的影响范围。
- [ ] 错误信息足以定位阶段，不使用无法行动的笼统兜底文案。
- [ ] 主题切换后应用无需重启即可正确更新；自定义应用样式不会污染宿主和其他应用。
- [ ] 运行时能观测到 surface、数据、Bridge、权限和 Agent 调用的成功/失败结果，且敏感字段已脱敏。

## 10. 暂不纳入本阶段

- 不把应用绑定到某个会话、Agent 或工作区临时状态。
- 不自动把普通网页开发任务注册成内部子应用。
- 不在没有权限协议和沙箱边界的情况下开放任意系统文件、网络或宿主 IPC。
- 不以覆盖已发布版本的方式实现快速修改；修改统一先进入草稿。
- 不为了补齐单个 UI 入口而复制一套独立的应用存储或运行时。
- 不把“全局显示”解释为允许访问主窗口 DOM、任意 z-index、Node/Electron 或绕过平台确认。
- 不默认开放全平台能力；文件、网络、Agent、画布、多媒体和浏览器能力必须按声明、确认和审计逐项开启。
