# 子应用分享与导入（App Share Package）

把子应用打包成单个 `.sparkapp` 文件分享，同平台的其他人可直接导入得到完整可用的
应用——**除 AI 渠道外完全一致**（源码、发布版本、数据、文件、权限、清单全部随包，
Provider/API Key 不随包，导入后使用导入方自己的渠道）。

## 分享包格式（v1）

单文件 `.sparkapp` = UTF-8 JSON（内容全为文本，免 zip；与仓库既有导出/导入范式一致）：

- `formatVersion: 1` — 不识别即拦截导入
- `appId / exportedAt / platformVersion` — 身份与兼容性提示
- `manifest` + `draft`（源码/config）+ `releases[]`（保留原版本号与发布时间）
- `publishedVersion` — 导入后发布指针优先指向它，缺失回退最高版本
- `data[]`（全命名空间）+ `files[]`（文件空间，UTF-8 文本）
- `capabilities` — 能力依赖清单（见下）
- `integrity { sha256, byteSize }` — 针对「不含 integrity 的包体 JSON」的哈希，
  拦截截断/误改（JSON.parse 保键序 + stringify 确定，可复现哈希原文；非对抗性签名）
- 任何密钥不进包：Provider Key 在系统 Keychain 不在导出范围；源码/data 值里疑似
  明文密钥仅做启发式提示（不含内容），包内保留原文以保证可用性

## 能力检查报告

子应用运行期直连宿主 IPC，不持久化依赖清单 → 导出时**静态扫描** draft + 全部版本
源码与 data 值：

- `ipcChannels`：`sparkApp.ipc.invoke/on('...')` 的静态可解析字面量（模板字符串等
  动态形式无法识别，已知限制）；导入时对照本机 `IpcSchemaRegistry` 键集，未识别的
  列 warning（覆盖率=有 schema 的通道）
- `providerRefs`：`provider:*` 通道与 `providerProfileId` 字面量 → 仅提示「用导入方
  自己的渠道」
- `secretHints`：启发式正则（sk- 前缀 / api_key|secret|token|password 赋值形态），
  报位置不报内容

导入前出完整报告：FORMAT_VERSION（error 拦截）｜INTEGRITY（error 拦截）｜
PLATFORM_VERSION（包版本更新→warning 可继续）｜IPC_CHANNELS｜SOURCE_RUNTIME_LIMIT
（源码超 260K 运行时文档上限 → 「可存不可跑」warning）｜SECRET_HINT｜
DATA_LIMIT（单条 >512KB → error）｜FILE_LIMIT（单文件 >2MB / 非法路径 → error）｜
DRAFT_EMPTY。

## 导入与重复导入

- 仓储层 `SubAppRepository.importApp` 单事务：清空同 id 全部关联行 → 插应用行
  （发布过=published 且导入即启用）→ 显式版本号插入 releases（`UNIQUE(app_id, version)`
  拦重复）→ data 重建（revision 从 1）→ 发布指针指向 publishedVersion/最高版本
- 文件空间：写临时目录 → 同卷原子目录交换（target→`.old-*`、tmp→target）→ DB 事务；
  DB 失败回滚目录，保证两边一致
- 冲突二选一：包内 appId 本机已存在 → 可**覆盖**（整体替换草稿/版本/数据/文件，
  覆盖前自动把本机当前应用导出为 `.sparkapp` 备份）或**作为新应用导入**（新 appId，
  撞名自动加「（导入）」后缀）；同名不同 id ≠ 同一应用，默认新应用导入不覆盖
- 导入成功后关闭该应用的运行中实例（旧源码不继续跑旧结构数据，重开即新版）
- body 全程留在主进程内存：preview 发 token（有界 4 条 / TTL 10 分钟），apply 凭
  token + sha256 取用；renderer 只接触摘要

## UI 入口

- 子应用管理页：卡片「更多操作」菜单 → 「分享导出」（可选是否带 data/文件空间）；
  header → 「导入」（选文件 → 预览/报告 → 覆盖或新建 → 成功回执含备份路径）
- Agent 工具（spark_app_export/import）留待 P2，不在本期

## 明确不做（防范围膨胀）

差量/选择性导入、云端链接分享、zip/二进制支持、跨平台版本迁移——全量语义最简单
可靠，等真实需求再说。

  导入服务端到端（打包→写盘→预览→覆盖/新建→备份）
- `pnpm typecheck` / `pnpm lint` 相关子集；真机冒烟（导出→导入→覆盖导入）待人工验收
