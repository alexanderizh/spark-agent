# 017 Spark CLI TUI 界面重构设计

> 状态: 待审阅 | 最后核对: 2026-08-27

本文档是对 spark CLI 终端界面的整体重构设计稿，**先审阅、后实施**。所有「现状」均对照当前代码（`src/tui/*`）与四张截图得出；所有「新设计」均给出可直接实施的渲染规则与 mock 线框。

---

## 1. 问题清单（现状诊断）

### P1 机器 ID 泄漏到界面（截图 2，用户明确点名）

当前模型选择器每行渲染为：

```
❯ * sparkwork:provider-1:gpt-host  SparkWork Test · openai-responses · [sparkwork]
```

状态栏第一个字段直接显示完整路由 ID `sparkwork:provider-1:gpt-host`；欢迎屏也显示 `模型 sparkwork:provider-1:gpt-host`。

问题：路由 ID 是内部寻址用的机器标识，对用户是纯噪声；协议名 `openai-responses`、来源标签 `[sparkwork]` 同样是实现细节。

### P2 欢迎横幅信息冗余（截图 1 红框部分）

当前 `WelcomeBox` 共 5 行：品牌行、`模型 <id> · <绝对路径cwd>`、空行、两行快捷键教学。红框标注的模型 ID + cwd 行不需要；快捷键教学行占 3 行价值密度极低。

### P3 对话区没有视觉语法（截图 3/4 对比 Claude Code 后的核心差距）

当前投影层（`projection.ts`）把所有事件压成同构的 `(text, tone)` 行，由 `Static` 逐行贴脸输出：

| 内容 | 现状渲染 | 问题 |
| --- | --- | --- |
| 用户输入 | `● 任务文本`（normal 白字） | 与 agent 正文同为白字，仅前缀符号不同，扫读时无法区分 |
| agent 正文 | 纯文本逐行，无渲染 | Markdown 完全不渲染：标题、列表、代码块原样输出 |
| 思考过程 | `▍ 思考 · <截成单行的全文>` 全量平铺 | 与正文抢注意力，长思考刷屏 |
| 工具调用 | `⏺ readFile({"path":"src/tui/app.tsx"...}) ✓ 12ms` | 参数以 JSON 60 字符截断，噪声大 |
| 消息间距 | 块与块之间 0 空行 | 整屏糊成一片，无分组 |
| turn 结算 | `· 完成 · 1 steps · 120 tok · $0.000` | 每轮固定出现，尚可但样式随意 |

### P4 输入区边框状态不分明

当前输入框：全宽圆角边框，**accent 色（品牌橙）常亮**——没有输入时也亮，导致「哪里在等你」和「哪里是品牌装饰」混在一起；高度随内容跳动（1 行内容时上下边框贴字，视觉过紧）；锁定态只把边框变灰 + 文案，不够醒目。

### P5 状态栏排版随意

`模型  权限:default  推理:auto  120 tok · $0.0000 · /help` —— 分隔符混用（两个空格与 `·` 并存）、字段无主次、`flexWrap="wrap"` 在窄终端会折成错乱多行。

## 2. 设计原则

1. **内容亮、铬件暗**（chrome dim, content bright）：用户视线应该落在对话内容上，一切非内容（状态栏、工具行、结算、教学文案）全部压暗。
2. **三层层级一眼可辨**：用户输入（结构最强：全宽背景条）＞ agent 正文（最亮：默认前景色 + Markdown）＞ 过程信息（思考/工具/结算：最暗、可折叠）。
3. **单一强调色纪律**：terracotta `#d97757` 只出现在「需要用户注意或交互」的地方——光标行、输入聚焦、权限卡、计划卡。不做多色装饰。
4. **统一空行节奏**：块内换行 0 空行，块与块之间 1 空行。整屏靠空行分组，不再靠符号硬撑。
5. **终端诚实降级**：mono/窄终端自动退化为符号 + 无色方案，任何元素在 80×24 下不破版。

## 3. 视觉语言规范

### 3.1 色彩 token（`theme.ts` 扩展）

| token | truecolor | 256 | 用途 |
| --- | --- | --- | --- |
| `fg` | 默认前景 | — | agent 正文 |
| `dim` | `gray` | 240 | 铬件：状态栏、工具行、结算、提示 |
| `accent` | `#d97757` | 166 | 品牌与交互焦点（唯一强调色） |
| `ok` | `#46c46a` | 71 | 成功标记 |
| `warn` | `#d6a235` | 178 | 警告 |
| `error` | `#e5534b` | 167 | 失败 |
| **新增** `userBg` | `#30303a` | 236 | 用户消息背景条 |
| **新增** `codeBg` | `#24242c` | 234 | 代码块背景 |
| **新增** `selectionBg` | `#3a3a4a` | 238 | 选择器光标行背景 |

16 色终端：`userBg`/`codeBg`/`selectionBg` 退化为不设背景，改用左竖线 `▎` 标记；mono 全部退化（见 3.4）。

### 3.2 间距系统

- **块间距**：transcript 相邻块之间恰 1 空行（渲染层统一加，投影层不管）。
- **组内间距**：连续工具调用之间 0 空行（它们是一组动作）。
- **输入框**：`paddingX={1}`，内容区最小高度 1 行（边框总高 3 行起）。
- **Markdown 缩进**：列表每级 2 空格；代码块整体左缩进 1 空格 + 背景色。

### 3.3 字形表（`glyphs()` 扩展）

| 用途 | Unicode | ASCII 降级 |
| --- | --- | --- |
| 品牌 | `✳` | `*` |
| 用户提示符 | `❯` | `>` |
| 思考 | `✻` | `~` |
| 工具 | `⏺` | `+` |
| 成功 | `✓` | `v` |
| 失败 | `✗` | `x` |
| 折叠指示 | `▸ / ▾` | `> / v` |
| 引用/思考竖线 | `▎` | `\|` |

### 3.4 降级矩阵

| 能力 | truecolor/256 | 16 色 | mono |
| --- | --- | --- | --- |
| 用户消息 | 背景条 + bold | 左竖线 `▎` + bold | `> ` 前缀 + bold |
| 代码块 | 背景 + 缩进 | 仅缩进 + 上下 `─` 线 | 仅缩进 |
| 选择器光标 | 背景高亮 | 反色（inverse） | 反色 |
| 思考 | dim + italic | dim | 前缀 `~` |

## 4. 组件规范与前后对照

### 4.1 欢迎屏（瘦身）

**删除**：模型行（含路由 ID）、cwd 绝对路径、两行快捷键教学、外边框本身。
**保留**：品牌 + 版本 + 一行操作指引；未选模型时追加一行指引。

```
现状                              新设计
┌╭────────────────────┐
││ ✳ Spark v0.2.0 · 确定性编码 Agent │         ✳ Spark v0.2.0
││ 模型 sparkwork:provider-1:gpt… · /Users/… │
││ (空行)                       │         给 Spark 一个任务，或 /model 选择模型
││ · 输入任务开始，/help 查看全部命令 │         /help 查看全部命令
││ · ↑↓ 历史 · Shift+Enter 换行 … │
└╰────────────────────┘
```

规则：品牌行 accent + bold；指引行 dim；整体不再画边框（空态不需要卡片感）。

### 4.2 模型选择器（去 ID 化）

行内只保留三个信息：**显示名**（新派生字段，见第 6 节）、**提供方**、选中/光标标记。协议、路由 ID、来源标签全部撤下（`/status` 和报错详情里保留完整 ID 供排查）。

```
现状
❯ * sparkwork:provider-1:gpt-host  SparkWork Test · openai-responses · [sparkwork]
  * sparkwork:provider-2:glm-air   GLM 专线 · anthropic-messages · [sparkwork]

新设计（▓ = 光标行背景高亮）
▓ ❯  GLM-4.7          SparkWork        ✓
    Claude Sonnet 4.5 SparkWork
    gpt-host         SparkWork Test
    ──────────────────────────────
    c 配置本地渠道 · r 刷新 · ↑↓ 选择 · enter 确认
```

规则：
- 光标行整行背景高亮（`selectionBg`），非现状的仅 `❯` 前缀。
- 选中模型带 `✓`；显示名 = `route.displayName ?? route.model`（首字母大写化、`-`/`_` 转空格），提供方 = `providerName`。
- 重复显示名追加提供方消歧；仍重复追加 `(2)` 序号。
- SparkWork 连接状态压缩为标题旁一个词：`选择模型 · SparkWork 已连接`；诊断信息**只在断连时**显示。

### 4.3 对话区（核心：块模型 + Markdown）

投影层从 `(text, tone)` 行升级为**块（block）**：`user` / `assistant` / `thinking` / `tool` / `summary` / `system`。渲染层按块类型套视觉语法，块间统一空行。

**A. 用户消息块** —— 全宽背景条 + bold，最强结构：

```
现状:  ● 帮我重构 src/tui，对话区完全看不清层次

新设计（█ = userBg 背景条，占满行宽）:
████████████████████████████████████████████████████
█ ❯ 帮我重构 src/tui，对话区完全看不清层次          █
████████████████████████████████████████████████████
```

多行输入保留换行，整块连续背景。16 色/mono 降级为 `▎` 左竖线 + bold。

**B. agent 正文块** —— 无前缀、默认前景色、Markdown 渲染（见 4.6）：

```
现状（原样吐 markdown 源码）:
### 分析
1. 先做渲染层
运行 `npm test` 验证

新设计:
分析                                  ← H3: bold
                                     ← 标题上下各 1 空行
 1. 先做渲染层                        ← 有序列表：数字 + 空格
 2. 再改投影层
运行 npm test 验证                    ← 行内代码：accent 色
```

**C. 思考块** —— 默认折叠为单行，可展开：

```
现状:  ▍ 思考 · 用户要重构 tui 我先看看 projection.ts 的结构然后…

新设计（折叠态）:
 ✻ 思考 8.2s                         ← dim + italic，ctrl+o 展开
（展开态）
 ▾ 思考 8.2s
 ▎ 用户要重构 tui，先看 projection.ts 的结构…      ← dim + italic 逐行
 ▎ 其次 rows.tsx 的 Static 渲染…
 ✻ ctrl+o 收起
```

流式进行中：`✻ 思考中…`（dim，左侧 spinner 帧动画）。折叠/展开快捷键 `ctrl+o`，与 Claude Code 习惯一致。

**D. 工具块** —— 摘要化参数，不再吐 JSON：

```
现状:  ⏺ readFile({"path":"src/tui/app.tsx","limit":80}) ✓ 12ms

新设计（执行中）:
 ⠼ 读取 src/tui/app.tsx
（完成后，同一行落定）
 ✓ 读取 src/tui/app.tsx · 12ms
 ✗ 执行 rm -rf build · exit 1          ← 失败用 error 色
```

规则：每个工具一个「动词 + 关键参数」摘要函数（read/write/edit → 路径；bash → 命令首段；其余 → 第一个字符串参数），连续工具调用之间 0 空行成组，组与正文间 1 空行。JSON 全文不再上屏。

**E. turn 结算行** —— 保留但收紧：

```
 ✓ 完成 · 3 步 · 1,204 tok · $0.0031        ← dim
 ✗ 失败 rate_limited · 稍后重试或 /model 换渠道  ← error 色 + 恢复提示
```

**F. 权限卡 / 计划卡** —— 选项改为每行一项（现状四个选项挤一行）：

```
现状:  ❯ 1 允许一次   2 本会话不再询问   3 拒绝

新设计:
╭─ 权限确认 ─────────────────────────────╮
│ write · src/tui/app.tsx                │
│ 风险：需要授权                          │
│                                        │
│ ❯ 允许一次                             │
│   本会话不再询问                        │
│   拒绝                                  │
│                                        │
│ ↑↓ 选择 · enter 确认 · esc 拒绝        │
╰────────────────────────────────────────╯
```

### 4.4 输入区

| 维度 | 现状 | 新设计 |
| --- | --- | --- |
| 边框色 | accent 常亮 | **空闲 dim；聚焦（有输入或光标活动）accent；锁定 dim** |
| 高度 | 随内容跳动 | 最小 3 行（内容 1 行起），多行自然增高 |
| 空态占位 | 无（只有 `❯ `） | `❯ 给 Spark 下达任务…`（dim；/ 开头时切换为命令提示） |
| 粘贴折叠 | `[粘贴 N 行 · 提交后按原文发送]` | 保留，改 dim + italic |
| 锁定态 | 边框灰 + `(输入已锁定)` | 边框 dim + 内容行显示 spinner + 当前状态（`⠼ 正在思考…` / `等待权限确认`），不再显示 `(输入已锁定)` 这种对用户无行动价值的文案 |
| 补全提示 | 下一行 dim 罗列 | 保留，但限制最多 6 个 + `…` |

### 4.5 状态栏

单行、左右分区、统一 `·` 分隔、窄终端截断中间而非折行：

```
现状:  fake-m1  权限:default  推理:auto  120 tok · $0.0000 · /help

新设计:
 GLM-4.7 · default · auto · · · · · · · · · · · 1,204 tok · $0.0031
（左：显示名 · 权限 · 推理；右：用量；中间点线填充；全行 dim，模型显示名正常色）
非默认权限/推理时对应字段提亮（plan→ok 色，bypass→error 色）
```

模型只显示派生显示名（与选择器同源）；完整路由 ID 移至 `/status`。

### 4.6 Markdown 渲染规范（新增 `src/tui/markdown.ts`）

纯函数渲染器：`renderMarkdown(text, width, capabilities) → styled segments[]`，无第三方依赖（延续 stdlib-only 原则）。支持范围与规则：

| 元素 | 渲染规则 |
| --- | --- |
| `#`/`##`/`###` 标题 | bold；H1/H2 前后各 1 空行；H3 仅前 1 空行；层级 ≥4 按加粗段落处理 |
| 无序/有序列表 | `●` / `1.` + 空格，每级缩进 2 空格；条目间不空行 |
| 粗体 `**x**` | bold |
| 斜体 `*x*` | italic |
| 行内代码 `` `x` `` | accent 色（去反引号） |
| 围栏代码块 | 整块背景 `codeBg` + 左缩进 1 空格；块上一行 dim 语言标注 `` ```ts ``；≤3 行不显示语言标注行 |
| 引用 `>` | 左竖线 `▎` dim |
| 分隔线 `---` | dim `─` × min(48, width×0.6) |
| 链接 `[t](u)` | 显示 `t`，宽度足够时追加 dim `(域名)`；不足时省略 URL |
| 表格 | 按 `|` 对齐渲染（等宽字体可行）；降级为逐行原文 |
| 段落 | soft-wrap 按终端宽度；硬换行保留 |

降级：mono 终端去色保结构（符号、缩进、空行全部保留）。

## 5. 信息架构决策汇总（显示 vs 隐藏）

| 信息 | 现状 | 新设计 |
| --- | --- | --- |
| 模型路由 ID | 选择器、状态栏、欢迎屏三处 | **界面零显示**；仅 `/status` 与错误详情保留 |
| 协议 / 来源标签 | 选择器行内 | 隐藏；`/status` 保留 |
| cwd | 欢迎屏 | 移除；`/status` 保留 |
| 快捷键教学 | 欢迎屏 2 行 | 移除；`/help` 承接；快捷键提示只出现在相关组件脚注（如权限卡底行） |
| 思考全文 | 全量平铺 | 默认折叠单行，ctrl+o 展开（展开状态跨 turn 保持） |
| 工具参数 JSON | 60 字符截断上屏 | 摘要化（动词+关键参数）；JSON 不上屏 |
| turn 结算 | dim 单行 | 保留，格式收紧 |

## 7. 不做什么

- 不做代码块语法高亮（首版代码块统一背景色，语法高亮留到下版本）。
- 不做多主题/用户自定义主题（token 先定死，留扩展点）。
- 不做横向滚动/虚拟滚动（Static 已解决历史性能）。

## 8. 验收标准

1. 80×24 终端下：用户消息、agent 正文、思考、工具四类内容一眼可辨，无需阅读文字内容即可分层。
2. 界面上不出现任何 `provider-1` 式路由 ID（`/status`、报错除外）。
3. Markdown（标题/列表/粗体/行内代码/代码块/引用/链接/表格）全部正确渲染；mono 终端结构不丢。
4. golden 帧更新；`npm run verify`（typecheck + lint + test）全绿。
