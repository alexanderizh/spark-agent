# Spark Engine 功能设计索引

> 状态: 实施中 | 最后核对: 2026-08-26

## 这个文件夹是什么

《[自研Agent引擎完整架构设计](../自研Agent引擎完整架构设计.md)》是**总纲**：它定义内核不变量、子系统边界和里程碑。但总纲里每个子系统只有一节篇幅，远达不到「可以直接照着写代码」的粒度。

**本文件夹把每个功能域拆成独立设计文件，逐个细化到实现级**。每个文件必须回答：用户看到什么、配置怎么传、内部机制是什么、边界情况怎么办、怎么测试。粒度标准：读完后，实现者不需要再回来问「这里该怎么处理」。

## 撰写规范（每个功能文件的统一模板）

```markdown
> 状态: 待细化 | 细化中 | 已定稿待评审 | 已评审

# <编号>-<功能名>

## 1. 目标与非目标 ← 这个功能解决什么、明确不解决什么

## 2. 对标分析 ← Claude Code / Codex / opencode 各家怎么做，差异与启示

## 3. 用户可见行为 ← UX 契约：TUI 与宿主 GUI 下的完整交互时序

## 4. 配置接口 ← 配置文件 schema、CLI 参数、会话内命令、优先级顺序

## 5. 内部机制 ← 事件、状态、流程；事件给出 zod schema

## 6. 边界与异常 ← 失败、超时、竞态、降级路径，逐条枚举

## 7. 与其他子系统的交互 ← 引用其他编号文件，禁止重复定义

## 8. 测试要点 ← FakeModel 驱动的确定性测试用例清单

## 9. 开放决策点 ← 尚未拍板的选项与推荐倾向
```

规则：

- 对标部分只写**核实过的事实**（源码、官方文档、本机实测），推测必须标注「未核实」；
- 涉及事件写入的一律给 zod schema，与 M1 spec 的账本 schema 对齐；
- 每个文件自成一体，实现者不需要翻总纲就能开工（总纲只提供不变量背景）。
