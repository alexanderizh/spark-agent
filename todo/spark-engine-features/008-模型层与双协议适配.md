# 008 - 模型层与双协议适配

> 状态: 实施中 | 最后核对: 2026-08-26

## 1. 目标与协议边界

内置只实现两套一等协议：Anthropic Messages 与 OpenAI Responses。内核只依赖统一 IR；Chat Completions 等其他协议必须通过插件 seam 扩展，不能把第三套厂商分支写进 TurnMachine。

实现采用 Node 原生 fetch + SSE，不引模型 SDK。该决策用于完整掌控缓存、usage、opaque continuation、取消和错误分类；请求/事件字段仍以官方协议为唯一事实源。

## 2. 官方依据（2026-08-26 核对）

- OpenAI Streaming Responses：<https://developers.openai.com/api/docs/guides/streaming-responses>
- OpenAI Function Calling：<https://developers.openai.com/api/docs/guides/function-calling>
- OpenAI Responses API Reference：<https://developers.openai.com/api/reference/resources/responses>
- Anthropic Streaming Messages：<https://platform.claude.com/docs/en/build-with-claude/streaming>
- Anthropic Tool Use：<https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview>

- Anthropic Errors：<https://platform.claude.com/docs/en/api/errors>

关键约束：OpenAI reasoning items 在工具循环后必须原样回传；Anthropic thinking blocks 的签名也必须保留。只存可见 thinking 文本会破坏第二步请求，因此 continuation 是 M2 的基础契约而不是可选优化。

## 3. 统一 IR

```ts
type LlmDelta =
  | { type: 'text'; text: string }
  | { type: 'thinking'; text: string }
  | { type: 'tool_call'; callId: string; name: string; args: unknown }
  | { type: 'usage'; inputTokens: number; outputTokens: number; cacheReadTokens?: number; cacheWriteTokens?: number }
  | { type: 'continuation'; continuation: { protocol: Protocol; data: unknown } }
  | { type: 'heartbeat' }
  | { type: 'done' };
```

Thinking 配置为显式联合类型：adaptive（可选 omitted/summarized）、enabled（固定 budget，兼容旧模型）、disabled。具体模型是否支持由能力注册表裁剪；adapter 不靠模型名猜测并静默丢字段。

## 4. Anthropic Messages adapter

请求映射：

- `system` → text blocks；稳定段存在时启用顶层 ephemeral prompt caching；
- user text → user text block；连续 tool results 合并为一个 user content 数组；
- assistant 同协议 continuation → 原样 content blocks；否则从中立 text/tool calls 重建；
- 工具 schema → `name/description/input_schema`；boolean schema 显式拒绝；
- `tool_result` 携带匹配 `tool_use_id`，失败时 `is_error=true`。

流状态机处理 `message_start / content_block_start / content_block_delta / content_block_stop / message_delta / message_stop / ping / error`。`input_json_delta` 累积到 block_stop 才 JSON.parse 并发出 tool_call；thinking signature 只进入 continuation，不暴露为文本。

usage 映射 input/output/cache_read/cache_creation；流中 error 与 HTTP 200 后错误同样进入结构化 KernelError。

## 5. OpenAI Responses adapter

请求映射：

- system sections 合并为 `instructions`；
- user/assistant/tool result 映射为 Responses input items；
- 同协议 continuation 的 output items 原样回传，保留 reasoning/encrypted state；
- 工具定义使用 function + JSON Schema；本地 AJV 仍是执行前最终边界；
- prompt cache 当前使用官方自动前缀缓存，显式 breakpoint 进入 009 后统一启用。

流处理 `response.output_text.delta`、refusal delta、reasoning summary/text delta、`response.output_item.done`、`response.completed`、failed/incomplete/error。工具调用只在完整 item 后 JSON.parse；以 call_id 去重，兼容 output_item.done 与 completed 同时带完整 item。

usage 映射 input/output 与 `input_tokens_details.cached_tokens`。只有 `response.completed` 能发 continuation/usage/done；提前 EOF 为 incomplete stream。

## 6. SSE 与 HTTP 边界

- 增量 UTF-8 decoder 支持多字节跨 chunk、LF/CRLF、多行 data、comment、id、retry。
- 单事件默认上限 8 MiB；非法 UTF-8、非法 JSON、已知事件缺字段均 fail-closed。
- 成功响应必须有 `text/event-stream` 与 body；200 JSON 等形态报 protocol mismatch。
- HTTP 错误只提取受限长度的 type/message/request-id/status/retry-after；绝不把请求头或 API key写入错误。
- 408/409/429/5xx 可重试，其他 4xx 默认不可重试；流中错误按是否已产生输出决定能否重放。

## 7. Provider / Model 注册表与配置

正式配置格式：

```toml
[agent]
model = "primary"
failover = ["backup"]
max_retries = 2

[providers.openai]
protocol = "openai-responses"
base_url = "https://api.openai.com/v1"
api_key_env = "OPENAI_API_KEY"

[models.primary]
provider = "openai"
model = "gpt-model-id"
```

合并顺序：内置默认 < `~/.spark/config.toml`（或 `SPARK_HOME/config.toml`）< 项目 `.spark/config.toml` < `SPARK_MODEL/SPARK_FAILOVER_MODELS` < CLI `--model`。

注册表公开 descriptor，不公开凭据；API key 只在创建 adapter 的私有闭包中使用。配置快照不含 key，可安全进入 session.started。没有模型、未知 provider/model、缺凭据环境变量都会给出精确错误，CLI 不回退 FakeModel。

## 8. 已验证用例

- SSE 每字节拆分的中文 UTF-8、CRLF、多行 data、事件大小上限。
- 两套协议的工具调用、thinking/reasoning、usage/cache 与 continuation replay。
- 非法工具 JSON、重复 continuation、缺终态、HTTP 429 与 retry-after。
- retry/failover 只发生在无可见输出前。
- 全局/项目/env/CLI 配置优先级与凭据不进入 snapshot。
- 本地真实 HTTP Responses 服务 → CLI → 5 条连续事实事件；npm pack 后全新安装同样通过。
