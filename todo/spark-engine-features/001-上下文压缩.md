# 001 - 上下文压缩

> 状态: 已评审 | 最后核对: 2026-08-26

## 1. 目标与非目标

**目标**：让单会话在有限上下文窗口内可以无限延续。定义完整的压缩机制：配置接收、token 计量、触发时机、执行流程、进度与结果展示、保护内容、压缩后的上下文组装、崩溃恢复语义。

**非目标**：

- 单条工具输出的头尾截断（属 [004 工具执行管道](#)，本文只定义它与压缩的边界）；
- 跨会话的长期记忆（独立功能，未来另立文件）；
- 模型侧的上下文管理（cache_control、服务端缓存——属 [009 提示缓存策略](#)）。

**三种机制，一次分清**（本文档的核心术语）：

| 机制 | 粒度 | 触发者 | 定义 |
|---|---|---|---|
| **截断 truncation** | 单条工具输出 | 自动（写入前） | 头+N 行 + 尾+M 行 + 省略标记，全文进制品库。属 004 |
| **微压缩 micro-compaction** | 单条历史条目 | 自动（兜底） | 把**较早轮次**的大工具结果正文替换为 `[已归档 artifact:<id>]` 占位。本文 §13 |
| **粗压缩 compaction** | 连续事件区间 | 自动/手动 | 一次摘要模型调用，把一段历史重建为结构化摘要块。本文主体 |

## 2. 对标分析

| 维度 | Claude Code | Codex | opencode |

| 手动压缩 | `/compact`，可带附加指令（"focus on the API refactor"） | `/compact` 命令 | 未核实（待查其 specs/ 目录） |
| 自动压缩 | 接近上限自动触发（默认开，可关） | token 用量达阈值自动，阈值可配 | 未核实 |
| 保留策略 | 保留最近历史，较早内容进摘要 | 明确保留最近完整轮次 | 未核实 |
| 条目级回收 | microcompaction：旧工具输出自动替换为占位 | — | 未核实 |
| 可视化 | `/context` 显示上下文构成分解 | — | — |

（Claude Code / Codex 行为基于公开文档与产品实际行为，内部阈值未公开，以下我们的数值均为自主设计而非转述。）

**三条吸收进我们的设计**：附加指令进摘要提示词（Claude Code）；「保留最近完整轮次」作为硬规则而非按条目裁剪（Codex）；`/context` 可视化让计量透明（Claude Code）。

**我们超出两家的点**：① 压缩是一次**事件化**的操作——请求/开始/完成/失败全部进账本，TUI、宿主 GUI、回放同源消费；② 摘要块**字节固化**（生成后进制品库逐字节复用），压缩后阶段重新获得提示缓存稳定性（两家都没有公开的此保证）。

## 3. 用户可见行为（UX 契约）

### 3.1 触发前：建议

状态区（TUI footer 上一行）出现黄色常驻提示，不弹窗不打断：

```
⚠ 上下文已用 71% (142k/200k) — 可运行 /compact 主动压缩
```

### 3.2 压缩中：进度

模型结束当前轮后开始压缩。TUI：transcript 完全不动，status 区切换为：

```
⟳ 正在压缩上下文… (摘要模型: claude-haiku-4-5, 已 3.2s)
```

宿主 GUI（SparkWork）：同一事件投影为会话内的系统进行条。**压缩期间输入框可用**，输入照常进 FIFO 队列（与「运行中输入不打断」语义完全一致——压缩对用户而言就是一段特殊的 turn）。

### 3.3 压缩后：结果卡

transcript 在压缩边界插入一张系统卡（默认 `brief` 档，一行）：

```
⟳ 上下文已压缩  142,331 → 9,412 tokens · 保留最近 3 轮 · 自动触发 (80%)
```

`full` 档展开显示四块：摘要全文（markdown 渲染）、被压缩范围（第 4~38 轮）、受保护内容清单、用户附加指令回显（如有）。`silent` 档什么都不显示（事件仍记录）。

### 3.4 查看构成：`/context`

```
上下文构成 (window 200k, 当前 96,514 = 48%)
  system + 指令           4,102   ████
  环境上下文                312   ▏
  摘要块 ×1 (第38轮)      9,412   █████████
  保留轮次 (最近3轮)      71,890   ████████████████████████████████████
  队列中待发消息              88   ▏
  输出预留 (max_tokens)    8,192   ████
  空闲余量                106,486
历史压缩: #1 第38轮 142,331→9,412 (自动)  #2 …
```

### 3.5 手动压缩

`/compact`（无参）或 `/compact 重点保留数据库迁移的决策过程`。运行中输入则排队到当前轮结束执行。

## 4. 配置接口（设置怎么接收）

四级优先级（高→低）：**会话内命令 > 项目 `.spark/config.toml` > 全局 `~/.spark/config.toml` > 内置默认**。

```toml
# ~/.spark/config.toml
[context]
# 模型窗口覆盖（模型注册表缺省值不准时）
[context.window]
"claude-sonnet-4-6" = 200_000
"my-gateway-model"  = 128_000

[context.compaction]
mode = "auto"            # auto | manual | off
auto_threshold = 0.80    # 占用比例（含输出预留后的可用口径，见 §6）
suggest_threshold = 0.70 # 建议提示线
keep_recent_turns = 3    # 粗压缩必须保留的最近完整轮数
keep_min_tokens = 12_000 # 保留区 token 下限（与轮数取并集，防 3 轮也太小的病态场景）
announce = "brief"       # full | brief | silent
summarizer_model = ""    # 空 = 主模型；推荐填便宜快速模型
max_summary_tokens = 4_000

[context.micro_compaction]
enabled = true
entry_threshold = 6_000  # 单条历史工具结果超过此 token 才会被微压缩
```

会话内即时调整：`/config context.compaction.mode manual`（写会话状态，不回写文件）。`/compact` 一次性附加指令不属于配置。

**校准状态持久化**（§6 计量系数）存于会话目录 `session.json`，不进事件账本——它是可再生的运行时状态，不是事实。

## 5. 内部机制：事件与状态

### 5.1 事件 schema（zod，与 M1 spec 账本对齐）

```ts
const CompactionTrigger = z.enum(['auto', 'manual', 'forced']);

const CompactionRequested = z.object({
  type: z.literal('context.compaction.requested'),
  data: z.object({
    trigger: CompactionTrigger,
    instructions: z.string().optional(),
    usage: z.object({
      tokensEstimated: z.number().int(),  // 下一请求 prompt 预估
      windowTokens: z.number().int(),
      ratio: z.number(),
    }),
  }),
});

const CompactionStarted = z.object({
  type: z.literal('context.compaction.started'),
  data: z.object({
    summarizerModel: z.string(),
    inputRange: z.tuple([z.number().int(), z.number().int()]), // [firstSeq, lastSeq]
  }),
});

const CompactionCompleted = z.object({
  type: z.literal('context.compaction.completed'),
  data: z.object({
    summaryArtifactId: z.string(),   // 摘要正文存制品库，hash 寻址
    summaryTokens: z.number().int(),
    tokensBefore: z.number().int(),
    tokensAfter: z.number().int(),   // 压缩后整份 prompt 预估
    compactedRange: z.tuple([z.number().int(), z.number().int()]),
    keptRange: z.tuple([z.number().int(), z.number().int()]),
    keptTurns: z.number().int(),
    trigger: CompactionTrigger,
  }),
});

const CompactionFailed = z.object({
  type: z.literal('context.compaction.failed'),
  data: z.object({ error: z.string(), retried: z.boolean(), degraded: z.boolean() }),
});
```

**原子性**：`completed` 是唯一的切换点。写日志用 append + fsync，`completed` 落盘前任何崩溃都等于「压缩从未发生」，读取侧继续用旧投影——事件日志天然给了我们 compare-and-swap 语义，无需额外事务。

### 5.2 摘要提示词（固定模板 + 注入点）

摘要请求 = 系统模板（固定字节，版本号 `compaction-prompt-v1`）+ 结构化输入 + 可选用户附加指令。结构化输入是**对被压缩区间的再投影**（投影器换用摘要型投影：工具输出只保留一行结论与 artifact 引用，控制摘要成本）。

摘要正文是**结构化 markdown**，固定八节（缺节写「无」）：

```markdown
# 会话摘要（第 4–38 轮 → 第 38 轮压缩）
## 任务与目标        ← 用户最初诉求 + 演变
## 关键决策与理由    ← 技术选型、方案取舍，含被否方案
## 已完成工作        ← 按时间序的结果清单
## 文件与产物        ← 路径 + 改动摘要（模型可自行重读）
## 错误与解决        ← 踩过的坑与修法（防重蹈）
## 用户偏好与约束    ← 本会话中用户明确表达的偏好
## 未完成与下一步    ← 悬挂事项
## 前序摘要继承      ← 上一次压缩的摘要要点（累积压缩时）
```

固定节结构使摘要可被程序校验（测试断言八节齐全），也让「摘要质量」可评测。

### 5.3 压缩后的请求布局（组装）

```
┌─ system prompt（含技能/指令注入）        ← 逐字节不变（缓存段 A）
├─ environment context（cwd/git/平台）      ← 逐字节不变（缓存段 A 续）
├─ [compact-summary v1] …八节摘要… [/compact-summary]   ← 摘要块（缓存段 B 起点）
├─ 保留区：最近 K 轮原始事件投影            ← 追加式增长（缓存段 B 续）
└─ 新用户消息
```

**字节固化规则**：摘要块在 `completed` 事件中指向制品库（hash 寻址），之后每轮组装**逐字节复用制品内容**，禁止重排/重渲染。效果：压缩完成后，system→摘要块→保留区构成新的稳定前缀，从第一轮起重新累积提示缓存命中——压缩的缓存代价被限制为「一次断点」，而非持续失稳。

### 5.4 触发判定流程（每轮 assistant 终态后）

```
1. usage = 下一请求 prompt 预估（§6）
2. ratio = usage / window_tokens
3. ratio ≥ suggest_threshold → 发 TUI 建议事件（仅状态变化沿，不重复发）
4. ratio ≥ auto_threshold && mode==auto && !队列中已有压缩 → 排入压缩
5. 手动 /compact 在队头 → 立即排入（同轮去重）
6. 执行点：下一用户消息出队之前（见 §7 静止点）
```

## 6. token 计量（判断"该压了"的依据）

双轨制：

- **权威值**：每次 API 响应的 `usage`（Anthropic `input_tokens` / Responses `input_tokens`）。它精确反映服务端口径（含缓存读写与系统提示计入规则）。
- **预估值**：本地估下一条请求——system/env/摘要块/保留区各段用 js-tiktoken（OpenAI 系模型）或 `chars / 3.2`（Anthropic 系，比率经校准）逐段估算后求和，加 `max_tokens` 输出预留。

**校准闭环**：每次响应记录 `(预估值, API 权威值)`，会话内滑动窗口（最近 8 次）求修正系数持久化到 `session.json`。预估偏差收敛后，自动触发点不漂移。

`window_tokens` 来源：模型注册表 → `[context.window]` 覆盖 → 都没有则保守取 32k 并在 `/context` 与 `doctor` 显式警告。

## 7. 触发时机与静止点规则（什么时候压）

**唯一执行点：turn 边界静止点**——上一 turn 已终态、下一用户消息尚未出队。绝不发生在：

- 工具循环中途：未闭合的 `tool_use → tool_result` 对进入摘要会直接产生协议非法请求（两家 API 都强制配对），且破坏不变量 #5（确定性组装）；
- 流式输出中途；
- 权限审批挂起中（审批本身依赖完整上下文展示）。

运行中的 `/compact` 进 FIFO 队列，排在当前轮终态后、下一条用户消息前——与命令排队语义（FIFO、不打断）完全一致，不新增旁路。

## 8. 保护内容（哪些永不进摘要）

| 内容 | 保护方式 | 理由 |
|---|---|---|
| system prompt（含技能注入） | 组装层硬编码，压缩函数不可见 | 指令是行为契约，动了等于换人格 |
| environment context | 同上 | 会话锚点（cwd/git 状态） |
| 权限决策记录（本会话 allow 产物） | 同上 | 压掉会导致模型重复索权，用户重复审批 |
| 最近 K 轮完整原始事件 | `keep_recent_turns` + `keep_min_tokens` 并集 | 手头任务的细节新鲜度 |
| 未闭合工具调用对 | 结构上不可能出现（§7 静止点） | 协议正确性 |
| 队列中的用户未发消息 | 不属于上下文，属队列系统 | 未消费的输入 |
| 摘要块本体 | 累积压缩时作为摘要输入的一部分，其信息被继承而非丢弃 | 防多次压缩后信息指数衰减 |

## 9. 失败与降级

| 场景 | 行为 |
|---|---|
| 摘要模型调用失败 | 重试 1 次（指数退避 2s）→ 仍失败：发 `failed{degraded:true}`，会话**继续不压缩**，状态区黄字警告「压缩失败，将在下轮重试」；下轮边界自动重试 |
| 持续失败且 ratio ≥ 98% | 当前 turn 以明确错误终止（`context_exhausted`），会话可恢复：用户 `/compact`、`/config` 换摘要模型、或 `/new` 新会话。绝不静默截断历史冒充成功 |
| 压缩后仍超限（摘要+保留区就超窗） | 先微压缩保留区中的大工具结果（§13）重算；仍超 → 同上 `context_exhausted`，错误信息指出保留区过大、建议调小 `keep_recent_turns` |
| 写 `completed` 前崩溃 | 压缩未发生语义（§5.1），重启后照旧投影，无损 |
| 校准系数文件损坏 | 回退系数 1.0，下次响应自动重建 |

## 10. resume / fork / 回放语义

- **resume**：重放事件序列重建上下文。读到 `completed` 后，组装器切换为「摘要块（按 artifactId 取制品）+ 保留区」布局——与其他投影同源，无专用恢复路径。
- **fork**（从任意 turn 分叉）：fork 点在压缩点之后，则新会话拷贝 `completed` 事件引用（制品库按 hash 去重，零拷贝成本）+ 保留区事件。
- **`spark events --replay`**：压缩事件照常回放（它是历史的一部分）；`--replay --view context` 可逐事件显示上下文占用曲线，压缩点标注为垂直线——这是调试上下文问题的标准工具。

## 11. 与其他子系统的交互

- **002 上下文组装**：本文定义摘要块这个新段类型；布局优先级与段注册机制归 002。
- **004 工具管道**：截断发生在写入前（工具结果落账本时就已截断+引用化），压缩面对的永远是已截断条目；摘要投影把引用进一步收为一行。
- **009 提示缓存**：缓存断点=压缩点。分段缓存标注（system 段 A / 摘要后段 B）的标记协议归 009，本文提供边界事件。
- **010 制品库**：摘要正文是普通制品，无特权。
- **015 CLI**：`spark run --no-auto-compact`（一次性禁自动）、`spark events --view context`。
- **020 doctor**：校准系数异常（偏差 >30%）、窗口来源为兜底值时报告。

## 12. 测试要点（全部零 token）

1. **自动触发**：FakeModel 脚本「20 轮、每轮附 8k tokens 工具输出」→ 断言 `requested/started/completed` 序列、比例阈值、事件字段。
2. **布局字节**：压缩后第 1/2/3 轮请求的 `system+env+摘要块` 前缀逐字节相同（缓存证书子项）。
3. **保护内容**：压缩前后请求中 system、env、权限记录段逐字节不变。
4. **摘要结构**：FakeSummarizer 产出必含八节（校验器）；缺节 → 测试失败。
5. **手动排队**：运行中输入 `/compact`，断言不打断当前 turn、终态后先压缩再消费队列。
6. **静止点**：构造工具循环进行中到达阈值的场景，断言压缩延迟到边界。
7. **失败降级**：FakeSummarizer 抛错两次 → 断言 `failed`、会话可继续、下轮重试。
8. **崩溃恢复**：写 `completed` 前 kill -9，重启后投影无摘要块、上下文完整。
9. **累积压缩**：两次压缩后摘要含「前序摘要继承」节且 token 单调有界。
10. **计量校准**：FakeModel 返回伪 usage 序列，断言系数收敛且 `requested` 的 ratio 用校准后估值。

## 13. 微压缩（条目级兜底）

仅当粗压缩完成后仍超窗（§9 场景 3）时启用：把保留区中 `entry_threshold` 以上的**旧工具结果**正文替换为 `[已归档 artifact:<id>，spark artifacts read <id> 取全文]` 占位。与截断共用占位格式（模型已学会取全文的动作）。单独开关、单独配置、同样事件化（`context.micro_compaction.completed`，被替换条目 seq 列表 + 节省 token 数）。不做 Claude Code 式的常态后台清理——那会频繁击穿缓存；我们只把它当溢出救生舱。

## 14. 开放决策点

| # | 决策 | 选项 | 推荐 |
|---|---|---|---|
| 1 | `auto_threshold` 默认值 | 0.75 / 0.80 / 0.85 | **0.80**：留出单轮典型增长（工具循环）+ 输出预留的余量，又不至于过早付缓存断点成本 |
| 2 | `announce` 默认档 | brief / silent | **brief**：透明度优先，silent 让用户在压缩后突然「失忆」却不知原因 |
| 3 | `summarizer_model` 默认 | 空(=主模型) / 内置便宜模型表 | **空**：不隐式产生额外费用；doctor 与文档推荐显式配置 |
| 4 | `keep_recent_turns` 默认 | 2 / 3 / 5 | **3**：Codex 同量级；最终以实测摘要后任务连续性调优 |
| 5 | 用户 pin 单条消息不压缩 | 做 / 不做 | **暂不做**：`keep_recent_turns` 已覆盖大部分诉求，pin 增加一条 UI+schema 链路，进 backlog 观察需求强度 |
