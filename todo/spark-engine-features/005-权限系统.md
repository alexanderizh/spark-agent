# 005 - 权限系统与结构化规则 DSL

> 状态: 实施中 | 最后核对: 2026-08-26

## 1. 目标与边界

权限系统负责“人的意图轴”：工具是否允许、拒绝或需要审批。006 的 OS 沙箱负责“机器边界轴”，即获准后进程最多能访问什么；两者不可互相替代。

本纵切已实现结构化规则求值、四种权限模式、按会话与资源隔离的临时授权、审批范围校验和完整事件审计。永久规则写回 TOML 隶属 016 配置系统；在具备保留注释、并发写冲突检测和明确 user/project 目标选择前，TUI 不展示虚假的永久授权入口。

## 2. 工具权限契约

每个 `ToolDefinition` 必须显式声明 `permissionClass`：

- `read`：无副作用读取；
- `workspace-write`：工作区内文件写入；
- `command`：shell 或进程执行；
- `external`：网络、远端系统或其他外部副作用。

模式判断不得从“是否 destructive”反推。`destructive` 只提高风险展示与重试限制，不能代替权限类别。注册表强制 `permissionClass=read` 与 `readonly=true` 双向一致，并深拷贝、冻结 JSON Schema，阻止插件注册后篡改元数据绕过 plan。

默认审批上限：`never` 自动允许；`once` 只允许单次；`session` 可批准单次或当前会话的同一资源；`always` 每次都必须审批，审批器即使返回 session 也会 fail-closed。

## 3. 结构化规则 DSL

规则是纯数据：

```ts
interface PermissionRule {
  id: string;
  tool: string; // 仅支持 * 通配符
  action: 'allow' | 'ask' | 'deny';
  reason?: string;
  match?: Array<
    | { path: string; operator: 'equals'; value: string | number | boolean | null }
    | { path: string; operator: 'glob' | 'prefix'; value: string }
  >;
  remember?: 'never' | 'session'; // 仅 ask 可用，且不能放宽 approval=always
}
```

`path` 使用 RFC 6901 JSON Pointer；全部 matcher 按 AND 求值。规则层顺序为 builtin → user → project → CLI → host，同一调用命中多条时最后一条生效。规则 id 与 source 会进入审计事件。

通配符匹配采用线性回溯算法，只解释 `*`，不执行用户正则，避免 ReDoS。规则长度、JSON Pointer 和 matcher 大小均在装载时校验；无效规则使策略构造失败。

## 4. 权限模式

- `default`：按规则与工具默认审批元数据执行；
- `acceptEdits`：自动允许 `read` 与 `workspace-write`，`command/external` 仍按策略处理；
- `plan`：只向模型暴露 `read` 工具，同时执行层再次拒绝任何非 read 调用；
- `bypass`：已注册且 schema 合法的工具跳过权限询问，CLI/TUI 必须显示危险警告。未知工具与参数校验不能被 bypass 绕过。

CLI 支持 `--permission-mode <mode>`；`--dangerously-skip-permissions` 是 bypass 的显式危险别名，与其他 mode 同时传入时报错。

## 5. 会话授权

会话授权键为 `sessionId + tool + 资源指纹`：文件工具按 path 归一为授权资源，其他工具按完整参数的 SHA-256 指纹隔离。授权不会跨 Session，不会因允许一次 write 而放行所有 write，也不会在日志中持久化敏感参数指纹原文。

内存中最多跟踪 1024 个 Session；超限只淘汰最早授权并重新询问，不会扩大权限。

## 6. 审批生命周期与审计

```text
tool.call
  → schema 校验
  → permission.evaluated（allow / deny / ask，含 mode/rule/reason）
  → ask 时 permission.requested
  → 审批返回范围校验与 grant 记录
  → permission.decided
  → allow 后才写 tool.intent
  → tool.result
```

策略异常、审批异常、非法 grant scope、grant 记录失败均转为 deny；副作用之前不写 `tool.intent`。审批界面只展示策略允许的选项，并显示真实参数、策略原因与会话授权范围。

## 7. 已验证用例

- 分层覆盖、工具通配符、JSON Pointer 的 equals/glob/prefix 匹配；
- plan 模式模型工具过滤与幻觉调用执行层拒绝；
- acceptEdits 不会放行 external 工具；
- session grant 同资源复用、异资源与异 Session 隔离；
- bash/approval=always 的恶意 session 决策被拒绝且不执行；
- 每次策略求值均写 `permission.evaluated`，黄金事件账本字节级固定；
- CLI 未知 mode 与冲突参数在读取配置前失败。
