# 000 - 开源选型与多引擎借鉴

> 状态: 已评审 | 最后核对: 2026-08-26

## 1. 目标与非目标

**目标**：确立 spark-engine 的第三方库选型——有成熟开源方案的需求一律用开源库，自研只发生在「开源方案与内核八不变量冲突」或「该需求本身是我们的差异化」的地方。依据是对 Codex、Claude Code、opencode 三家真实技术栈的核实调研。

**非目标**：不逐库做性能基准（实现期按需做）；不覆盖纯内部模块（事件账本、TurnGate、投影器——这些是差异化本体，没有现成轮子）。

## 2. 三家技术栈事实（调研于 2026-08-26）

### 2.1 Codex（openai/codex，Rust）

仓库为 150+ crate 的 Cargo workspace（已核实 `codex-rs/Cargo.toml`）。与我们设计直接相关的第三方依赖及其用途：

### 2.2 Claude Code（闭源，公开事实）

- TypeScript + **Ink（React 渲染到终端）**——我们的既定同路线；
- Grep/Glob 工具直接驱动 **ripgrep（`rg`）二进制**，不自带搜索引擎；
- 会话事实日志 `~/.claude/projects/<munged-cwd>/<sessionId>.jsonl`（本机已实测）。

### 2.3 opencode（anomalyco/opencode，MIT，201k stars）

全 TypeScript + Bun 的 monorepo（已核实 packages/ 目录）：

`app / cli / client / core / desktop / plugin / protocol / sdk / sdk-next / server / tui / ui / web / session-ui / llm / schema / function / http-recorder / effect-drizzle-sqlite / effect-sqlite-node / containers / enterprise / slack …`

关键启示：

- **core 与所有前端（tui/desktop/web）彻底分离**，client 只是 server 的一个消费者——与我们「事件日志多投影」结构同构；
- **protocol、schema、sdk 各自独立成包**——协议稳定性靠物理边界保障，印证我们把协议层做成独立边界的设计；
- `sdk` 与 `sdk-next` 两代并存——SDK 演进不破坏旧宿主；
- `http-recorder` 把「请求录制」做成独立包——确定性测试基础设施的工程化；
- 存储走 Effect + Drizzle + SQLite；
- 仓库根有 `specs/` 目录——设计先行、规格入库的文化（本文件夹即同类实践）；
- build/plan 双内置 agent + `@general` 子代理。

## 3. Rust → TypeScript 选型映射表（核心交付）

原则：**每个需求域先问 Codex/opencode 用什么，再找 TS 生态最优对应物**；冲突时以内核不变量（确定性、可取消、拷贝即用）优先。

| 需求域 | Codex(Rust) | TS 生态候选 | **spark-engine 选型** | 理由 |
|---|---|---|---|---|
| TUI 框架 | ratatui | ink / @clack | **ink + react**（已定） | Claude Code 同路线；React 组件模型适配工具卡渲染 |
| Markdown 解析 | pulldown-cmark | markdown-it / marked / unified | **markdown-it** | AST 完整可遍历（我们的渲染器 = `(AST, 终端能力) → 帧` 纯函数投影，必须拿 AST 而非 HTML）；插件生态成熟 |
| diff | similar | jsdiff / diff-match-patch | **jsdiff**（`diff` 包） | 事实标准；行级+词级 API 齐全 |
| 语法高亮 | syntect | shiki / cli-highlight / prism | **shiki**（懒加载 grammar + 进程内缓存） | VS Code 同源着色质量；冷启动代价用「首次高亮后缓存」对冲；无 grammar 时降级纯色 |
| 模糊匹配 | nucleo | fuse.js / uFuzzy / fzf-wasm | **uFuzzy** | 零依赖、性能对标 fzf、适合文件路径场景；fuse 的距离模型不适合路径排序 |
| 文件搜索（工具） | `ignore` crate | —（直接用 rg） | **驱动 `rg` 二进制**，缺失时降级 fast-glob + `ignore` npm 包 | Claude Code 同路线；rg 的速度与 gitignore 语义无可替代；降级路径保证拷走即用 |
| 文件监听 | notify | chokidar / fs.watch | **chokidar v4** | 事实标准；v4 零依赖 |
| PTY | portable-pty | node-pty | **node-pty** | VS Code 同源；唯一注意点：原生模块，打包期处理（见 §5） |
| shell 解析 | shlex | shell-quote / shell-tokenizer | **shell-quote**（parse + quote 双向） | 工具白名单匹配与转义都需要；带补丁跟随上游安全修复 |
| JSON Schema（工具参数） | schemars | zod-to-json-schema | **zod + zod-to-json-schema**（已定） | zod 是我们全部边界校验的单一来源 |
| MCP | rmcp | @modelcontextprotocol/sdk | **官方 TS SDK** | 官方维护，协议跟进零成本 |
| SQLite（索引，M3+） | sqlx | better-sqlite3 / node:sqlite | **node:sqlite（Node ≥22 内置）**，better-sqlite3 备选 | 零原生依赖 = 拷贝即用硬规则的最大赢家；SparkWork 已有 better-sqlite3 ABI 打包经验可回退。M1 完全不引库（纯 jsonl + 内存索引） |
| HTTP | reqwest | fetch / undici / got | **原生 fetch（undici）** | Node ≥20 内置；流式 SSE 用 undici 的 `response.body`，可取消性由 AbortSignal 满足不变量 #6 |
| token 计量 | tiktoken-rs | js-tiktoken / gpt-tokenizer | **js-tiktoken（OpenAI 系）+ chars 比例估算（Anthropic 系）+ API usage 回填校准** | 见 002 文件的双轨计量设计 |
| 结构化日志 | tracing + otel | pino | **pino** | 性能顶级、transport 生态全；otel 导出实现期按需 |
| 模型 SDK | 内置 client | @anthropic-ai/sdk / openai | **直连 fetch，不引 SDK** | 双协议 IR 是我们的差异化（008）；SDK 的抽象层反而屏蔽缓存与 usage 细节 |
| 沙箱 | seccompiler/bwrap/seatbelt | 无对应库 | **无库：spawn `sandbox-exec`（macOS）/ `bwrap`（Linux），TS 只拼参数** | Codex 同路线（seatbelt 是调系统工具不是库）；沙箱细节进 006 |
| 临时目录 | tempfile | — | **`node:fs` + 名约定**（`tmp-` 前缀 + 进程退出清理注册表） | 简单到不值得引库 |
| 颜色/终端能力 | owo-colors / supports-color | picocolors / supports-color | **picocolors + supports-color** | 双双零依赖、事实标准 |
| 折行 | textwrap | wrap-ansi | **wrap-ansi**（ink 生态同源） | 处理 ANSI 中的 CJK 宽度正确 |
| 凭据存储 | keyring-store | keytar(废) | **无库：env → macOS `security` CLI → `~/.spark/credentials`(0600)** | keytar 已废弃且带原生依赖；细节进 017 |
| 配置 | toml + toml_edit | smol-toml / @iarna/toml | **smol-toml（读）+ 保留注释重写用 `toml-patch` 思路自实现** | 配置文件定 TOML（与 Codex 一致）；写回保注释是唯一小自研点 |

**明确自研清单**（开源无对应或与不变量冲突）：事件账本与投影器、TurnGate 状态机、上下文组装与压缩（001/002）、权限策略引擎（005，对标 starlark 但不用 starlark——TS 下引 Python 方言解释器不成比例，用结构化规则 DSL）、工具输出截断（004，Codex 也是独立自研 crate）、App Server 协议（018）、FakeModel 测试设施。

## 5. 依赖治理规则

1. **许可证白名单**：MIT / Apache-2.0 / BSD-2/3/4 / ISC / 0BSD / Unlicense。禁 GPL/AGPL/LGPL/SSPL（保持闭源与商用自由）；MPL-2.0 逐案评审。
2. **体积与数量预算**：运行时生产依赖 ≤ 30 个直接依赖；npm 发布包解包后 ≤ 1 MB；干净生产安装（含 Ink 全部传递依赖）≤ 40 MB；M2 引入 Shiki 时 grammar 必须按语言懒加载并单独计量。M1 实测发布包约 95 KB、生产安装约 32 MB，其中约 17 MB 来自 Ink 7 的 `es-toolkit` 完整 npm 包。保留外部依赖而不私自裁剪/重打包，可继续获得上游安全更新并保持许可证边界清晰；若上游缩减发布内容，预算同步下调。
3. **原生模块白名单**：仅 `node-pty` 一个（PTY 无纯 JS 方案）。每次升级必须在三平台跑 `spark doctor` 的原生模块检查（020）。首选 Node ≥22 内置能力（node:sqlite、fetch、AbortSignal）消灭其他原生依赖。
4. **锁定与审计**：pnpm lockfile 提交；CI 跑 `npm audit --omit=dev`，high 以上阻断；依赖升级独立 PR。
5. **每个依赖进场前回答三问**：维护活跃度（6 个月内提交）？失败模式与不变量冲突吗（尤其可取消性与字节确定性）？退场成本（包一层 seam 吗）？——第三问决定哪些依赖必须包在接口后面（如 markdown-it 只在渲染管线出现、不允许泄漏到其他模块）。

## 6. 已授权的实现决策

| 决策 | 选项 | 推荐 |
|---|---|---|
| Node 基线下限 | ≥20 vs ≥22 | **采用 ≥22.14**：解锁 node:sqlite 消灭最大原生依赖风险；与 SparkWork 当前 Node 基线一致 |
| 高亮冷启动 | 预热常用 5 语言 vs 纯懒加载 | 纯懒加载 + LRU 缓存，首帧优先 |
| Bun 兼容 | 只保 Node vs 双跑 | **只保 Node**（Bun 的子进程/信号语义差异不值得测试矩阵），opencode 走 Bun 是其生态选择，非通用最优 |
